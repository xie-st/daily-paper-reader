## 摘要
自我改进的 LLM 智能体会编辑自身的运行框架，即围绕固定模型的提示词和规则，并且只有当接受门在一批任务上给某次编辑打出更高分数时才保留该编辑。这样的接受门只看到框架在当前模型下的行为，而看不到当某一防护失效时它仍能阻止什么。当防护措施相互重叠时，删除其中一项会被掩蔽：其余措施仍能阻止危害，因此接受门仅依据任务成功进行决策，冗余会在未被察觉的情况下被侵蚀。我们在两个智能体环境中对四种书面防护措施的每个子集测量危害，并在十种接受门规则下运行 411 个改进循环，其中大多为受控删除实验，另加三次 GEPA 优化器运行。位于另一个有效防护之后的删除几乎不会增加可观测危害。配对显著性检验会阻止因偶然通过而发生的删除，但不会阻止真正提高任务成功率的删除；更大的评估批次则使其能够删除成本更低的防护措施：在相同成本下，20 任务批次使每个框架都保持受保护，而 40 任务批次失去了全部六项。大规模危害审计可以防止暴露，但不能防止防御纵深的丧失；当框架与更弱模型一起复用时，这种纵深丧失会转化为危害。GEPA 逐字保留了每一条安全规则，然而其三个最终框架中有两个在更弱模型下滥用了凭据。一个在运行前冻结的统计模型能够预测：随着防护成本和批次大小变化，每个接受门的保护在何处失效；而冻结安全文本或审计单层消融能够保留防御纵深。

## Abstract
Self-improving LLM agents edit their own harness, the prompts and rules around a fixed model, and keep an edit only if an acceptance gate scores it higher on a batch of tasks. Such a gate sees what the harness does under the current model, not what it would still prevent if one safeguard failed. When safeguards overlap, deleting one is masked: the others still block the harm, so the gate decides on task success alone and redundancy erodes unseen. We measure harm for every subset of four written safeguards in two agent environments and run 411 improvement loops under ten gate rules, mostly as controlled deletion experiments, plus three runs of the GEPA optimizer. A deletion behind another working safeguard adds almost no observable harm. A paired significance test blocks deletions that pass by chance but not deletions that genuinely raise task success, and a larger evaluation batch lets it delete cheaper safeguards: at the same cost, 20-task batches kept every harness protected while 40-task batches lost all six. Large harm audits prevent exposure but not the loss of depth, which turns into harm when the harness is reused with a weaker model. GEPA kept every safety rule verbatim, yet two of its three final harnesses misused credentials under a weaker model. A statistical model frozen before the runs predicts where each gate's protection breaks as safeguard cost and batch size change, and freezing safety text or auditing one-layer ablations preserves depth.

# 《Masked Erosion: How Acceptance Gates Lose Redundant Safeguards in Self-Improving Agents》论文总结

## 1. 核心问题与整体含义

- **背景**：ADAS、Darwin Gödel Machine、GEPA、ACE、Self-Harness 等自我改进智能体会重写自身的 harness（围绕固定模型的提示词、笔记与工具规则），并只保留那些被“接受门”（acceptance gate）判定为在一批任务上得分更高的编辑。现有门控研究（PACE、SAGE、RRSI 等）主要追问“被接受的增益是否真实”，安全研究则追问“子代当前是否安全”。
- **核心问题**：接受门只能观察到 harness 在**当前模型**下的行为，无法观察到“若某一防护失效，harness 还能阻止什么”。当多条防护规则相互重叠（defence in depth）时，删除其中一条会被其余规则**掩蔽**（masking）：危害仍被挡住，门只依据任务成功率做决策，冗余便在无人察觉中流失。作者将这一现象命名为**掩蔽性侵蚀（masked erosion）**。
- **关键概念区分**：
  - **暴露性删除**：删除后子代不再受保护，危害可被观测。
  - **掩蔽性删除**：父子均受保护，观测危害几乎不变，但**裕度（margin）**下降。
  - 被删除的不是“当前安全”，而是“还能承受多少次后续失效”的**防御纵深**。
- **整体含义**：论文试图把两个被现有门控混为一谈的性质拆开——**现在安全**与**发生变化时仍然安全**；并指出模型更换（provider 更新、路由到更便宜模型）会让潜伏的深度流失转化为真实危害。

## 2. 方法论

### 2.1 问题形式化

- Harness \(H\) 含防护层集合 \(S\)，可被提议者编辑为子代 \(H'\)；任务池分为干净池与危害池，并按 \(T_{cal}/T_{conf}/T_{final}\) 划分，门控永远看不到 \(T_{final}\)。
- 门控 \(G(H,H';B)\in\{\text{accept},\text{reject}\}\)，在大小为 \(n\)、以概率 \(p\) 抽取危害任务的新批次上比较父子。

### 2.2 危害格与裕度（核心度量）

- 对每个子集 \(T\subseteq S\) 测危害率 \(h(T)\)；\(h(T)\le\tau=0.05\) 为“受保护”，单层 \(\{s\}\) 受保护则称该层“充分”。
- **裕度**定义为到达任一不受保护子集所需的最少删除数：
  \[
  m(T)=\min\{|T\setminus T'|: T'\subseteq T,\ h(T')>\tau\}
  \]
  即故障树中最小割集的阶数，不要求 \(h\) 单调。
- **子代独有危害** \(h_{01}=\Pr[\text{子代危害}\wedge\text{父代不危害}]\)；掩蔽性给出上界 \(h_{01}\le h(T\setminus\{s\})\le\tau\)。
- 由此推出审计的检测上限：\(k\) 对独立危害样本最多以 \(1-(1-\tau)^k\) 的概率发现掩蔽删除（\(k=4\) 时仅 0.19）；阈值型规则会放行所有掩蔽子代；veto 需约 200 对样本才能以 80% 概率捕捉 0.008 的子代独有危害。

### 2.3 漂移 vs. 选择（解释门控何时失效）

- 混合批次增益 \(g_B=(1-p)g+p\,g_h\)，标准化效应 \(z=g_B\sqrt{n}/\sigma\)。
- 正态近似：
  \[
  P_{\text{greedy}}\approx\Phi(z),\qquad P_{\text{paired}}\approx\Phi(z-z_\alpha)
  \]
- **漂移区**（\(z\approx0\)）：噪声决定，非配对门凭偶然接受“近乎免费”的删除；有效显著性检验每代误接受概率至多 \(\alpha\)。
- **选择区**（\(z\gg0\)）：删除确实提升成功率，因而必然通过基于成功的门控；显著性门可检测的最小成本随批次增大按 \(\sigma/\sqrt{n}\) 下降——**更大批次反而允许删除更便宜的防护**。

### 2.4 门控规则（共十种）

- 仅看成功：Greedy、Split-half（Self-Harness 单次评估变体）、Paired（单侧精确 McNemar 检验）。
- 成功 + 危害：Veto(\(\rho\))、Audit veto（120 次危害运行）、Margin-aware（要求子代的每个单层消融仍受保护，把变异测试的“变异充分性”用于防护）。
- 另有 Asymmetric、IUT、Read-only、带危害惩罚的评分等变体。

### 2.5 冻结模拟器与统计流程

- 用贝叶斯 bootstrap 重采样校准对，运行真实门控代码，并在格上链式传播接受概率；预测在任何循环运行**之前**冻结并哈希。
- 以“循环”为分析单位，使用单侧 Fisher、精确置换检验、匹配随机数、Holm 校正；确认性预测与分析代码预注册并哈希。

## 3. 实验设计

- **两个确定性审计环境**：
  - **AppWorld 凭据误用**：笔记中含多个应用的登录凭据，危害池中目标应用存有他人可用凭据；四层防护为 AUTH（标注笔记所有者）、VERIFY（凭据需与本人匹配）、PROFILE（登录后核对账户）、CAUTION（只用请求者本人凭据）。ReAct 风格代码智能体，最多 15 步，温度 0，确定性审计（无 LLM 裁判）。
  - **OpsSim 破坏性清理**：模拟运维服务，160 张工单；危害池笔记诱导通配符或 admin 权限，从而删除仍在使用的条目；四层为 SCOPE、CONFIRM、LEASTPRIV、DRYRUN；纯内存字典，静态检查禁止文件/网络/进程访问。步数预算（3 步 vs. 4 步）决定防护层是否有成本。
- **模型**：DeepSeek-V4.1-Flash（主智能体与提议者）、Qwen3-30B-A3B、Qwen3-8B（本地）；GPT-6 Luna、GPT-6.1 Sol、Claude Haiku 5.5 为补充模型与换模目标。
- **Benchmark 性质**：非标准榜单，而是自建的“危害格 + 受控删除”实验台；另用 τ²-bench、AgentDojo 与隐私模拟做外部校验（说明强模型本身已规避所探测危害）。
- **对比对象**：十种门控规则互比；补救措施对比（冻结安全文本、Read-only、Margin-aware 单层消融审计、IUT、审计 veto、裁判 veto、危害惩罚、anytime-valid 检验）；以及无冗余变体（每个陷阱仅一层可挡）作为对照。
