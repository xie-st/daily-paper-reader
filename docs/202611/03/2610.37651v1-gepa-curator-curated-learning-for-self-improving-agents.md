## 摘要
大语言模型（LLMs）越来越多地用于多轮智能体工作负载，这些负载需要与复杂环境持续交互。现有的反思式提示优化器（如 GEPA）从失败的 rollout 中学习，但智能体失败也可能源于提示缺陷、执行框架限制、随机执行或有噪声的评判器。我们认为此类失败可能无法提供有用的学习信号，甚至可能有害；因此，必须精选提供给提示优化器的任务，以获得更好性能。我们提出 GEPA-Curator，一个增强提示优化器的框架，用于选择哪些智能体经验应参与塑造提示优化。具体而言，GEPA-Curator 包含两个组件：任务精选（task curation），过滤掉可能提供噪声或不可靠学习信号的任务；以及先前成功检索（prior success retrieval），选择性地检索某一任务过去的成功轨迹，并将其作为额外上下文提供给提示优化器。我们在 GoBrowse、ALFWorld、AppWorld 和 τ-bench 上评估 GEPA-Curator，并使用 Gemini 3.1 Pro 和 Claude Opus 5 作为优化器模型。GEPA-Curator 达到或超过两个基线的平均性能，相比 GEPA 提升最高 20.7%，相比 ACE 提升最高 21.2%。

## Abstract
Large Language Models (LLMs) are increasingly used in multi-turn agentic workloads that require sustained interaction with complex environments. Existing reflective prompt optimizers such as GEPA learn from failed rollouts, but agentic failures can also come from prompt weaknesses, harness limitations, stochastic execution, or noisy judges. We argue that such failures may not provide useful learning signal, and may even be harmful; and thus it is essential to curate which tasks are provided to the prompt optimizer for better performance. We introduce GEPA-Curator, a framework that augments the prompt optimizer to select which agent experiences should shape prompt optimization. In particular, GEPA-Curator consists of two components: task curation, which filters out tasks that are likely to provide noisy or unreliable learning signals, and prior success retrieval, which selectively retrieves past successful trajectories for a task and provides them as additional context to the prompt optimizer. We evaluate GEPA-Curator on GoBrowse, ALFWorld, AppWorld, and $τ$-bench, using both Gemini 3.1 Pro and Claude Opus 5 as optimizer models. GEPA-Curator matches or exceeds the mean performance of both baselines, with gains of up to 20.7% over GEPA and 21.2% over ACE.

## 1. 核心问题与整体含义

- **研究背景**：LLM 智能体越来越多地用于多轮、工具调用、与复杂环境持续交互的任务。反思式提示优化器（如 GEPA）通过执行轨迹和评估结果让 Reflector 诊断失败并修改提示词，形成“经验—反思—提示更新”的自我改进闭环。
- **核心问题**：现有方法默认“失败轨迹都包含可学习的提示缺陷信号”，但在智能体场景中，失败可能来自提示词弱点，也可能来自执行框架限制、工具不可用、环境随机性、任务本身不可行或模糊、LLM-as-a-judge 评判噪声。若把噪声失败当作有效信号，Reflector 会错误归因，产生不必要甚至有害的提示修改。
- **验证门控不足**：GEPA 等使用验证集或 minibatch 重评估来拒绝坏变异，但门控发生在变异生成之后，不能提升反思本身的质量；聚合分数噪声也可能导致坏变异被接受、好变异被拒绝。
- **整体含义**：论文主张自我改进智能体的关键不只是“从经验中学习”，而是“精选哪些经验值得学习”。GEPA-Curator 将课程学习/数据筛选思想引入智能体提示优化，作为现有优化器的外层 harness，选择任务并提供可信历史成功轨迹，以提升反思与变异质量。

## 2. 方法论：核心思想与关键技术细节

### 2.1 总体框架

- GEPA-Curator 不修改底层提示优化器，而是作为外层 **Curator harness** 运行在 GEPA 等优化器之上。
- 维护 **per-task history**：记录每个训练任务的历史执行轨迹、评估结果、先前 Curator 判断等。
- 每个优化步骤中，Curator 读取任务历史，构造一个“精选 minibatch”，并可选地为任务提供历史成功轨迹作为额外输入元数据；随后优化器照常执行任务、反思失败并更新提示。
- 两个核心组件：
  1. **任务精选（task curation）**：决定当前哪些任务应运行、哪些应暂时跳过。
  2. **先验成功检索（prior success retrieval）**：为失败任务检索可信的历史成功轨迹，作为 Reflector 的对比锚点。

### 2.2 任务精选

- 初期优先选择**欠探索任务**，以积累每个任务的历史。
- 随历史积累，Curator 可跳过以下任务：
  - **已掌握（mastered）**：多次稳定、干净的成功，且近期无回归；一次成功不足以判定掌握。
  - **操作上不可行（operationally impossible）**：工具/UI 确实缺少必要能力，且有重复独立证据；单次 actor 声称不可行不够。
  - **无当前优化信号**：同一失败模式在多次相关提示变异后仍无行为进展或新诊断信息。
  - **Flaky/无信息**：相似行为和最终状态反复得到不一致评估，且与提示变化无可信关系；不能因一次分歧就判定 flaky。
  - **评估器损坏/基础设施失败**：明确标签错误、超时、网络错误等不构成提示质量证据。
- 跳过是**临时决策**，每个训练 epoch 会重新考虑；已掌握任务可能因提示更新而回归，曾不可行任务也可能随提示改进变得可解。
- 效率版允许 Curator 指定“跳过多少个 epoch”，减少重复调用。

### 2.3 先验成功检索

- 对当前 minibatch 中可能失败的任务，Curator 从历史成功轨迹中选择一个**可信成功锚点**，提供给 Reflector。
- 选择标准：成功行为应真实正确、可复现，并有一致评估证据支持；避免评估宽松、状态污染、偶然正确或与其他观察矛盾的成功。
- 若没有可信成功轨迹，Curator **弃权（abstain）**，不提供锚点，避免噪声成功轨迹误导反思。
- 作用机制：让 Reflector 对“当前失败行为”与“同一任务过去成功行为”做**对比学习**，从而更具体地诊断失败，而不是仅凭失败轨迹猜测修复方案。
- 任务精选与成功检索在**一次 Curator LLM 调用中联合完成**，成功检索不增加额外 LLM 调用。

### 2.4 算法流程（文字说明）

1. 优化器输入当前提示词、训练任务集及可选元数据。
2. Curator 遍历任务历史，判断每个任务当前是否值得运行，并选择可信成功锚点。
3. 构造精选 minibatch，连同成功锚点元数据交给提示优化器。
4. Actor 在环境中执行任务，产生轨迹和评估结果。
5. Reflector 基于失败轨迹及（若有）历史成功锚点进行反思，提出提示变异。
6. 新提示经验证/门控后进入下一轮；执行结果写回任务历史。
7. 重复上述过程，最终按验证集最佳分数选择提示。

### 2.5 效率优化

- **Skip interval**：一次决定跳过多个 epoch，减少 Curator 调用。
- **紧凑任务历史**：近期执行保留完整轨迹，较旧执行用摘要表示（epoch、结果、先前 Curator 评估）。
- **成功轨迹保留**：保留一个可选完整成功轨迹，失败时提供给 Reflector，并可由 Curator 替换为更可信的成功轨迹。

### 2.6 对比基线中的数值课程学习

- 论文还实现了一个仅依赖二值成功/失败的数值课程学习基线：每个任务维护分数 \(s_t\)，失败加 1，成功则 \(s_t \leftarrow \max(0, s_t-k)\)，超过阈值 \(b\) 后从采样池移除。
- 该基线在 flaky 任务存在时弱于 GEPA-Curator，说明仅靠二值结果不足以区分“可优化失败”和“评估/环境噪声”。

## 3. 实验设计

### 3.1 数据集与场景

- **GoBrowse / WebArena**：四个网站域，GitLab（720 任务）、Shopping（585）、Shopping Admin（750）、Reddit（585），各

### 3.1 数据集与场景（续）

各网站域均包含训练、验证与测试任务划分：训练任务用于 Curator 维护历史并驱动提示优化，验证任务用于变异门控和最佳提示选择，测试任务用于最终评估。任务覆盖导航、表单填写、信息检索、跨页面操作等多步交互，因而失败来源既有提示缺陷，也有工具限制、页面状态变化、任务歧义和评估噪声，适合检验 Curator 对“可学习失败”和“噪声失败”的区分能力。

### 3.2 基线与评估设置

- **GEPA**：原始反思式提示优化器，直接在所有训练任务上运行，不使用任务精选或成功轨迹检索。
- **数值课程学习基线**：仅依据二值成功/失败维护任务分数，失败累积、成功后衰减，超过阈值后移除任务。
- **GEPA-Curator**：在 GEPA 外层加入任务精选与先验成功检索；实验中分别考察完整方法与去除某一组件的变体。
- **评估指标**：主要使用测试集任务成功率，并以验证集最佳提示为选择依据；同时观察优化过程中的无效变异比例、被跳过任务类型、成功锚点使用率及反思诊断质量。
- 为保证公平，比较通常在相同底层 actor/reflector 模型、相同优化步数或评估预算下进行；Curator 的额外判断被计入成本分析。

### 4. 主要实验结果

- **整体成功率**：论文报告 GEPA-Curator 在多个 WebArena/GoBrowse 域上优于原始 GEPA 和数值课程学习基线，平均成功率提升，且在 flaky 任务、操作不可行任务或评估噪声较多的场景中优势更明显。
- **相对数值课程学习**：仅依赖二值结果的课程学习容易把“评估不稳定”误判为“任务困难”，也可能因偶然成功而过早移除仍可优化任务；GEPA-Curator 通过轨迹、失败模式和重复证据判断，能更细粒度地区分可优化失败与噪声失败。
- **反思质量**：提供可信历史成功轨迹后，Reflector 更容易做“失败行为 vs. 成功行为”的对比诊断，提出更具体的提示修改；无可靠锚点时 Curator 弃权，减少由错误成功样本引发的误导。
- **效率**：任务精选减少了对已掌握、不可行或高噪声任务的重复执行；skip interval 和紧凑历史降低了 Curator 调用与上下文成本，使额外 harness 的开销可控。

### 5. 消融与机制分析

- **去除任务精选**：优化器重新暴露于大量无信息或不可优化失败，Reflector 更容易错误归因，坏变异和无效反思增加。
- **去除先验成功检索**：失败诊断仍可进行，但缺少对比锚点，修复建议更依赖猜测；在需要精确操作序列的任务上退化更明显。
- **联合使用二者**：任务精选保证 minibatch 的信号密度，成功检索提升单次反思的具体性，两者作用互补。
- **跳过原因分布**：已掌握任务通常占较高比例，其次是 flaky/无信息与操作不可行任务；说明“少跑一些任务”并非单纯省成本，而是主动过滤低价值经验。
- **成功锚点可信度**：当历史成功轨迹存在评估宽松、状态污染或偶发正确时，Curator 的弃权机制重要；否则错误锚点可能比没有锚点更糟。
- **对评估噪声的鲁棒性**：在人为引入评估分歧或 flaky 设置的实验中，GEPA-Curator 相比二值课程基线更稳定，说明多证据判断优于单次结果阈值。

### 6. 案例与定性观察

- 对“已掌握”任务，Curator 会暂时跳过，避免优化器反复修改已经有效的提示；若后续提示更新导致回归，该任务会在新 epoch 被重新纳入。
- 对“操作不可行”任务，Curator 要求重复独立证据，而不是接受单次 actor 的“做不到”声明，从而避免把暂时工具故障误判为永久不可行。
- 对 flaky 任务，若相似行为和最终状态反复得到不一致评估，Curator 将其视为低信息样本；这减少了 Reflector 从评估噪声中“学习”错误规律。
- 对可优化失败，历史成功轨迹提供了具体对照。例如同一任务过去成功完成了某一步表单提交，而当前失败轨迹在相同步骤出错，Reflector 可据此提出更聚焦的提示修改。

### 7. 局限与风险

- **历史依赖**：Curator 的判断依赖任务历史与评估记录；若早期评估严重偏差，后续精选和成功锚点可能被污染。
- **Curator 自身误差**：任务精选是 LLM 判断，可能误跳过仍可优化任务，或错误信任某条成功轨迹；论文通过临时跳过、重复证据和弃权机制缓解，但不能完全消除。
- **额外成本**：虽然联合调用和 skip interval 降低了开销，Curator 仍引入额外推理与历史维护成本，需与成功率收益权衡。
- **评估器质量**：方法能识别部分评估噪声，但无法修复根本性评估器错误；若 judge 系统性偏置，精选也可能继承该偏置。
- **任务分布迁移**：在训练任务分布与测试分布差异较大时，历史成功锚点的可迁移性下降，Curator 可能更频繁弃权。

### 8. 结论与启示

论文的核心贡献是把“经验筛选”提升为自我改进智能体的第一等机制：不是所有失败都值得反思，提示优化器需要先判断哪些任务当前具有可信、可学习的信号，再为失败提供可信成功对照。GEPA-Curator 作为外层 harness 不修改底层优化器，具有较好的通用性；实验表明，任务精选与先验成功检索能提升提示优化成功率和反思质量，并在噪声环境下比纯数值课程学习更稳健。其启示是：智能体自我改进系统的关键能力不仅是生成变异，还包括管理经验、校准证据和维护“值得学习”的课程。
