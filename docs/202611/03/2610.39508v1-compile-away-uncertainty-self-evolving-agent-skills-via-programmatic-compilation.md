## 摘要
自演化智能体技能使 AI 智能体能够从交互经验中积累并精炼可复用的程序性知识，而无需更新模型参数。然而，此类技能通常以文本形式表示并通过 LLM 推理执行，因此即使是先前已学习的过程也必须反复解释和重新生成，从而在每次执行中引入本可避免的不确定性。相比之下，程序执行是确定性的且可独立验证。直观而言，将定义明确的操作转化为可执行程序可减少对 LLM 推理的依赖，并因此降低执行不确定性。受此直觉启发，我们提出 SkillCompiler，一种将程序化编译集成到技能演化过程中的自演化技能框架。具体而言，SkillCompiler 采用可执行性感知的技能编译策略，将技能分解为细粒度操作，分析其可执行性，并构建混合技能骨架：对依赖上下文的操作保留 LLM 推理，同时将定义明确的操作编译为经过验证的程序。为避免冗余的程序合成并使可执行知识能够跨演化技能积累，我们进一步设计程序资产复用机制，将经过验证的程序组织为可复用资产，在适用时检索已有实现，并仅在必要时合成和验证新程序。在五个基准和六个模型系列上的大量实验表明，SkillCompiler 持续优于最先进方法，任务性能提升最高达 32.33%。

## Abstract
Self-evolving agent skills enable AI agents to accumulate and refine reusable procedural knowledge from interaction experience without updating model parameters. However, since such skills are typically represented as textual documents and executed through LLM reasoning, even previously learned procedures must be repeatedly interpreted and regenerated, introducing avoidable uncertainty into every execution. In contrast, program execution is deterministic and independently verifiable. Intuitively, transforming well-specified operations into executable programs can reduce reliance on LLM reasoning and, consequently, reduce execution uncertainty. Motivated by this intuition, we introduce SKillCompiler, a self-evolving skill framework that integrates programmatic compilation into the skill evolution process. Specifically, SkillCompiler adopts an executability-aware skill compilation strategy that decomposes skills into fine-grained operations, analyzes their executability, and constructs hybrid skill skeletons that retain LLM reasoning for context-dependent operations while compiling well-specified ones into validated programs. To avoid redundant program synthesis and enable executable knowledge to accumulate across evolving skills, we further design a program asset reuse mechanism that organizes validated programs as reusable assets, retrieves existing implementations whenever applicable, and synthesizes and verifies new programs only when necessary. Extensive experiments on five benchmarks and six model families demonstrate that SkillCompiler consistently outperforms state-of-the-art methods, achieving up to 32.33\% improvement in task performance.

## 1. 核心问题与整体含义

- **研究背景**：LLM 智能体虽具备推理、规划、工具使用等能力，但面对新任务时往往需要重新发现相似的解题流程，即便相关经验已被获取。智能体技能（agent skills）提供了一种不更新模型参数即可保存和复用程序性知识的自然方式。
- **核心问题**：现有技能演化方法虽能持续积累和精炼可复用知识，但面临两大挑战：
  - **执行不确定性**：技能通常以文本形式表示、通过 LLM 推理执行，即使技能本身不变，重复执行也可能因概率性推理路径而产生不同中间决策与结果。

## 2. 方法论

### 核心思想
SkillCompiler 将程序化编译集成到技能演化过程中：在操作级别分析可执行性，选择性把输入输出明确、执行逻辑清晰、效果可验证的操作编译为经独立验证的程序；对依赖语义理解、上下文判断或动态观测的操作保留 LLM 推理，形成“混合技能骨架”。同时维护程序资产库，优先复用已验证实现，仅在必要时合成新程序。

### 系统组成
框架包含五个组件：任务分析器（Task Analyzer）、程序员（Programmer）、执行器（Executor）、技能优化器（Skill Optimizer）、程序资产管理器（Program Asset Manager）。工作流分三阶段：

**阶段一：可执行性感知的技能编译**
- **操作分解**：将任务与技能知识分解为细粒度操作，每个操作用 6 元组契约表示：κᵢ = ⟨Iᵢ, Oᵢ, preᵢ, postᵢ, checkᵢ, gᵢ⟩，分别对应输入、输出、可观察前置条件、预期局部效果、验证方式、可复用执行指导。任务特定实体仅在调用时实例化，使同一操作可跨任务复用。
- **操作分析**：判断操作是否可程序化——要求输入输出可显式表示、执行过程可明确指定、前置条件可从环境观测、输出或局部效果可独立验证，且可用工具接口支持有界实现。满足者选为程序化执行，否则保留为智能体引导。
- **技能骨架构建**：将操作组织为混合骨架 Sₓ = ⟨Oₓ, σₓ, Eₓ, βₓ⟩，其中 Oₓ 为操作出现集合，σₓ 为执行顺序，Eₓ 为数据与前置关系，βₓ 为当前参数绑定。骨架显式描述确定性程序与 LLM 推理如何协作。
- **编程与验证**：优先通过程序资产管理器获取已有兼容实现；无可用实现时，依据操作契约、允许的工具接口与执行证据合成新程序，并在隔离环境中验证（能否成功执行、输入输出是否符合 Iᵢ/Oᵢ、局部效果是否满足 postᵢ/checkᵢ）。验证失败则将错误反馈给程序员修复，直至获得合格实现或该操作回退为智能体引导。只有验证通过的程序才被纳入技能骨架。

**阶段二：程序资产复用**
- **兼容性程序检索**：依据操作语义描述与执行要求检索候选程序。技能骨架按词汇相似度排序，原子技能使用 Dice 相似度、历史效用与激活状态综合评分：R(a,o) = 2|T(o)∩T(a)|/(|T(o)|+|T(a)|) + 0.1u(a) + 0.05·1[active(a)]。候选先经能力与契约兼容性过滤，再按分数排序。
- **可复用资格判定**：检索到的程序须同时满足参数可正确绑定、前置条件满足、环境提供所需接口、既有验证记录仍适用，即 Pvalid(a,x) = {p ∈ P(a) : Bind(p,x) ∧ Pre(p,x) ∧ Env(p,x) ∧ Cert(p,x)}。仅当存在唯一合格或优选实现时才自动调用，否则保持智能体引导。

**阶段三：技能优化**
- **基于轨迹的技能修订**：执行失败时，技能优化器逐操作对比实际执行与操作契约，定位失败环节。调用条件不满足或过宽则更新 preᵢ；操作间信息传递错误则修改参数绑定或依赖关系；执行指导不完整则更新 gᵢ；程序未产生预期效果则送回修复与验证。修订是操作级的局部修改，而非从失败任务重新生成整个技能。
- **技能合并与更新**：将修订操作与技能库中已有操作比较，仅当能力语义相同且契约字段在参数对齐下语义一致时才合并：Mergeable(κᵢ,κⱼ) = SameCap(κᵢ,κⱼ) ∧ ∃π: ∧_{f∈{I,O,pre,post,check}} Compat(π(fᵢ), fⱼ)。任务特定实体通过参数化与参数绑定抽象。若更新涉及程序化操作，则重新检索或生成并验证其实现后再执行。

- **问题定位精准**：明确指出文本技能反复经 LLM 解释执行所带来的“可避免不确定性”，并以程序执行的确定性与可验证性作为解决思路，动机清晰且自洽。

- **程序资产复用机制**：将已验证程序组织为可持久积累的资产，结合词汇检索、契约兼容性过滤与验证记录适用性判定，减少跨技能演化中的重复合成开销。

- **不确定性的量化分析**：引入 EIR、APS、EPR 等指标，直接检验“编译降低执行不确定性”这一核心主张，而非仅报告任务准确率。

## 8. 不足与局限

- **依赖可识别的操作边界与可验证效果**：方法假设操作具有明确输入输出、可观察前置条件与可独立检查的局部效果。对于模糊、开放式或强上下文依赖的任务，可编译操作有限，编译只能减少而非消除不确定性。
- **局部验证的泛化性有限**：程序验证仅在测试输入与环境状态下提供正确性证据，不保证在未见条件下语义等价或分支覆盖完备；程序复用也依赖契约兼容性与足够复用次数来摊销合成与验证成本。
- **任务与模型覆盖仍有缺口**：ALFWorld 仅在 DeepSeek-V4.1-Flash 上评估；未在动态 Web 环境或更广泛的真实任务中验证；部分基线在个别基准上的表现可能受实现细节影响，比较的公平性存在一定不确定性。
- **算力信息缺失**：论文未报告 GPU 型号、数量、训练时长等硬件资源，仅给出 token 与调用次数，难以完整评估实际部署成本与可复现性。
- **收益分布不均**：SearchQA 与 DocVQA 上提升幅度较小（如 DocVQA 上部分模型仅提升 0.5%），说明方法对任务特性敏感；Avg 列为未加权平均，可能掩盖任务间的差异。
- **程序资产库的长期维护问题**：随着技能演化，程序版本、契约变更与验证证据的兼容性管理可能变得复杂；论文未深入讨论资产库规模增长后的检索效率与冲突消解策略。
- **对底层模型能力的依赖

- **对底层模型能力的依赖**：尽管程序化编译降低了执行阶段的不确定性，但操作分解、可执行性判断、程序合成与失败归因仍由 LLM 完成，因此方法收益上限受底层模型的分析与编程能力制约。较弱模型可能在契约抽取、程序修复循环中消耗更多 token，或使更多操作回退为智能体引导，从而削弱编译收益；实验中不同模型的提升幅度（6.02–11.90 个百分点）与平均分波动（4.85%）也印证了这种模型依赖性。论文未系统分析“模型能力—可编译操作比例—最终收益”之间的定量关系，也未讨论在弱模型上如何设置回退阈值以控制成本。

## 9. 综合评价与适用建议

- **定位**：SkillCompiler 处于“纯文本技能演化”与“端到端程序合成”之间的中间路线，其核心贡献不是让智能体完全程序化，而是以操作契约为粒度，把“可确定、可验证”的部分从概率性推理中剥离出来，并用资产库让这份确定性可跨技能累积。
- **适用条件**：当任务包含较多输入输出明确、效果可局部验证的重复子操作（如数学计算、文档字段抽取、环境状态查询与校验）时收益最明显；当任务以开放式语义判断、长上下文理解或动态环境探索为主时，可编译操作比例下降，方法退化为带资产复用的技能演化，优势收窄。
- **实践建议**：落地时可先做操作级可执行性普查，估计可编译比例以判断投入产出；对程序资产库设置验证证据的有效期与环境依赖标注，避免契约漂移导致错误复用；对回退为智能体引导的操作保留显式标记，便于后续人工审查或补充工具接口。
- **研究启示**：该工作提示“不确定性”本身可作为技能演化的优化对象——不仅优化任务成功率，也优化执行路径的稳定性；未来可进一步探索操作契约的自动发现、程序验证的覆盖度度量，以及资产库规模增长后的检索与冲突消解机制。
