# Where Should the Evaluation Budget Go in LLM-Driven Agent Scaffold Evolution?

Abstract 

Large language model (LLM)-driven agent scaffold evolution im-proves agent workflows through iterative candidate generation and evaluation. Evaluation both guides subsequent search and deter-mines the final scaffold, but evaluating every candidate on the full task set incurs substantial execution costs. We investigate how eval-uation budgets can be allocated across these two roles. Our experi-ments show that sparse feedback can sustain productive evolution, while additional targeted evaluation improves final selection. Re-play analyses further show that shared informative items and a com-mon scoring reference support comparisons among closely matched candidates. Motivated by these findings, we propose EvalAlloc ,an evaluation allocation framework that combines sparse search-time feedback with targeted final confirmation. A short fully evalu-ated warm-up establishes a shared informative core and calibrates a response model whose item parameters remain fixed during search. After search, EvalAlloc refits the model and applies paired succes-sive halving, reusing accumulated observations and executing only missing evaluations. Across four benchmarks and two evolution frameworks, EvalAlloc achieves higher mean performance than full evaluation in most settings while using approximately half as many evaluation cells. 

1 Introduction 

A scaffold for a large language model (LLM) agent is an executable program that defines how an agent coordinates LLM calls, maintains intermediate state, and interacts with tools and external informa-tion sources [13, 26, 31]. For Web-facing agents, scaffolds govern how agents acquire and use information through Web searches, document retrieval, and interactions with online services [22, 36]. While these scaffolds have traditionally been designed and refined manually, recent advances have enabled their automated optimiza-tion [2, 13, 34]. For example, ShinkaEvolve [17] iteratively proposes scaffold modifications and uses evaluation feedback to guide subse-quent evolution. However, evaluating candidate scaffolds can incur substantial execution costs. A single task instance may involve multiple LLM calls, retrieval steps, and tool interactions [21, 32], making full evaluation across many candidates expensive. Although parallel evaluation and asynchronous program generation can overlap com-putation [28], feedback-dependent search decisions still require evaluation results. Existing approaches reduce evaluation costs through sparse score estimation and evaluation cascades [8, 9], treating evaluation primarily as a fitness-estimation problem. In scaffold evolution, however, evaluation supports two distinct de-cisions: it provides fitness feedback that shapes archive updates and subsequent proposals [33], and it determines which scaffold is ultimately returned. These decisions impose different requirements: search benefits from inexpensive yet comparable feedback, whereas final selection requires reliable discrimination among competitive candidates. This raises a central question: How should a limited evaluation budget be allocated across these two decisions to improve the quality of the ultimately selected scaffold? 

To answer this question, we investigate how evaluation alloca-tion affects evolutionary search and final scaffold selection. Our investigation yields three findings. First, sparse evaluation feedback can sustain productive evolution, whereas removing feedback sub-stantially degrades search quality. Second, shared informative items improve comparisons between closely matched candidates, while maintaining a common scoring reference helps preserve compara-bility across evolutionary iterations. Third, search improvements are concentrated in early iterations, whereas final selection remains sensitive to uncertainty among top candidates. These findings sug-gest that evaluation should provide inexpensive yet comparable feedback during search, while reserving additional observations for final selection. Motivated by these findings, we propose EvalAlloc , an evalu-ation allocation framework that separates sparse search-time feed-back from targeted final selection. During search, a short fully evaluated warm-up identifies a shared informative core and cali-brates a response model. Subsequent candidates are evaluated on sparse item sets centered on this core, while the model’s item pa-rameters remain fixed to maintain a common scoring reference for archive updates and parent selection. After search, EvalAlloc applies warm-started paired successive halving (SH), reusing accu-mulated observations and performing only missing evaluations. A refitted response model further supports comparisons during later selection rounds. We evaluate EvalAlloc on four benchmarks and two evolution frameworks, with three independent runs per setting. Compared with full evaluation, EvalAlloc uses approximately half as many evaluation cells while achieving competitive or higher mean performance across the evaluated settings. Ablation studies further show that informative item allocation and final selection are the main contributors to its effectiveness. These results demon-strate the benefits of separating sparse search-time feedback from targeted final evaluation. Our main contributions are summarized as follows: 

• We investigate evaluation allocation as a decision-dependent problem in LLM-driven scaffold evolution, demonstrating that search-time feedback and final scaffold selection impose distinct requirements on evaluation resources. 

• We propose EvalAlloc, an evaluation allocation framework that combines a shared informative core, a fixed search-time arXiv:2610.37276v1 [cs.LG] 27 Oct 2026 , , 

response model, and warm-started paired successive halving to allocate evaluation effort across evolutionary search and final selection. 

• We evaluate EvalAlloc across four benchmarks and two evolu-tion frameworks, complemented by controlled replay analyses, demonstrating competitive final performance with substantially fewer evaluation cells. 

2 Related Work 

LLM-Driven Agent and Program Evolution. Recent work has explored the automated design and optimization of agent scaffolds and executable workflows using LLMs [23]. ADAS [13] uses a meta-agent to generate agent programs based on previous discoveries, while AFlow [34] employs Monte Carlo Tree Search to optimize code-represented workflows. Other approaches, including ShinkaE-volve [17] and AdaEvolve [4], iteratively generate, evaluate, and refine programs using evaluation feedback to guide subsequent search. These approaches primarily focus on improving candidate generation and evolutionary optimization. Our work instead exam-ines the evaluation process underlying this feedback-driven search, studying how limited evaluation resources can support both evolu-tionary decisions and final scaffold selection. 

Efficient LLM Evaluation. Reducing the cost of evaluating LLMs has received growing attention. Methods such as tinyBench-marks [24] use carefully selected examples and statistical estimation to approximate full-benchmark performance, while SparseEval [35] optimizes representative items for efficient score estimation and ranking. CollabEval [8] exploits shared information across evalua-tions through matrix completion to improve statistical efficiency. Growing Pains [12] uses fixed item-response calibration and anchor items to maintain score comparability across evaluation periods. These studies demonstrate the effectiveness of sparse observations and response modeling. However, in scaffold evolution, evaluation estimates also influence archive updates and subsequent candidate generation. Therefore, we examine not only estimation accuracy, but also how shared informative observations and stable scoring references support reliable evolutionary decisions. 

Evaluation Allocation and Candidate Selection. Evaluation allocation is closely related to sequential resource allocation and best-arm identification. Successive halving [14] and Hyperband [18] progressively concentrate evaluation resources on promising can-didates, while racing-based methods such as irace [20] eliminate weaker configurations through sequential comparisons. Common random numbers [10] provide a classical motivation for evaluat-ing alternatives under shared conditions to reduce the variance of pairwise comparisons. Recent analyses of code evolution [9] also highlight the importance of reliable candidate evaluation and selec-tion. Building on these ideas, our work studies evaluation allocation across two distinct stages: providing inexpensive yet comparable feedback during evolution and reusing accumulated observations for reliable final scaffold selection.

SEARCH is used for evolution and final selection, DEV for auxiliary audits, and TEST exclusively for evaluating the selected scaffolds. Each run makes 80 proposals from the same ini-tial program, with three seeds per setting. We use Qwen3.5-9B [27] as the executor, with temperature zero, thinking disabled, and at most 16,384 output tokens, and DeepSeek-V4-Flash-0731 [29] as the proposer. Both models are served locally with vLLM [16] on a single node with eight NVIDIA H20 GPUs. Most analyses in this section replay evaluators on the 24 Full runs (four benchmarks, two frameworks, three seeds), in which every candidate is evaluated on all SEARCH items, so the full-SEARCH mean of each candidate is known. A replay keeps the candidate sequence fixed and varies only which cells the evaluator observes. We measure two search-time quantities. Close-pair agreement is the share of candidate pairs whose full-SEARCH means differ by at most .03 that the evaluator orders correctly; these are the com-parisons that archive updates face. Archive regret is, averaged over the run, the gap between the mean full-SEARCH score of the ten best candidates generated so far and that of the ten candidates the evaluator ranks highest. 

4.2 Search Needs Feedback, but Not Full Evaluation 

Evaluation feedback plays an important role in guiding evolution-ary search. Figure 1 compares the evolution trajectories under three evaluation strategies on DROP and HotpotQA, using a shared audit set. Without evaluation feedback, candidate quality remains rela-tively low and shows limited improvement. In contrast, random partial evaluation maintains candidate quality close to Full, sug-gesting that effective evolution does not require evaluating every candidate on the entire SEARCH set. Search improvements are also concentrated in early iterations. Although this does not establish the optimal temporal allocation, it motivates investing in early calibration and using sparse feedback for subsequent candidates. 

Takeaway 1. Evolutionary search requires evaluation feedback, but sparse evaluation can sustain candidate improvement without the cost of full evaluation. 

4.3 Comparability Depends on Shared Informative Observations 

We conduct offline replays on 24 Full evolution trajectories (four benchmarks, two frameworks, and three seeds), with three replays per trajectory. Each replay fixes the generated candidate sequence and varies only the evaluation cells observed by the evaluator. The first 𝑊 = 10 candidates are fully evaluated, while subsequent candidates are evaluated on 60 of the 300 SEARCH items. All policies use the same evaluation budget, with full-SEARCH scores serving as the reference. We assess three metrics: Spearman correlation with full-SEARCH scores, close-pair agreement for candidates whose reference scores differ by at most .03, and archive regret, defined as the average fitness gap between the true and estimated top-10 archives. These metrics capture both score estimation quality and the evolutionary decisions supported by limited feedback.

4.4 Final Selection Needs Confirmation 

Final scaffold selection requires more reliable comparisons than those needed to guide evolutionary search. Figure 2 compares the native selection rule with successive halving (SH) on the same candidate pools under different search-time evaluation strategies. SH substantially improves final performance when search feedback is absent, recovering strong candidates that the native selection rule may overlook. With random partial evaluation, the gains are smaller and less consistent, while full evaluation leaves little room for further improvement. These results highlight the importance of final confirmation when search-time evaluation is limited.  

> Takeaway 3. Final selection requires reliable comparisons beyond search-time fitness estimates, particularly when evaluation feedback is sparse or absent.

5 Method 

Figure 3 illustrates EvalAlloc, an evaluation allocation framework that distributes evaluation effort across three stages: Core Calibra-tion , Shared-Core Evolution , and Warm-Started Selection . EvalAl-loc decouples the two roles of evaluation: search-time feedback only needs to be cheap and comparable enough to guide evolu-tion, whereas the final choice needs precise comparisons among the strongest candidates. It therefore splits one evaluation bud-get into a sparse search stage and a separate selection stage that reuses every observation collected during search. The key idea is to invest a small evaluation budget upfront to establish a reusable reference, use shared informative items to provide comparable feedback throughout evolution, and concentrate additional evalua-tions on final scaffold selection. EvalAlloc operates as a drop-in evaluator, leaving the native framework’s proposal, archive, and parent-selection policies unchanged.

5.3 Warm-Started Selection 

Search-time evaluation aims to provide inexpensive feedback for continued evolution, whereas final selection requires distinguishing the strongest candidates. After search, EvalAlloc therefore runs successive halving (SH) over all valid candidates, using additional observed outcomes rather than relying on search-time fitness es-timates. Candidates with identical code (the same abstract syntax tree after removing docstrings) are merged first. The evaluation budget thus becomes increasingly concentrated on competitive candidates.

6 Experiments 6.1 Setup 

Baselines. We compare EvalAlloc against five evaluation strate-gies with different budget allocations. Skip Eval performs no eval-uation during either search or final selection, and select the last valid evolved program. Successive Halving (SH) [14] provides no evaluation feedback during search and applies successive halving to the generated candidate pool for final selection. Random evalu-ates each candidate on a randomly sampled 50% subset of SEARCH items. Cascade [2, 23] first evaluates candidates on 20% of SEARCH items and promotes candidates meeting a top-25% threshold to full evaluation, while allocating no additional evaluations to the re-maining candidates. Full evaluates every candidate on all SEARCH items. 

Implementation Details. We use the same benchmarks, evolu-tion frameworks, and model configurations as in Section 4.1. Unless otherwise specified, EvalAlloc allocates 30% of the full-evaluation budget to search, with the first 𝑊 = 10 valid candidates fully eval-uated and each subsequent candidate evaluated on 𝑘 = 60 items (20% of SEARCH). The shared informative core contains 𝑘 0 = 54 items (90% of 𝑘 ), and the Gumbel sampling temperature is 𝜏 = 0.001. For final selection, we use 𝑅 = 4 successive-halving rounds with cumulative item prefixes of 30, 60, 120, and 300, retaining 30, 15, 8, and 1 candidates, respectively. For the response model, we set the latent dimension to 𝑑 = 2, the regularization coefficient to 𝜌 = 1, and the informativeness uncertainty penalty to 𝑧 = 2.

6.3 Ablation Study 

We ablate three components of EvalAlloc on ShinkaEvolve across all four benchmarks. W/o selection skips final confirmation and selects the candidate with the highest refitted response-model es-timate from the same search runs. W/o response model uses raw observed means for search feedback and raw union means for final selection. W/o informative items replaces informative item selec-tion with random sampling while preserving the shared core and evaluation budget. The latter two variants require new evolution runs because they change the search-time feedback. Table 4 shows that removing final confirmation consistently re-duces TEST performance, highlighting the importance of additional evaluation for selecting among competitive candidates. Replacing informative items with random ones produces the largest aver-age degradation, suggesting that sharing evaluation items alone is insufficient without considering their informativeness. Removing the response model has a smaller and less consistent effect, as the shared core already provides substantial comparability among can-didates. The response model therefore primarily serves to calibrate sparse feedback onto a common scoring scale. Overall, these results identify informative item selection and final confirmation as the main contributors to EvalAlloc. 

6.4 Analysis 

Budget Allocation in Warm-up Stage. Figure 4 examines the effect of warm-up length 𝑊 on DROP with ShinkaEvolve under a fixed search-stage budget. A longer warm-up provides more ob-servations for calibration but leaves fewer evaluation items for subsequent candidates. The default 𝑊 = 10 achieves the highest mean performance, although the differences are within seed-to-seed variation. All three configurations outperform Random at comparable evaluation cost. Offline replays further show that an excessively long warm-up reduces search-time ranking accuracy as later evaluations become too sparse. These results highlight the trade-off between upfront calibration and informative feedback during subsequent evolution. 

Budget Allocation in Search Stage. Figure 5 examines the effect of search-time evaluation budget on DROP with ShinkaEvolve. We fix the warm-up at ten fully evaluated candidates and vary the target search budget from 20% to 40%. The default 30% allocation achieves the highest observed mean TEST performance, while the 20% configuration offers comparable performance at lower cost. Increasing the search-time budget does not consistently improve final performance in this setting, suggesting that sparse feedback can be sufficient to guide productive evolution. 

Budget Allocation in Selection Stage. Figure 6 examines the effect of final confirmation budget while reusing the same search runs. Compared with direct selection based on search-stage esti-mates, successive halving (SH) improves TEST performance across all four benchmarks. Applying SH to the top 30 candidates captures most of the improvement at lower cost, while considering all can-didates provides a modest additional gain. These results highlight the value of targeted final confirmation and the trade-off between selection cost and final scaffold quality.

7 Conclusion 

Evaluation influences both evolutionary search and final scaffold selection. Our investigation shows that sparse informative feedback can guide evolution, while shared evaluation items and a stable scor-ing reference support comparable decisions across candidates. Mo-tivated by these findings, we propose EvalAlloc, which combines sparse search-time feedback with warm-started final confirmation. Across four benchmarks and two evolution frameworks, EvalAl-loc achieves competitive performance while using approximately half as many evaluation cells as Full. These results highlight the importance of allocating evaluation effort according to its distinct roles in search and final selection.
