## 摘要
电商和音乐流媒体等 Web 平台上的推荐系统需要针对每个数据集重新调校其训练配方。大语言模型（LLM）智能体现在能够重写这些配方，从而支持推荐系统的递归自我改进（RSI）。现有智能体每轮提出一个编辑，完全重新训练推荐系统，并且仅当排序质量提升时才保留该编辑。与可通过执行评分的程序或补丁不同，推荐系统编辑会改变模型的训练方式，这带来两个挑战。首先，排序反馈存在延迟：一次编辑的排序质量只有在完整重新训练后才能得知，因此大量重新训练预算被用于最终被丢弃的编辑。其次，重新训练前可获得的信号并不可靠：采样训练损失可能看起来已经解决，但全排序性能仍然较差，而且对于改变损失或采样器的不同编辑，这些信号不可比较。我们提出 RecRSI，它基于对当前模型的诊断生成多样化的候选编辑，并利用早期排序反馈选择一个候选进行完整重新训练：每个候选都接受一次短试运行，即其完整训练运行的最初若干步骤，并由在留出探针用户上的全排序 NDCG@10 评分。在三个数据集上使用两个序列推荐器，并在相同完整重新训练次数下，RecRSI 在所有设置中均显著优于现有自我进化智能体，并且在两个 Amazon 数据集上，其第一轮就达到这些方法五轮均未达到的排序质量。

## Abstract
Recommenders on Web platforms such as e-commerce and music streaming need their training recipes re-tuned for each dataset. Large language model (LLM) agents can now rewrite these recipes, enabling recursive self-improvement (RSI) of recommender systems. Existing agents propose one edit per round, fully retrain the recommender, and keep the edit only if its ranking quality improves. Unlike programs or patches that can be scored by execution, a recommender edit changes how the model is trained, which raises two challenges. First, ranking feedback is delayed: an edit's ranking quality is known only after full retraining, so much of the retraining budget goes to edits that are later discarded. Second, the signals available before retraining are unreliable: sampled training losses can look solved while full-ranking performance remains poor, and they are not comparable across edits that change the loss or sampler. We propose RecRSI, which generates diverse candidate edits from a diagnosis of the current model and selects one for full retraining using early ranking feedback: each candidate receives a short trial, the first steps of its full training run, scored by full-ranking NDCG@10 on held-out probe users. With two sequential recommenders on three datasets and the same number of full retrainings, RecRSI significantly outperforms existing self-evolving agents in every setting, and on both Amazon datasets reaches in its first round a ranking quality that none of them reaches in five.

## 1. 核心问题与研究动机

- **背景**：推荐系统的训练配方（架构、训练损失、负采样器、优化调度、预测方式等）对最终性能影响巨大，且最优配方随领域与数据集而变，目前仍依赖人工反复改代码、重训调参。
- **现有范式**：LLM 智能体（AlphaEvolve、DeepEvolve、Self-EvolveRec 等）已能重写推荐系统训练代码、完整重训、仅当排序质量提升时保留编辑，从而把递归自我改进（RSI）引入推荐系统开发。
- **核心矛盾**：这类循环继承自"可直接执行评分"的编程任务，但推荐系统编辑改变的是**模型的训练过程**，其奖励只能在完整重训后观测。由此产生两个挑战：
  - **反馈延迟**：一次编辑的排序质量要等完整重训结束才知道，而完整重训成本高昂（随物品目录和交互日志增长）。现有智能体每轮只提 1 个编辑并直接重训，导致大量预算浪费在最终被丢弃的编辑上——论文统计三个框架、两个骨干、三个数据集共 90 次重训，仅 37 次（41%）产生被保留的编辑。
  - **重训前信号不可靠**：推荐系统常用采样目标训练，采样损失接近下界时全排序性能仍可能很差；且当编辑改变损失或负采样器时，损失尺度不同、彼此不可比（如 Office 首轮，in-batch softmax 编辑损失 6.2，而 BCE 编辑约 1.05，按最低损失选会误删最优编辑）。
- **关键洞察**：结果奖励的问题在于"何时到达"而非"测量什么"。理想的早期信号应保留结果奖励的两个性质——**训练一致性**（用编辑自身的架构/损失/采样器/调度，从共享初始化 θ(0) 与种子 ξ 出发训练）与**排序一致性**（用全排序 NDCG@10 在留出用户上评估）。现有早期信号（父模型诊断、LLM 补丁判断、零成本代理、曲线外推等）至少缺失其中之一。

## 2. 方法论：RecRSI

### 核心思想
每轮让 LLM 基于父模型诊断提出 **K 个多样化候选编辑**，对每个候选做一次**短试训**（完整训练的前若干步），用**全排序 NDCG@10 在 probe 用户上评分**，只把本轮唯一一次完整重训花在试训分数最高的编辑上。

### 关键流程（Algorithm 1）
1. **诊断父模型**：在 probe 用户上前向计算，汇总父模型的排序失败模式，包括：
   - 正样本输给 32 个随机物品中最强者的比率与平均分差；
   - 物品身份单独解释的分数方差占比（衡量是否对所有用户同序排序）；
   - 正样本在 rank 1–10、11–100、>100 的分布；
   - head/tail 物品上的 NDCG@10。
2. **诊断条件化批量提议**：LLM 结合父代码、配方与训练框架接口、历史记忆 M，提出 K=3 个编辑，要求分布在不同组件（损失、负采样器、优化器、预测、架构）以保证多样性；每个编辑返回 search-and-replace 补丁、改动组件、引用诊断的假设、预期优先改善的 rank 组。
3. **编辑合法性检查**：补丁干净应用、静态检查（禁止导入/属性访问）、合成 batch 冒烟测试（能完成训练步并暴露评分接口）；失败给一次修复请求，再失败即丢弃；与历史配方重复者去重。评估代码固定且不可编辑。
4. **短试训**：对每个候选 a，从 θ(0)、种子 ξ 出发，按编辑自身的调度训练前 K_s=4,000 步（约 15% 预算，不做早停），计算
   - m_a = NDCG@10(θ_a^(K_s); U_probe)
   - 父配方同样试训得参考分 m_p。
5. **选择与重训**：a\* = argmax_a m_a，对其做完整重训；若 select NDCG@10 相对父模型提升超过 δ=10⁻⁴ 则 promote。
6. **记忆更新**：记录每个编辑的组件、假设、试训分数、promotion 决定、重训后在 probe 用户各 rank/流行度组的变化；除二值 promote 决定外不写入 select 指标，Test 交互完全隔离于搜索。

### 设计要点
- **训练一致性**：从 θ(0) 而非父权重 θ_p 开始，保证试训模型与完整重训在第 K_s 步状态一致，且能评估新增参数类编辑（新模块、学习式预测头）；从 θ_p 继续会改变被评估的训练路径。
- **排序一致性**：试训分数由结果奖励的同一评估器计算（同物品集、同历史掩码、同 tie-breaking），因此在 BCE、in-batch softmax、采样器编辑之间可比。
- **数据隔离**：验证用户按固定哈希分为 probe（早停 + 选编辑）与 select（决定 promote），另有 20% 审计子集未使用；Test 为每个用户更晚的一次交互，只在轨迹结束后评估一次。
