# ABSTRACT 

Repeated attempts at interactive tasks uncover facts, useful operations, and fail-ures that can inform subsequent execution. We introduce ReGE, a framework for turning this recorded experience into guidance for a fresh attempt. Its main im-plementation, ReGE-Syn, uses a single coach call to jointly synthesize bounded execution records and available artifacts into self-contained guidance, connecting task-specific findings with proposed actions and relevant pitfalls. A student starts from the task’s initial environment state and adapts this guidance to current ob-servations. Source generation, synthesis, and student execution use the same base model, without parameter updates or a stronger teacher. Across four benchmarks, ReGE improves accuracy by an average of 9.9 percentage points for GPT and 8.8 percentage points for Claude compared with unguided execution. On matched BrowseComp-Plus subsets, ReGE-Syn reduces guidance-construction tokens by 98.2% on GPT and 95.5% on Claude relative to adapted AggAgent, with observed success. Combined construction and execution tokens decrease by 15.7% and 35.4%, respectively, counting input plus output and excluding source generation. BrowseComp-Plus ablations further associate access to process information with fewer student steps and show that joint synthesis produces substantially shorter guidance than Direct history or Independent summaries, with observed success. These results demonstrate how agents can use their own recorded experience to improve subsequent task completion, and suggest a low-cost way to consolidate the execution records of parallel agent systems such as agent swarms.

We introduce ReGE (Re-execution Guided by Experience ), a framework for constructing guidance from recorded attempts. Its main implementation, ReGE-Syn, presents bounded execution records and available artifacts together to a coach, which produces self-contained guidance in one call. The coach connects task-specific findings with proposed operations and relevant pitfalls. A fresh student starts from the task’s initial environment state, using current observations to follow, adjust, and verify the guidance. Source generation, synthesis, and student execution use the same base model, without parameter updates or a stronger teacher; this lets us test whether a lower-priced model guided by its own attempts can match higher-priced models. The framework also includes ReGE-Sel, which forwards one judge-selected trajectory as guidance (see §4.6). We evaluate ReGE on Terminal-Bench 2.0, Spider2-Lite, AndroidWorld, and BrowseComp-Plus with GPT and Claude model lines. Across four benchmarks, ReGE improves accuracy by an av-erage of 9.9 percentage points for GPT and 8.8 percentage points for Claude compared with un-guided execution. On a subset, gpt-5.6-luna with ReGE reaches 67.4% average success, comparable to the 67.0% of the higher-priced gpt-5.6-sol, at 28% of its cost including source-pool generation (Figure 1). On matched BrowseComp-Plus subsets, ReGE-Syn reduces guidance-construction to-kens by 98.2% on GPT and 95.5% on Claude relative to adapted AggAgent, with observed suc-cess. Although student execution uses more tokens, combined construction and execution usage falls by 15.7% and 35.4%, counting input plus output and excluding source generation. Further BrowseComp-Plus ablations examine which source information helps execution, how to organize multiple attempts, and how the guidance’s output form affects its use. Our contributions are: • Joint synthesis of execution experience. ReGE-Syn connects concrete findings, oper-ations, and failure lessons across recorded attempts into actionable guidance for a fresh execution by the same base model. • Capability gains with low guidance-construction cost. Across four benchmarks, ReGE improves mean task completion over unguided execution. On matched BrowseComp-Plus subsets, ReGE-Syn substantially reduces construction tokens relative to adapted iterative aggregation and retains lower combined usage after student execution. With ReGE, a lower-priced model reaches the success of a higher-priced model in its family at 28% of its cost. 

# 2 REGE: E XPERIENCE -G UIDED AGENT EXECUTION 

ReGE is a framework for constructing guidance from recorded experience and using it in a fresh execution. Guidance can be built by jointly synthesizing multiple attempts (ReGE-Syn) or selecting one trajectory (ReGE-Sel). We focus on joint synthesis; §4.6 compares the variants. The student starts from the task’s initial environment state and uses the guidance alongside current observations. 2Preprint Source generation, guidance construction, and student execution share the same base model, without parameter updates or a stronger teacher. Figure 2 illustrates the synthesis implementation. 2.1 RECORDED EXPERIENCE 

A task consists of an instruction x, an initial environment state s0, and a benchmark evaluator. Repeated attempts produce a source pool P = {τ1, . . . , τ K }. For ReGE-Syn, we construct the text representation V (P) programmatically: each attempt forms a separate block, with available reasoning or action narratives and commands in step order, followed by final artifact paths and contents. These fields are copied and truncated to bound the input length; no per-trajectory LLM summary is generated before the coach sees them. Benchmark correctness labels are withheld from both coach and student. Raw per-step observation fields are omitted, so execution feedback is accessible only where preserved in the rendered text or artifacts. This representation provides bounded execution records rather than the complete environ-ment history. Appendices A.1 and A.2 specify the field mappings, truncation limits, and prompts. 2.2 JOINT EXPERIENCE SYNTHESIS 

Useful experience can be distributed across attempts: one may uncover a necessary task fact, another a workable command, and another a failure to avoid. ReGE-Syn brings these records into a shared context and prompts a coach to turn them into self-contained guidance for a fresh attempt. Using the same base model with parameters θ, the coach Cθ constructs 

g = Cθ (x, V (P); psyn ) , (1) where psyn specifies the guidance construction task. All retained source blocks are presented together, preserving attempt boundaries and step order. A single coach call produces the guide, allowing decisions about what to retain and connect to account for information across attempts. Independent per-trajectory summarization makes these decisions separately before combining summaries. The coach is prompted to connect concrete findings with proposed operations and relevant pitfalls, retaining details needed to act on them. The default guidance is an execution-ordered plan. Exact paths, values, commands, format re-quirements, and encountered problems are placed alongside the steps where they matter. When the records support a candidate answer or artifact, the coach is asked to include it together with a way to verify it. The guide must be understandable without consulting the source attempts, since the student receives only the resulting guidance. Source correctness labels are unavailable, so its recommendations remain subject to the student’s checks against the current environment. ReGE-Syn shares joint aggregation with response-aggregation methods such as Self-MoA (Li et al., 2025). Here, the coach synthesizes bounded execution records and available artifacts into guidance for further interaction: the student must carry out and verify the proposed operations in a fresh en-vironment. # 3 EXPERIMENTAL SETUP 

Benchmarks. We evaluate on four benchmarks. Terminal-Bench 2.0 (The Terminal-Bench Team, 2025) includes 89 tasks, with a budget of 30 agent turns per execution. Spider2-Lite (Lei et al., 2025) includes 135 instances with local SQLite databases; agents receive read-only access and up to 18 SQL calls. AndroidWorld (Rawles et al., 2025) uses the text-only T3A agent, with guidance supplied through its native task-guideline interface and a step budget of ten times task complexity. After excluding two templates that crash the emulator, we evaluate 114 templates with three parame-terisations on GPT and one on Claude, yielding 342 and 114 instances, respectively. BrowseComp-Plus (Chen et al., 2025) includes 830 questions over a fixed corpus of 100,195 documents. Agents use retrieval and document-opening tools without live web access, with a 40-step budget. We use DeepSeek-V4-Flash with reasoning disabled as the LLM equivalence judge for BrowseComp-Plus. 

Models and budgets. We use gpt-5.6-luna and claude-sonnet-5, holding the base model fixed across source generation, guidance construction, and student execution. Source pools contain four attempts per task on all benchmarks (see Appendix B.1). ReGE and AggAgent share these pools and each receive one fresh student execution under the same benchmark-specific step limit to match the bud-get. Generation settings, effective serving limits, and collection exceptions are documented in Ap-pendix A.3. 

Baselines. Control performs one unguided execution (pass@1) under the same student step limit. Our Reflexion adaptation (Shinn et al., 2023) allows up to three executions, using reflections from preceding trials and label-free self-evaluation for stopping. AggAgent (Lee et al., 2026) iteratively inspects source records using its released tools and prompts. To align it with our fresh-execution protocol, we adapt its final response into guidance for a fresh student. Independent summaries, our agentic PDR adaptation (Kim et al., 2026), summarize four source trajectories separately and concatenate the summaries to guide a fresh student (Appendix A.2). We also report two references without student re-execution: Self-Consistency (SC; Wang et al., 2023) votes over available source outputs, while Best-of-N reports the original score of the source selected by the judge model. 

Inference cost. Our primary cost metric is the sum of input and output tokens used after source-pool generation, including all method-specific guidance construction and execution calls. Input-only usage and costs that include source generation are explicitly identified.

4.1 EFFICIENT EXPERIENCE SYNTHESIS 

Joint synthesis makes effective guidance inexpensive to construct. On matched BrowseComp-Plus queries, ReGE-Syn reduces construction tokens by more than 95% relative to AggAgent on both base models, while maintaining observed task success (Table 3). Guidance construction conse-quently accounts for only a small fraction of ReGE-Syn’s combined usage. These results show that consolidating prior attempts into useful guidance need not make construction the dominant inference expense. 

The construction savings translate into lower combined usage. Students guided by ReGE-Syn consume more tokens than those guided by AggAgent, partially offsetting the construction savings. However, the reduction in construction cost more than compensates for this additional student work. On these matched subsets, ReGE-Syn uses the fewest combined construction and execution tokens among Control, Reflexion, AggAgent, and ReGE-Syn. For Reflexion, construction includes self-evaluation and reflection, while execution sums token usage across all actor trials. This comparison counts input plus output tokens and excludes source generation. 

Experience guidance can reduce downstream execution effort. For claude-sonnet-5, ReGE-Syn uses fewer student output tokens and steps than unguided Control on Terminal-Bench 2.0 and Spider2-Lite (Table 4). On Spider2-Lite, SQL calls fall by 50% and output tokens by 30%, whereas both measures remain nearly unchanged on AndroidWorld. 4.2 COMPARISON WITH OTHER MODELS 

With ReGE, a lower-priced model matches higher-priced models of its family at a fraction of their cost. We compare gpt-5.6-luna with ReGE against single unguided executions of two higher-priced models from the same family, gpt-5.6-terra and gpt-5.6-sol, and of the newer gpt-6-luna, which is priced below gpt-5.6-luna. Due to budget constraints, we use the first 50% of tasks by task ID on Terminal-Bench 2.0, Spider2-Lite, and AndroidWorld (task templates with one parameteriza-tion each on AndroidWorld) and the 300 BrowseComp-Plus queries used in our ablations. The other models use the prompts, tools, step limits, and graders of the main Control runs, and their results are paired by task with the gpt-5.6-luna results of Table 2, leaving 468 comparable tasks. On this subset, ReGE raises the average task success of gpt-5.6-luna from 56.8% to 67.4%, compared with 63.9% for gpt-5.6-terra, 67.0% for gpt-5.6-sol, and 49.4% for gpt-6-luna (Table 5 and Figure 1). Including source-pool generation, ReGE costs $0.21 per task at list prices, 58% of the cost of gpt-5.6-terra and 28% of that of gpt-5.6-sol; gpt-6-luna costs $0.009 per task. When the source pool already exists, ReGE costs $0.034 per task, 9% and 4% of the costs of gpt-5.6-terra and gpt-5.6-sol and close to the $0.041 of one unguided gpt-5.6-luna execution. 4.4 WHEN DOES RECORDED EXPERIENCE HELP ?

ReGE-Syn shows its largest gains on pools containing both successful and failed attempts. 

Table 8 compares ReGE-Syn with Control within source-quality groups. Mixed pools show the largest observed success-rate gains in all eight model–benchmark combinations. Across Terminal-Bench 2.0, Spider2-Lite, and AndroidWorld, these gains range from 13.0 to 21.6 percentage points. On BrowseComp-Plus, they reach 48.0 points on GPT and 35.2 on Claude. These results show that source experience need not be uniformly successful to support more effective subsequent execution. 

Source quality also reveals the limits of experience reuse. Fresh successes remain possible when all source attempts fail, but improvements over Control are smaller and inconsistent. On GPT Terminal-Bench 2.0, success rises from 0.0% to 9.4%, whereas both methods remain at 0.0% on GPT Spider2-Lite. When all sources succeed, Control already solves at least 90% of tasks in every model–benchmark combination, leaving less room for improvement. 4.7 FROM RECORDED EXPERIENCE TO FRESH EXECUTION

Execution Case: Recovering a Database from Its Log

# 5 RELATED WORK 

Aggregation of multiple attempts. Repeated sampling produces candidates that can be selected through voting (Wang et al., 2023) or evaluation (Cobbe et al., 2021), or combined through gener-ative aggregation (Jiang et al., 2023; Wang et al., 2024b). Self-MoA jointly aggregates responses sampled from a single model (Li et al., 2025). AggAgent extends aggregation to long-horizon agen-tic tasks by using tools to inspect candidate solutions and retrieve information from their trajectories (Lee et al., 2026). ReGE-Syn shares the goal of combining useful information across attempts. It 9Preprint jointly reads bounded execution records and available artifacts in one coach call, producing guid-ance that a student uses during a fresh interaction with the environment. Agent swarms decompose a task into heterogeneous sub-problems that parallel sub-agents execute concurrently (Kimi Team, 2026); ReGE-Syn studies the complementary step of consolidating the records of parallel attempts at the same task into guidance for one fresh execution. 

Distillation for subsequent execution. Parallel-Distill-Refine constructs a workspace for subse-quent generations using operators that include joint global summarization and candidate selection (Madaan et al., 2025). Kim et al. (2026) adapt PDR to agentic coding by independently summa-rizing rollouts and concatenating selected summaries to condition new rollouts in freshly initialized environments. ReGE-Syn constructs guidance jointly from the retained source records, allowing content choices to account for information across attempts before producing the guide. 

Reflection and agent memory. Reflexion uses verbal reflections on task feedback to guide subse-quent trials (Shinn et al., 2023). ExpeL extracts insights from accumulated experience (Zhao et al., 2024), while Agent Workflow Memory induces reusable workflows (Wang et al., 2024c). Auto-Guide derives context-aware guidelines from offline experience (Fu et al., 2024), and AutoManual organizes knowledge acquired through interaction into instruction manuals (Chen et al., 2024). Voy-ager stores executable skills for later reuse (Wang et al., 2024a); A-MEM organizes experience into linked notes and revises existing memories as new information arrives (Xu et al., 2025). We study task-specific reuse, asking how records from multiple attempts at the same problem can support a new execution with the same base model. 

# 6 LIMITATIONS AND CONCLUSION 

Due to computational budget constraints, our evaluation is limited to four benchmarks: Terminal-Bench 2.0, Spider2-Lite, AndroidWorld, and BrowseComp-Plus, with ablation studies conducted on selected subsets of the evaluation data. Further evaluation should cover broader task settings and repeated executions with aligned settings. We presented ReGE, a framework that turns recorded attempts into guidance for fresh agent exe-cution. Its main implementation jointly synthesizes concrete findings, operations, and pitfalls in a single coach call. Across four benchmarks, experience-guided execution improves mean task com-pletion while keeping the base model fixed. On matched BrowseComp-Plus subsets, joint synthesis sharply reduces guidance-construction tokens relative to adapted iterative aggregation and lowers combined construction and execution usage, excluding source generation. BrowseComp-Plus anal-yses further support compact experience reuse through multiple guidance forms. These findings establish a practical way to make an agent’s prior attempts useful for subsequent action. AI U SE STATEMENT

A.1 SOURCE REPRESENTATION 

Fields and artifacts. Artifacts are produced files on Terminal-Bench 2.0, submitted SQL and query results on Spider2-Lite, submitted answers on BrowseComp-Plus, and action narratives and the final action summary on AndroidWorld. Empty or non-submitting attempts remain in the pool. 

Truncation and overflow. ReGE-Syn, ReGE-Sel and ReGE-A retain at most 120 rendered steps per source, with reasoning and commands truncated to 200 and 160 characters per step, respec-tively. Each artifact is capped at 6,000 characters. If the combined source serialization exceeds 350,000 characters, all artifact bodies are removed while their paths remain. Any remaining excess is truncated at that limit and followed by an explicit marker. Direct history uses a step-only rendering that omits tool observations and separate final-artifact blocks. A.2 PROMPTS AND GUIDANCE DELIVERY 

The boxes reproduce construction prompts and delivery text, with placeholders and line breaks nor-malized for typesetting. 

ReGE-Syn: Joint Synthesis Prompt 

System message. You are an aggregation agent: several independent agents attempted a task (correctness unknown) and you synthesize the single best guidance for a fresh agent. You do NOT have access to the ground truth solution. 

User message. 

TASK: ⟨instruction ⟩

K independent previous attempts (full trajectories + final files): 

⟨serialized source pool ⟩

Write an EXECUTABLE STEP-BY-STEP PLAN for a fresh agent that will solve the task from scratch: (1) numbered steps in execution order, each concrete enough to act on; (2) the critical facts the attempts uncovered – exact paths, values, commands, formats, edge cases – placed at the steps where they matter; (3) pitfalls the attempts exposed and how to avoid them. If the evidence already supports a final answer or artifact, state it in the plan together with how to verify it. The plan must be self-contained: the fresh agent sees only this plan, never the attempts. 

ReGE-A: Alternative Construction Request 

Produce your solution as a single string with exactly two XML sections: 

<explanation>...</explanation><answer>...</answer> . The explanation must be self-contained – a reader who never saw this prompt understands how the answer was derived. The answer is your best final solution to the task.
