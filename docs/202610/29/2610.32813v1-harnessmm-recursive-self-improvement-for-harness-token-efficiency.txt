# Abstract 

Agent harnesses repeatedly invoke reasoning after tool feed-back, even when an earlier call has already fixed the next action. We introduce HarnessMM (Harness Minus Minus), a method for improving harness token efficiency through guarded decision reuse and recursive self-improvement (RSI). RSI iteratively refines companion harness configurations from training feedback, with validation selecting the configuration for deployment. A controller at the model–tool boundary reuses resolved decisions to replace later reasoning callbacks while actor weights remain fixed. Executable Decision Graphs store exact actions, literal arguments, causal dependencies and public guards. Guarded Decision Reuse activates these per-sistent decisions from observed receipts; Certified Callback Substitution executes them through the native interface and records removal of the registered slow callback. New semantic decisions, unsupported evidence and selector abstention in-voke the original actor again. The representation restricts what feedback may change, while complete-task measurements establish quality and cost. On HumanEval, HarnessMM pre-serves Codex success at 90.82% while reducing Tokens/task (k) from 66.72 to 47.02 (29.54% saving). For DeepSeek Har-ness, success rises from 71.43% to 85.71% while Tokens/task (k) fall from 96.28 to 11.62 (87.93% saving). A separate MBPP ablation measures 26.91% lower cost than single-use graphs and 19.52% lower cost than retained callbacks. These results establish guarded decision reuse as a practical way to reduce repeated reasoning in existing harnesses. 

# 1 Introduction 

Agent harnesses connect model reasoning to tool execu-tion. ReAct alternates reasoning, actions and observa-tions [46]; SWE-agent demonstrates that interface design shapes software-engineering performance [44], and Tool-former learns when to call APIs [33]. After each tool result, the harness must decide whether the observation demands new reasoning or merely permits an already resolved action to exe-cute. Repeated deliberation can regenerate decisions whose semantics have not changed. Efficiency methods intervene at different points. Prompt compression and history management reduce the input re-played into a call [16, 17, 21, 30, 42]. Fast–slow architectures and routing change who reasons and how deeply [4, 27, 45]. Executable skills, observation-independent plans and com-piled tool dependencies reuse or schedule prior computa-tion [19, 40, 43]. ActionEngine further executes task programs against reusable application memory with reactive repair [52]. These methods already establish the value of programmatic ex-ecution. HarnessMM studies a narrower contract: an episode-specific action remains literal, later feedback changes its el-igibility, and the execution record identifies the reasoning boundary actually bypassed. Feedback can optimize instructions and agent programs through APE, STOP, ADAS, Self-Refine and Reflexion [13, 24, 36, 49, 53]. Such optimization constructs a harness; its deployment still determines which callbacks recur. Jev’s typed probability interface [1] motivates compact candidate selec-tion, but adding a selector does not remove the original call-back automatically. We call this accounting mismatch the Sub-stitution Paradox : computation is saved only when eliminated reasoning exceeds added authorship, selection and recovery. A concrete opportunity appears when slow reasoning fixes several actions before their execution feedback arrives. After writing a program, the next compilation command can already be specified; after compilation, a successful return code can activate an already-specified test command. We call a decision resolved when prior reasoning has fixed its action and literal arguments; the unknown tool receipt determines whether that action is ready to execute. The example separates semantic un-certainty from execution uncertainty and suggests a different role for feedback: activating a resolved decision. Our insight is that such decisions can persist across feedback boundaries as guarded executable commitments. An authored graph can serve multiple transitions while its continuations remain re-solved; new inference returns control to the slow actor, which may reason and author further graphs throughout the task. We introduce HarnessMM (Harness Minus Minus), a method for improving harness token efficiency by chang-ing when the harness invokes its reasoning model (Figure 1). HarnessMM inserts a controller at the native decision bound-ary while keeping model weights, tools and task interfaces fixed. Executable Decision Graphs (EDGs) store actions and literal arguments already resolved by slow reasoning, together with their dependencies and public execution guards. Guarded Decision Reuse (GDR) retains these decisions across tool transitions and checks whether observed receipts satisfy their guards. This changes the harness’s execution policy so that resolved actions avoid repeated context input and reasoning output while unresolved decisions retain access to the orig-inal reasoning process. Complete-task accounting includes graph authorship, selection, remaining slow calls, fallback and unsuccessful executions. Recursive self-improvement (RSI) iteratively refines companion harness configurations: the current harness supplies training feedback for candidate edits, validation selects the retained candidate, and that har-ness supplies the next round’s training feedback. The selected configuration is frozen before test evaluation (Appendix B.2). We integrate HarnessMM into Codex and DeepSeek Har-ness and evaluate each against its original harness. On the same 98 HumanEval test tasks, HarnessMM preserves Codex success at 90.82% while reducing Tokens/task (k) from 66.72 to 47.02, a 29.54% saving. For DeepSeek Harness, success rises from 71.43% to 85.71% while Tokens/task (k) fall from 96.28 to 11.62, an 87.93% saving (Section 5.3). These com-parisons demonstrate that improving when a harness invokes reasoning and executes actions can reduce token consump-tion while preserving or improving task performance. An MBPP ablation isolates persistent decision reuse and callback removal, measuring 26.91% lower cost than single-use graphs and 19.52% lower cost than retained callbacks. Companion studies evaluate their benchmark-specific instruction and con-text configurations separately (Section 5.4). Our contributions are: • EDGs separate resolved action semantics from feedback-dependent readiness, making prior deliberation exe-cutable at future tool boundaries. • GDR retains the graph and uses public receipts to activate causally ordered actions while reserving new decisions for slow reasoning. • CCS substitutes native execution for registered callbacks and verifies omission with receipt-bound certificates. The MBPP ablation measures how reuse and callback substi-tution affect success and complete task cost. 

# 2 Related Work 

Prompt, context and reasoning compression. LLMLin-gua and its successors compress prompt inputs [16, 17, 30]; AgentDiet and observation masking reduce replayed trajectory context [21, 42]. Thinking budgets control generated reason-ing [15]. These methods reduce the size or depth of a call; HarnessMM targets whether that call needs to recur at all. 2Fast–slow agents and model routing. Talker–Reasoner sep-arates response and planning [4]; CogRouter adapts cognitive depth [45]; boundary-guided routing chooses the reasoning model [50]. Jev motivates typed compact decisions [1]. Our Jev-motivated typed selector uses a candidate-ID/abstention interface, with single-token decoding when selection requires a model call. HarnessMM studies whether such a compact decision actually removes a future reasoning callback. 

Skills, memory and reusable programs. Chain-of-thought prompting exposes intermediate reasoning [41], Voyager re-tains executable skills [40], and SkillLens retrieves procedural context [25]. A skill or macro can inform future reasoning or encapsulate a routine. An EDG instead stores episode-specific, fully resolved semantic commitments; public execution condi-tions control their activation. This distinction allows execution to replace a reasoning call rather than merely guide it. 

Agent and harness optimization. APE, STOP and ADAS improve prompts, programs and agent configurations from feedback [13, 49, 53]. Self-modification methods extend the search to improvement operators [38, 47, 51]. HarnessMM changes when a harness calls its reasoning model and when it directly executes a previously resolved action. Instruction optimization, context compaction and RSI supply companion configurations; they are outside the core execution method and retain separate experimental attribution. Their development protocols and costs appear in Appendix B.2.

# 3.3 The Substitution Paradox 

The paradox arises when fast–slow composition adds a deci-sion without removing its downstream deliberation. If a fast stage costs Cf but removes none of an original continuation’s 

Cn tokens, its additive path costs Cn + Cf . Short output alone cannot resolve this overhead: typed output and frequent fast-path activation do not establish callback elimination. A beneficial substitution requires 

Cremoved > C introduced , (3) where introduced computation includes authorship, routing, additional context and any fallback or recovery. This cost condition and the capability constraint address separate re-quirements. 

# 4 HarnessMM: Reusing Decisions 

HarnessMM changes the route from tool feedback to the next native action. EDG stores resolved decisions, GDR deter-mines their eligibility, and CCS substitutes native execution for registered slow callbacks. The controller integrates with an existing harness through its public-state adapter, slow-call entry point and native action dispatcher. 

Method boundary and fixed configuration. The core method decides whether a stored action can replace the next reasoning call. Prompt editing, context compaction and fi-nalization rules configure the surrounding harness. They are developed on training data, selected before evaluation and held fixed during each run. The runtime selector chooses an eligible EDG node or abstains; it does not choose which optimization techniques to combine. Appendix D.5 maps each reported configuration to its actual intervention. Figure 1 separates harness RSI from execution within a task. The upper row shows RSI revising the harness using training task results and complete token cost; the lower row shows the 3GDR and CCS graph edits. At runtime, the controller ingests each public receipt, updates eligibility, and either executes a stored action or invokes the slow actor. The latter can resolve new decisions and author another graph. 

# 4.1 Executable Decision Graphs (EDG) 

An EDG stores actions whose semantics and arguments slow reasoning has already resolved. For example, a coding actor can fix a file-write action, a make command and a pytest 

command. Public guards determine whether these stored ac-tions can execute; later receipts supply readiness evidence without regenerating their arguments. At slow decision i, actor H0 emits the current tool action and an EDG Gi = ( Vi, E i), a bounded executable continua-tion. Its future decision nodes are

its public execution guard. The author fixes gj with the node; the adapter evaluates it against subsequently observed receipts. Each node has its own guard. The input EDG in Figure 1 combines reasoning, context compaction, fast decisions and tool use. For the coding exam-ple, guards can check a missing file, available build inputs or a successful build. Dependencies must also be complete. Edges connect the root or an earlier node to a successor, forming an acyclic graph. Missing or rejecting receipts prevent admission; an empty graph returns control to the slow actor.

# 5 Experiments 

# 5.1 Evaluation protocol 

All methods use the same tasks, backbone, original tools, task limits and scorer. All compared methods, including baselines and native harnesses, receive token-efficiency prompts and an explicit objective to reduce complete-task input-plus-output token consumption while preserving task performance. Suc-cess uses the benchmark evaluation endpoint, and token cost includes input plus output for all paid calls, including failures. Development optimization cost is reported separately from complete-task execution. Full-population coding comparisons use custom 20/20/60 splits: HumanEval 33/33/98 and MBPP 85/85/257, with deterministic rounding and fixed task IDs. TRAIN supplies revisions, validation selects TRAIN-frozen candidates, and TEST measures the selected configuration. The coding ablations evaluate the core execution method; na-tive harness pairs evaluate its integration with fixed context and finalization settings. Figure 2 retains the companion studies. Appendix D.5 identifies their differing mechanisms, popula-tions and cost scope.

# 6 Limitations 

Savings depend on provider input, cache and context account-ing and on the availability of resolved actions. New semantic decisions require slow reasoning. Authorship, selection and recovery can outweigh avoided calls. Public-state adapters are task specific, and small development sets leave policy-level quality differences uncertain. 

# 7 Conclusion 

HarnessMM improves harness token efficiency by storing resolved decisions, checking when they can execute and us-ing them to replace repeated reasoning calls. Complete Hu-manEval comparisons on all 98 test tasks preserve Codex suc-cess at 90.82% with 29.54% fewer actor tokens and improve DeepSeek Harness from 71.43% to 85.71% with 87.93% fewer tokens. 11 A HarnessMM visual harness RSI study 

The eight MiniWoB++ harness RSI iterations in Figure 5 evaluate HarnessMM. Every RSI iteration evaluates all 32 training tasks once per arm, with identical task instances and actor seed. The actor is Qwen3.5-9B; inputs are full screenshots, the action limit is 15 and the episode allowance is 180 seconds. Single-use EDG permits one future execution per authored graph. HarnessMM retains eligible nodes across later tool-feedback boundaries. # B.1 QA profiles and execution

# C.1 Execution variability and paired instruction effects

Run θ combines slow actor calls, fast selection and tool execution operators. A client can prescribe a concurrency and submission schedule s, but cannot thereby fix the server’s microbatch or numerical path. Below, i indexes decisions within one execution, and k indexes offline rule-development rounds. To measure an instruction edit, we compare the original and edited harnesses under the same prescribed schedule. τt(h′, h ; s) = E[mb(yt(h′, s )) − mb(yt(h, s ))] . (10) The expectation averages over execution conditions within that schedule. # C.4 Action adapter: CoT-authored conditional execution

# D Execution contract, algorithm and evidence attribution 

HarnessMM replaces repeated reasoning calls with stored actions through a contract between a slow author, a persistent executor and the existing native harness boundary. A directed action graph alone is a standard executable planning representation. Here each admitted continuation has immutable arguments, public feedback can only change its readiness, and the native request ledger records omission of a specified reasoning callback. These restrictions make reuse inspectable. They do not imply that every authored action is correct or every graph lowers cost. 

# D.1 State and execution algorithm 

A graph instance contains an authored root action, a finite acyclic set of future nodes, literal native arguments, dependencies and public guards. Runtime state contains the completed native receipts, the remaining graph nodes and the public episode history. Graph content and runtime state are different objects: completing a predecessor changes the latter without rewriting the authored action. 1. At a native decision boundary, register the parent callback and ingest the preceding public tool receipt. Validate its association with the action that produced it. 2. Construct the eligible set from unresolved nodes whose dependencies are complete, public guards pass and arguments meet the adapter’s closure checks. 3. If exactly one node is eligible, use the declared deterministic route. If several are eligible, the configured typed selector chooses a candidate ID or abstains. Charge any model-based selector input and output. 4. On admission, execute the selected literal arguments through the original native interface. Record the result and compare it with the authored node. Emit an omission certificate only after checking execution and absence of the registered slow request. Mark the node completed and retain the unresolved remainder of the graph. 5. On rejection, an empty set or abstention, invoke the original slow actor with its public task context. Record the author request and any fallback. A newly authored graph replaces the unresolved remainder; already executed receipts remain in the episode history. 6. Continue under the common benchmark limits. A terminal answer uses the same commitment point and stops. The native scorer evaluates the complete task; the request ledger charges every paid call. This algorithm describes the full mechanism. The coding adapter uses literal terminal commands and observed tool results. Instruction-only and answer-acceptance studies use different candidate producers, stated in Appendix C; they cannot be treated as independent demonstrations of persistent coding graphs. 15 D.2 Closure, guards and structural invariants 

Literal closure and semantic closure. Literal closure is a syntactic restriction: all executable arguments have concrete values, with no placeholder to bind from unseen feedback. It is checked by the action schema and candidate-membership audit. Semantic closure is stronger: prior reasoning has determined the action’s meaning and its future applicability is captured by the declared guard. A concrete command can still be semantically wrong. General semantic closure is therefore not established merely by parsing literal arguments. For a fixed authored decision d and public state s, let valid( d, s ) mean that the action has its intended task meaning at that state. Interpreting guard acceptance as semantic permission additionally assumes 

eligible( d, s ) = 1 = ⇒ valid( d, s ). (12) This implication depends on the adapter and the authored guard. The implementation enforces the left-hand checks; complete native task evaluation measures their quality consequences. There is no statewise correctness guarantee for arbitrary tools or tasks. 

Argument immutability. Assume the configured adapter uses the validated graph and native interface, the graph objects are not modified after authoring, and the recorded receipts are faithful. A reused node executes the literal arguments authored for that node. The typed selector returns only a node ID; it has no argument-generation interface. Native dispatch reads the selected stored arguments, and certificate verification compares those values with the tool receipt. This establishes an execution invariant under the stated assumptions, independently of task success. 

Dependency-respecting execution. Initially, no future node is completed. At each transition, eligibility admits only a node whose predecessor receipts are in the completion map. A completed node is removed from the unresolved set. Induction over transitions therefore gives predecessor-respecting execution with at most one dispatch per node instance. The initial acyclicity check prevents a future node from requiring its own completion. A later author call can create an identical graph, but it is a separate paid authoring event. 

Omission evidence. A valid certificate binds the authored graph instance, selected node, exact native arguments, predecessor receipt, tool receipt and registered callback. The physical request ledger independently establishes absence of the specified slow request at that boundary. This is a structural observation about the executed route. It does not establish an identical counterfactual trajectory, an absent call’s token quantity, or a task-quality improvement. Comparisons on the same full task sets measure these effects. 

# D.3 Break-even analysis without counterfactual token attribution 

Let A denote additional author and selector actor tokens and F additional fallback tokens. If K eliminated callbacks would have costs c1, . . . , c K , a same-trajectory token calculation gives net saving only when P 

> j

cj > A + F . Under the simplifying assumption of a common callback cost c > 0, the condition is K > (A + F )/c . This relation describes the dependence on reuse coverage; it is not a prediction of measured saving, because the omitted calls are not executed and the substituted trajectory can differ. The reported estimator is instead the difference in total tokens across all episodes for each method. Every arm uses the same independent task membership and execution contract, and each arm’s numerator includes its actual author, selector, slow, finalization and paid unsuccessful calls. Shared authoring is assigned once to its declared population. Cached provider input remains counted under the token protocol. CPU guards and native tools affect time and behavior, but their work cannot be added to a token total without an independently defined resource conversion. 

# D.4 Novelty and closest mechanisms 

ReWOO separates planning from tool observations and supports dependency-bound evidence variables [43]; LLMCompiler plans and dispatches tool dependencies for parallel execution [19]. HarnessMM shares executable planning and reuse with these approaches. # F.4 Additional related-work and adapter context 

Finally, uncertainty in model evaluation arises at multiple levels: task sampling, prompt choice, random seeds, execution order, and numerical/runtime behavior [10, 31, 48]. Repeating one task characterizes its execution distribution, with the task remaining the independent sampling unit. We use paired source-group estimates, retain all comparison endpoints, and separate exploratory inspection from frozen comparisons [6, 7, 32]. Crossed and nested dependence must be treated explicitly rather than pooling all response cells as independent samples [29]. Efficient serving mechanisms such as PagedAttention address execution resources [20]; repeated-request controls characterize variability under the chosen runtime. The closest evaluation alternatives already address substantial parts of our question. FormatSpread quantifies spurious prompt-format sensitivity [35]; ProSA and POSIX examine prompt sensitivity at finer granularity [3, 54]; PromptEval estimates performance distributions over prompts efficiently [31]. PARC analyzes language/image transformations in vision-language models, with certainty derived from conformal answer scores rather than repeated execution [34]. Our comparisons combine instruction-content controls with repeated execution and image interventions. They examine how these sources of variation affect the interpretation of a quality–cost comparison. Vision-language systems combine image representations with instruction following, and visual-programming approaches expose intermediate operations that can be inspected or recombined [22, 37]. These approaches motivate treating instructions as controls over visual decisions. Balanced and compositional benchmarks, contrastive examples, and image interventions examine complementary aspects of this problem [11, 14, 18, 26]. Our true-image and shuffled-image conditions provide a within-sample diagnostic of image dependence. The same commit-or-defer interface accepts terminal answers. A text-QA adapter obtains an actor-generated draft, checks its source, type, and format, and either returns it or calls the original answering procedure. The draft and fallback are both charged. The action adapter can avoid reasoning calls, whereas the answer adapter changes request and response lengths. Both preserve the benchmark task interface, and complete-task accounting covers every model call along either path.
