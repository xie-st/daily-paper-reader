# Abstract 

With the rise of large language models, agentic systems are becoming increasingly autonomous, as they write code, call tools, revise prompts, and propose modifications to their own components. This autonomy raises a fundamental question for safe self-improvement: can an automated gate like a reward model or an automated reviewer reliably decide whether a proposed update should be accepted? The difficulty is structural. The gate must be a terminating, computable procedure, while the property we ultimately care about, namely whether an update is a genuine semantic improvement, depends on potentially unbounded program behavior. We formalize this mismatch by modeling agents as programs and defining improvement in terms of a semantic score that need not be computable. We study two evaluation abstractions. The first is a certifier that approves or rejects an update. The second is a search procedure that, given access to a proposal generator, attempts to output some improving candidate if one exists. We show that, in the fully general setting, no terminating procedure can simultaneously guarantee reliability (never accepting a non-improvement) and non-conservatism (never missing an available improvement): self-referential constructions can force any such gate or searcher to fail. Randomized gates with bounded error face the same limit. We then identify a standard decidable regime used in practice (bounded evaluation and a finite proposal budget) under which exhaustive simulation yields a terminating search procedure with the desired guarantees. We also show the limit of this recovery: a chain of accepted updates can raise the bounded score in every round while the true score falls. Our results draw a boundary between unbounded, universal settings where correctness guarantees collapse and bounded settings where they can be recovered by design. 

# 1 Introduction 

Many modern “agentic” pipelines follow the same pattern: an agent proposes a self-update (a code patch, prompt rewrite, new checkpoint, tool policy, etc.), and an automated gate decides whether to apply it (Lu et al., 2024; Yamada et al., 2025). The gate may be a reward model, a regression test suite, or an automated reviewer that must terminate and output accept/reject. The intended notion of improvement, however, is semantic: whether the updated agent is genuinely better depends on unbounded program behavior, long-horizon interactions, and open-ended tool use (Wang et al., 2023). This mismatch creates a concrete failure mode that is now routine in practice: once the proposal mechanism can anticipate or condition on the gate, it can “optimize the gate” rather than the intended objective. In other words, the proposer can exploit the evaluator as a predictable part of the environment. This paper formalizes that failure mode and proves a sharp boundary: in a fully general setting, no terminating gate or search procedure can be both reliable and non-conservative. The core obstruction is not statistical; it is structural. If candidates can depend (directly or indirectly) on the gate’s decision, then self-reference yields diagonal constructions in which any total computable gate must fail, either by accepting a non-improvement or by rejecting (or missing) an available improvement. 1arXiv:2610.21646v1 [cs.AI] 15 Oct 2026 We model an “agent” as an executable artifact (e.g., checkpoint + code) encoded by a program index p ∈ N,with behavior given by the partial function φp. Our first theorem shows that even for an extremely simple semantic score J (halting-and-output-1 on a fixed input), there is no total computable certifier that accepts exactly the strict improvements. The proof builds a self-referential candidate whose behavior flips depending on whether it is accepted, using Kleene’s recursion theorem (Kleene, 1952). This captures, in the starkest possible form, the modern evaluator-hacking phenomenon: the proposal mechanism can construct candidates that are “good if rejected” and “bad if accepted.” A natural response is to replace certification by search: rather than deciding each candidate, we ask for a total searcher that returns some improvement whenever the proposal mechanism contains one. Our second theorem shows that this does not help in full generality. Even if the searcher is given the code of the proposal enumerator, self-reference allows the enumerator to propose a candidate whose behavior depends on the searcher’s output, forcing any proposal-respecting total searcher to violate soundness or weak completeness. However, these negative results rely on unbounded behavior and universal quantification over proposal mechanisms. We then formalize a standard regime used in practice (bounded evaluation and a finite proposal budget) and show that the guarantees can be recovered relative to the bounded proxy . In that regime, exhaustive simulation yields a terminating searcher that is sound and weakly complete for the bounded score. This draws a clean line between (i) an unbounded universal regime where correctness guarantees collapse, and (ii) a bounded regime where they can be recovered by design. Two further results sharpen this picture. First, randomness does not help. A gate that flips coins and errs with probability at most 1 /3 can be converted into a deterministic sound and complete certifier, so it cannot exist either (Proposition 1). Second, the bounded regime has a blind spot of its own. We construct a chain of updates in which every step raises the bounded score and every step lowers the true score (Proposition 2). Guarantees relative to a proxy therefore do not control drift of the true objective across rounds.

The proof ingredients are classical: diagonalization, the s-m-n theorem, and Kleene’s recursion theorem (Kleene, 1952). We do not claim new computability-theoretic techniques. It separates the impossibility in the unbounded setting from its recovery in the bounded setting. It turns the folklore claim that evaluator hacking is unavoidable once the proposer can model the gate into a theorem with explicit assumptions. The formalization also yields results beyond the single update step, namely the randomized-gate bound of Proposition 1 and the drift construction of Proposition 2. # 2 Preliminaries 

This section bridges the gap between common ML intuitions (models, checkpoints, loss functions) and the computability-theoretic formalization used in our impossibility result. First, we model an “agent” as an executable artifact: e.g., a serialized model checkpoint plus inference code, a Python package, or a container image. Any such finite binary string can be encoded as a natural number. Consequently, we identify each agent with a program index p ∈ N (a Gödel number (Gödel, 1992)). Let φp denote the (partial) function computed by program p under a fixed universal machine. Given an input 

x (e.g., a prompt, an environment state, or a task instance), φp(x) denotes the output/action of the agent. Because an agent may run arbitrary code (loops, recursion, tool calls), φp(x) may diverge (run forever). Thus 

φp is in general a partial computable function . Before we approach the core contributions of this paper, let us introduce another fundamental tool (Kleene, 1952): 

Kleene’s Recursion Theorem (Fixed-Point Theorem). For any total computable function f : N → N,there exists an index e ∈ N such that 

φe = φf (e). (1) Intuitively, this guarantees the existence of self-referential programs whose behavior can depend on (an encoding of) their own description. We use this theorem to construct adversarial candidates in the proofs of Theorems 1–2. Another central theme in alignment and evaluation is the gap between what we wish the agent to optimize, and what we can compute or verify reliably. 3Semantic objective (ground truth). We represent the intended notion of performance by a semantic score functional 

J : N → S , (2) where S is a score set, e.g., {0, 1} for success/failure, or R for reward. Crucially, J is allowed to be uncomputable 

in general: perfect evaluation of real systems may require unbounded testing, reasoning about all inputs, or solving problems that are undecidable in the worst case. 

Certifier (proxy). Since J may be unavailable, the system may rely on a certifier

Accordingly, we assume V is total computable : it always halts with an output. 

# 3 Self-Improvement Loop 

We view self-improvement abstractly as a process that proposes a candidate modification q to replace a current agent p, and applies the update only if V (p, q ) = 1. To formalize the notion of “improvement” relative to the semantic objective J, we use: 

Definition 1 (Strict improvement) . Given J : N → S equipped with a strict order >, we say that q is a 

strict improvement over p if J(q) > J (p). The properties we would like a verification-based self-improvement system to satisfy are: 

Definition 2 (Soundness and completeness of a certifier) . Fix J and strict improvement as above. A total computable V : N × N → { 0, 1} is • Sound if ∀p, q (V (p, q ) = 1 ⇒ J(q) > J (p)). • Complete if ∀p, q (J(q) > J (p) ⇒ V (p, q ) = 1). Soundness corresponds to “no reward hacking / no false approvals” (safety), while completeness corresponds to “do not block genuine progress” (non-conservatism). Our main theorem shows that, for sufficiently expressive agents (allowing self-reference), these goals cannot be simultaneously achieved by any total computable certifier.

Rice’s theorem says nothing about finding witnesses with access to the generator’s code. # 4 Searching for Improvements 

Theorem 1 rules out a total computable certifier that accepts exactly the strictly improving updates. A natural response is to weaken the requirement: instead of certifying every candidate update, we only ask for a total computable searcher that returns some improvement whenever the proposal mechanism contains one. We show that even this goal is impossible in full generality.

E : N × N → N, (7) where E(p, i ) denotes the i-th proposed modification for base agent p.

# 5 Randomized, Hidden, and Stateful Gates 

Real gates rarely look like the deterministic certifier of Theorem 1. A reward model may use randomness. Its weights may be hidden from the proposer. It may keep state across queries. This section explains why these variations do not escape the impossibility. 

Randomized gates. Suppose the gate may flip fair coins. We model it as a probabilistic machine V that on input ( p, q ) halts on every coin sequence and outputs a bit. We do not ask for exact decisions, only for bounded error. 

Proposition 1 (No randomized certifier with bounded error) . Let J be the score functional from Theorem 1. There is no probabilistic machine V that halts on every input and every coin sequence and satisfies, for all 

p, q :1. if J(q) > J (p), then Pr[ V (p, q ) = 1] ≥ 2/3,2. if J(q) > J (p) does not hold, then Pr[ V (p, q ) = 1] ≤ 1/3.Proof. Suppose such a V exists. Fix an input ( p, q ) and consider the binary tree of coin sequences explored by 

V . Every path halts, so by König’s lemma the tree is finite. A deterministic machine can therefore simulate all paths and compute the exact acceptance probability α(p, q ), a rational number. Define V ′(p, q ) = 1 if 

α(p, q ) ≥ 1/2 and V ′(p, q ) = 0 otherwise. Then V ′ is total computable, and the error bounds make it sound and complete for strict improvement. This contradicts Theorem 1. 7The assumption that every coin sequence halts can be weakened. de Leeuw et al. (1956) show that machines that halt with probability one and err with probability bounded below 1 /2 decide only decidable sets, so the same conclusion holds. The same simulation also derandomizes any randomized searcher that returns, for every input, one fixed value with probability at least 2 /3. The deterministic version returns that value, so Theorem 2 rules it out as well. The lesson is simple. Randomness can hide the gate’s decision from the proposer, but it cannot enlarge the class of relations the gate decides. 

Hidden gates. Theorems 1 and 2 quantify over gates. For every gate there exists a candidate on which it fails, and the proof builds this candidate from the code of the gate. Hiding the gate changes who can carry out this construction. A proposer without access to the gate’s code cannot build the diagonal candidate. It does not change whether the failure exists. The guarantee “sound and complete for all inputs” is still false, because the bad input pair exists whether or not anyone can find it. Hiddenness is therefore a defense against a specific attacker, not a repair of the guarantee. It also degrades in practice: query access, accept and reject outcomes, and leaked transcripts all let a proposer learn a predictive model of the gate (Appendix A). 

Stateful gates. A gate that keeps state across queries is a machine with an extra state argument. Fix any reachable state s and consider the total computable certifier Vs(p, q ) = V (p, q, s ). Theorem 1 applies to Vs.So for every state the gate can be in, there is a candidate on which it fails in that state. State reshuffles which candidate defeats the gate, but some candidate always does. 

Human oversight. A gate that consults a human is not a total computable procedure, so our theorems do not constrain it. This is a design lesson rather than a loophole. The impossibility concerns fully automated gates, and it bounds what automation alone can guarantee. Grounding decisions outside the loop is exactly what the theorems leave open.

How fast drift can grow when the proposer adapts to the re-evaluation schedule is open. 98 Discussion 

Why the diagonal breaks under bounded evaluation. In the proofs of Theorems 1–2, the adversarial candidate q runs the gate ( V or S) as a subroutine. In the bounded regime of Theorem 3 this no longer works. The searcher ST,B,T E simulates each candidate for up to T steps across B proposals, so its own running time exceeds T . A candidate that runs ST,B,T E inside itself therefore cannot halt within T steps. Its bounded score is JT (q) = 0, and the self-referential flip no longer yields a strict improvement. This is how bounded evaluation blocks the diagonal. 

What the theorems do and do not claim. Theorems 1–2 are worst-case results. They rule out universal procedures that always halt and are sound and complete (or weakly complete) for all sufficiently expressive agents and proposal mechanisms. They do not imply that self-improvement cannot occur. They also do not imply that useful gates cannot be built for restricted settings. What they show is a gap between semantic correctness, as measured by J, and any terminating gate that must work uniformly over all candidates and generators. 

Where undecidability enters. The diagonal constructions in Theorems 1–2 use two modeling freedoms. Agents may run unboundedly, and candidates may depend on the evaluation procedure through self-reference. Both freedoms are natural for tool-using agents that execute code and adapt their patches. Theorem 2 even hands the searcher the code of the proposal enumerator. A total method that is sound and weakly complete for all generators still does not exist. 

One-sided guarantees and intermediate regimes. Only the joint requirement fails. Each guarantee alone is trivial. The gate that rejects every update is sound, and the gate that accepts every update is complete. A more useful one-sided design is proof-carrying updates. Here the gate accepts q only when the proposal comes with a certificate, checked by a fixed sound proof system, that J(q) > J (p). The Gödel machine of Schmidhuber (2003) is the canonical design of this kind: it rewrites its own code only after an internal searcher finds a proof that the rewrite raises expected utility. Such a gate is total and sound by construction, but it cannot be complete. For the score of Theorem 1, the set of true improvement pairs {(p, q ) : J(q) > J (p)} is not computably enumerable, since witnessing J(p) = 0 is a Π 1 fact. The set of pairs any fixed proof-checking gate accepts is computably enumerable. Such a gate therefore misses infinitely many genuine improvements. This gives a precise account of the conservatism of proof-gated self-improvement. Between the unbounded setting of Theorems 1–2 and the finite regime of Theorem 3 lie further restrictions. Section 5 treats three of them: randomized, hidden, and stateful gates. Other examples are proposal mechanisms that cannot condition on the gate (Appendix A), update languages whose effect on the score is decidable, and gates with more compute than the proposer. Mapping which restriction restores which guarantee is a concrete open problem. 

Decidable regimes. Section 6 formalizes a restriction that practice already uses, namely bounded evaluation and finite search. Under it, sound and weakly complete search exists (Theorem 3). The impossibility therefore comes from the unbounded and universal setting alone. Explicit design choices such as timeouts and finite candidate budgets remove it. 

Implications for evaluation pipelines. In ML terms, V and S stand for reward models, test suites, and automated code review. Theorems 1–2 show that no single terminating mechanism can bridge proxy evaluation and semantic improvement once behavior is unbounded and proposals can self-refer. Reliable pipelines therefore need combinations of bounded evaluation, restricted update languages, staged deployment and sandboxing, and one-sided checks that trade completeness for safety. 

Implications for automated research pipelines. Recent work builds end-to-end pipelines in which a language-model “scientist” generates ideas and code, runs experiments, and a second model or a scripted rubric reviews the outcome (e.g., The AI Scientist (Lu et al., 2024; Yamada et al., 2025)). Such a pipeline matches our model. The idea generator and the experiment runner form a proposal mechanism, and the reviewer acts as a computable gate. 10 Our results do not claim that any particular system is broken. They state a worst-case limit that such systems meet as their autonomy grows. Suppose the proposal mechanism can condition on the gate, for example by learning to predict the reviewer’s preferences. Then no terminating gate can guarantee both that it never accepts a non-improvement and that it never rejects or misses an available one, uniformly over all proposals. This is the regime where benchmark overfitting, reward hacking, and self-deception enter. The system optimizes what the reviewer measures, not what the designer intends. At the same time, automated research loops run with bounded compute and finite candidate budgets, so they sit in the decidable regime of Theorem 3. Exhaustive evaluation within a fixed budget then gives reliable guarantees with respect to the bounded proxy. The remaining risk is the gap between the bounded proxy and the intended objective. Section 7 shows that this risk is real even without an adversary, since accepted updates can raise the benchmark score while the true score falls. This motivates design choices already common in practice, such as timeouts, finite proposal budgets, restricted update languages, sandboxing, and occasional human grounding (Jimenez et al., 2023). 

Interactive and environment-coupled scores. A natural worry is that real agents are evaluated through interaction with an environment, while J in Theorem 1 looks only at φp(0). For the negative results, this restriction is harmless. The score J may be any functional that depends only on the partial function φp.Examples are the expected reward of p in a stochastic environment over a fixed horizon, the success rate on a benchmark distribution, or any scalar summary of trajectories obtained by reading φp as a policy over observation histories. As long as J is extensional and two comparable values are attainable, the diagonal of Theorem 1 applies, and Theorem 2 extends to interactive search in the same way. A certifier that fails for a static program also fails when evaluation must simulate an adaptive environment on top. The positive result needs more care. A finite horizon alone does not make expected reward computable. Theorem 3 extends to interactive evaluation only under explicit assumptions: finitely many actions and observations, computable transition probabilities with rational values, computable rational rewards, and a cap on the agent’s compute per step. Under these assumptions the evaluation tree is finite and every quantity in it is rational, so the interactive score is total computable and the searcher of Theorem 3 carries over (Proposition 3 in Appendix B). Without them, exact comparison of scores can itself be undecidable, and only approximate or one-sided guarantees remain. 

# 9 Related Work 

Our results sit within classical limits in computability theory (Cooper, 2017). The impossibility of a universal improvement certifier is aligned with the broader principle that non-trivial semantic properties of programs are undecidable, as captured by Rice’s theorem (Rice, 1953). While Rice’s theorem is often stated for properties of single programs, our setting concerns a relational property between a base agent and a proposed modification, and we use explicit fixed-point constructions tailored to this verification-gated “self-improvement” interpretation. We emphasize that the technical tools are classical; the novelty is the ML-facing formulation (i.e., modeling automated self-improvement as a gated update loop with explicit reliability and progress guarantees) and the resulting boundary between an unbounded regime where such guarantees cannot hold uniformly and a bounded regime where they can be recovered by design. The self-reference used in our constructions is enabled by Kleene’s Recursion Theorem (Kleene, 1952), a standard tool for building programs whose behavior depends on their own descriptions. In AI safety and agent foundations, related obstacles arise when agents attempt to reason about, verify, or safely delegate to more capable successors. Work on self-referential agents, including the Löbian obstacle, tiling agents, and Vingean reflection, studies conditions under which an agent can reason about successor systems without collapsing into inconsistency or conservatism (Soares & Fallenstein, 2015; Yudkowsky & Herreshoff, 2013). Our contribution is to translate these computability-theoretic phenomena into the concrete language of modern ML evaluation pipelines (reward models, test suites, and automated reviewers), and to show that replacing certification with search does not avoid the limitation when proposal mechanisms can adapt to the evaluator. Two lines of prior work address self-improvement directly. Schmidhuber (2003) proposes the Gödel machine, a self-referential system that rewrites any part of its own code once an internal proof searcher shows that the 11 rewrite raises expected utility. In our terminology this is a proof-carrying gate. It is sound by construction, and the Discussion (Section 8) locates its unavoidable cost: the set of provable improvements is computably enumerable while the set of true improvements is not, so every such gate misses infinitely many true improvements. Everitt et al. (2016) formalize agents that can modify their own policies and utility functions and study when a rational agent will preserve or subvert its goals. Their question is decision-theoretic and takes the evaluation of outcomes as given. Our question is computational: whether any terminating procedure can perform that evaluation at all. The two are complementary, and the drift result of Section 7 sits between them, since it shows the true score falling through the gap between a proxy and the objective, without any self-modification of goals. A complementary line of work studies the empirical and conceptual phenomenon whereby optimizing a proxy objective diverges from the intended goal. Amodei et al. (2016) identify reward hacking as a core problem in AI safety, observing that agents can exploit misspecified reward signals in ways unintended by the designer. Manheim & Garrabrant (2018) formalize several variants of Goodhart’s law for machine learning, distinguishing regressional, extremal, causal, and adversarial failure modes by which a proxy metric ceases to track the true objective under optimization pressure. Skalse et al. (2022) provide a formal framework for reward hacking in reinforcement learning, defining conditions under which a proxy reward function can be exploited by a sufficiently capable policy, and showing that such exploitation is generic rather than pathological. More recently, Pan et al. (2022) empirically demonstrate that reward model overoptimization degrades true performance as optimization pressure increases, even when the proxy initially correlates well with the ground truth. Our results complement this literature from a computability-theoretic angle. The reward hacking literature typically studies statistical proxy-objective gaps: the proxy is computable but misspecified, and failure arises from distributional shift or optimization pressure. Our impossibility results show that even if the proxy were 

perfectly specified , i.e., the certifier or searcher attempts to track the true semantic score J exactly, no total computable gate can be simultaneously sound and complete when candidates can self-referentially depend on the gate. In other words, the gap we identify is not statistical but structural : self-reference introduces a failure mode that cannot be closed by better proxy design alone, only by restricting the computational regime (bounded evaluation, finite proposals) as formalized in Theorem 3. 

# 10 Conclusion & Future Work 

We studied a minimal formal model of verification-gated self-improvement in which agents are programs, proposed updates are generated by a computable mechanism, and acceptance decisions are made by a terminating gate. The central finding is a sharp limitation in the unbounded, fully general setting: no terminating procedure can simultaneously guarantee that it never accepts a non-improvement and that it never rejects or misses a genuine improvement when proposals may be self-referential. This failure is structural rather than statistical. It follows from the interaction between unbounded program behavior and the ability of a proposal mechanism to adapt to the evaluator. It also survives randomization with bounded error and hiding the gate from the proposer (Section 5). At the same time, the negative results identify exactly which restrictions restore decidability. When evaluation is explicitly bounded and the proposal budget is finite, exhaustive checking recovers a terminating procedure with the desired guarantees relative to the bounded score being measured. The overall results motivate a simple design principle for autonomous improvement loops: make the limits explicit. Timeouts, finite candidate budgets, restricted update languages, sandboxing, and occasional external or human grounding are not optional conveniences. They are the conditions under which correctness guarantees become attainable. Section 7 takes a first step beyond the single update step and shows that accepted updates can raise the bounded score in every round while the true score falls. An important direction for future work is to characterize how fast this drift can grow when the proposer adapts to the evaluation schedule, and which additional constraints can control it while retaining useful progress. 12 References

# A Multi-Agents 

This appendix explains why the impossibility results extend to multi-agent pipelines. The main point is that (i) an interacting collection of agents can be encoded as a single composite program, and (ii) even if we keep the agents conceptually separate, self-reference can be realized through message passing whenever the proposer can condition on the gate’s behavior (directly or indirectly). 13 A.1 A minimal multi-agent model 

We model a multi-agent self-improvement pipeline as a finite tuple of programs together with a fixed interaction protocol. Let 

A = ( P, R, O, Π) denote a system consisting of a proposer P , a reviewer (or gate component) R, an orchestrator O (which routes messages, runs tests, and applies updates), and a protocol Π that specifies how these components interact over discrete time steps. On each round, the orchestrator provides inputs (task instances, tests, prompts, or environment states) to the components, collects their outputs, and produces an observable transcript. We consider updates that replace one component while holding the others fixed (the most common case in practice), e.g., replacing P with a candidate proposer P ′. Write A[P ← P ′] for the system where only the proposer is swapped. A gate is a terminating procedure that, given the current system and a candidate update, returns a binary accept/reject decision. In the simplest version: 

G(A, P ′) ∈ { 0, 1},

where G(A, P ′) = 1 means “accept replacing P with P ′.” 

A.2 Encoding a multi-agent system as a single program 

Because each component is a program and the protocol Π is fixed, the joint behavior of A can be implemented by a single program that simulates the interaction internally. Concretely, define a compiler (an effective transformation) that maps any tuple ( P, R, O, Π) to a single program index ⟨P, R, O, Π⟩ which: (i) simulates the protocol Π step-by-step, (ii) runs the component programs on the appropriate messages, and (iii) outputs the same external behavior (actions, transcript, or final decision) as the original multi-agent system. This is standard: multi-tape machines, communicating processes, and modular code can be compiled into a single Turing machine with only polynomial overhead. Therefore, any semantic score assigned to the multi-agent system (e.g., success probability, reward, correctness of a scientific claim) can be treated as a semantic score of the compiled single program. In particular, if we define a semantic score functional over composite systems, we can equivalently define a semantic score over their single-program encodings. 

A.3 Why the diagonal channel persists in multi-agent form 

The negative results rely on a structural ingredient: the candidate update can be chosen so that its behavior depends on the gate’s output. In a multi-agent pipeline, such dependence can be realized through interaction in several natural ways: • Direct query access. The proposer can explicitly query the reviewer (or a proxy of the gate) during generation (e.g., “would this be accepted?”). • Outcome feedback. Even without explicit queries, the proposer can adapt using accept/reject outcomes from previous rounds. • Transcript leakage. If reviewer comments or rubric scores are revealed, the proposer can learn a predictive model of acceptance and condition on it. Any of these channels allows the proposer to implement a “flip on accept” strategy: construct a candidate P ′

whose behavior under evaluation depends on whether G(A, P ′) would accept it. Intuitively, the proposer uses the gate as an oracle (directly or indirectly), creating a self-referential loop routed through other agents.

A.5 When the extension does not apply 

The diagonal channel requires that the candidate update can condition on the gate, either by querying it, observing outcomes, or learning from transcripts. If the system is designed so that candidates are generated independently of the gate (no feedback, no shared transcript, no ability to model the reviewer), then the self-referential construction is blocked. However, this restriction is strong and typically corresponds either to highly conservative pipelines or to bounded regimes where the gate’s guarantees are explicitly limited to a fixed evaluation horizon and finite proposal budget. 

# B Interactive Evaluation with a Computable Environment 

The Discussion claims that Theorem 3 extends to interactive evaluation under explicit assumptions. This appendix states those assumptions and proves the claim. 

Setting. Fix a finite action set A with a default action a0 ∈ A, a finite observation set O, a horizon H ∈ N,and a per-step compute cap Tstep ∈ N. A history of length t is a sequence h = ( a1, o 1, . . . , a t, o t) of actions and observations, encoded as a natural number. The environment is given by two total computable functions: a transition function μ that maps a history and a next action to a probability distribution over O with rational values, and a reward function r that maps a complete history of length H to a rational number. An agent is a program p. At each step it receives the encoded current history, and we simulate φp on it for at most Tstep steps. If the simulation halts with some a ∈ A, the agent plays a. Otherwise the agent plays the default action a0. The interactive bounded score Jint (p) is the expected value of r over the distribution on length-H histories induced by the agent and the environment. 

Proposition 3 (Computable interactive score) . Under the assumptions above, Jint : N → Q is total computable. Consequently, the exhaustive searcher of Theorem 3, run with Jint in place of JT , is total computable, sound, and weakly complete within budget with respect to Jint .Proof. Consider the tree of histories reachable in H steps. Its depth is H and its branching is at most |O| per step, so it has at most |O|H leaves. At each node, the agent’s action is determined by a simulation of at most 

Tstep steps with a default on timeout, so it always terminates and is computable from p. The probability of each edge is a rational value of μ, and the value of each leaf is a rational value of r. Therefore Jint (p) is a finite sum of products of rational numbers, each computable from p. Comparisons between rationals are decidable, so the exhaustive procedure of Theorem 3 goes through unchanged. 

Each assumption does real work. The finite horizon keeps the tree finite in depth. The finite action and observation sets keep the branching finite. The per-step cap makes the agent’s behavior at each node computable, since without it a single step could diverge. The rational values matter for the comparisons. If rewards or probabilities are arbitrary computable reals, the score can still be approximated to any precision, but deciding the strict inequality Jint (q) > J int (p) is no longer possible in general, because equality of computable reals is undecidable. In that case a one-sided design remains available, for example accepting only when an approximation certifies a gap of at least a known margin. 16
