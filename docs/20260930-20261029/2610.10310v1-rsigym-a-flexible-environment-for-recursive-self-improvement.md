## 摘要
递归自我改进需要将已接受的变更带入后续改进周期，而研究智能体提出的变更也需要大量研究基础设施。现有设置通常让智能体重建常规基础设施，或将探索限制在单个组件上。我们提出 RSIGym，一个基于一切即服务（Everything as a Service，EaaS）的智能体原生研究环境。RSIGym 通过可复用服务暴露训练、推理、推演（rollout）、评估和沙箱执行，并具有共享预算和权限控制，支持 Data、Harness 与 Joint 改进轨道。该设计使智能体能够在同一环境中研究单个干预，并联合优化数据、训练设置和执行框架。我们将 RSI-Index 定义为在涵盖软件工程、终端交互、数学、科学推理和基于技能的任务的五个基准上，剩余性能差距被缩小的平均比例。在独立的 Joint 运行中比较六个前沿研究模型时，Opus 5 在每次基准运行 500 美元平台服务预算下取得了最高的 RSI-Index，为 0.4809。其选定的系统提升了全部五个基准，将 SWE-bench Verified 从 17.67% 提高到 50.33%，并将 AIME 从 31.67% 提高到 97.78%。额外实验考察了 DSH-harness 改进、预算变化和受限网络访问，而记录的轨迹揭示了智能体如何诊断失败并选择候选方案。我们开源了完整的 RSIGym 代码库和结果，以支持可复现性和进一步研究。

## Abstract
Recursive self-improvement requires carrying accepted changes into later improvement cycles, while studying agent-proposed changes also requires substantial research infrastructure. Existing settings often leave agents to rebuild routine infrastructure or restrict exploration to individual components. We introduce RSIGym, an agent-native research environment based on Everything as a Service (EaaS). RSIGym exposes training, inference, rollout, evaluation, and sandbox execution through reusable services, with shared budget and permission controls supporting Data, Harness, and Joint improvement tracks. This design enables agents to investigate individual interventions and jointly optimize data, training settings, and execution harnesses within the same environment. We define RSI-Index as the mean fraction of the remaining performance gap closed across five benchmarks covering software engineering, terminal interaction, mathematics, scientific reasoning, and skill-based tasks. Comparing six frontier research models in independent Joint runs, Opus 5 achieves the highest RSI-Index of 0.4809 under a $500 platform-service budget per benchmark run. Its selected systems improve all five benchmarks, raising SWE-bench Verified from 17.67% to 50.33% and AIME from 31.67% to 97.78%. Additional experiments examine DSH-harness refinement, budget variation, and restricted network access, while recorded trajectories reveal how agents diagnose failures and select candidates. We open-source the full RSIGym codebase and results to support reproducibility and further research.

# RSIGym 论文结构化总结

## 1. 核心问题与研究动机

- **背景**：递归自我改进（Recursive Self-Improvement, RSI）要求把已被接受的改动带入后续改进周期；更强的“递归进步”还要求继承的改动改善后续改进的产生方式。自动科研系统（如 The AI Scientist）已能生成想法、跑实验、分析结果，但缺少承载“智能体自主改进目标系统”的统一研究环境。
- **现有环境的两个痛点**：
  - **重复造轮子**：如 PostTrainBench 只给智能体一块 H100 和网络，不给起始代码、训练数据、超参配置，智能体必须自建训练流水线，大量时间耗在常规工程上。
  - **探索被切碎**：MLGym、Agent²RL-Bench、AI4AI-Bench 主要开放权重/算法优化；AutoHarnessBench 固定权重只搜 harness；RSIBench-Data 固定训练栈只改数据。没有环境能同时研究单组件干预与其交互。
- **核心主张**：训练数据与超参决定“学到什么模型”，harness 决定“模型如何推理、用工具、行动”，二者共同演化需要可复用基础设施 + 可配置改进空间。RSIGym 用“一切即服务”（EaaS）把这一空间统一起来。

## 2. 方法论

### 2.1 核心思想：EaaS + 共享预算/权限

- 研究智能体 π 在**轻量 CPU-only 容器**中工作，只持有 harness 仓库、数据和笔记；训练、推理、评估、沙箱全部远程执行，智能体不装 GPU 驱动、不部署模型、不搭评测环境。
- 平台持有所有底层供应商凭证，智能体只拿一把**按 run 发放的平台 key**；所有服务调用前经统一授权服务校验权限与余额，完成后计费入账。
- 好处：算力只在服务执行时消耗（不因智能体思考而空转）；任务可跨机并行；所有智能体共享同一基础设施，差异归因于“研究决策”而非“环境配置能力”。

### 2.2 五个可复用服务

| 服务 | 智能体提交 | 返回 | 后端 |
|---|---|---|---|
| Training | 训练配置、数据集、可选自定义 loss | 逐步指标、checkpoint ID | Tinker（LoRA 微调） |
| Inference | 对基座/checkpoint 的 chat 请求 | 带 tool call 的补全 | Tinker |
| Rollout | 对前沿模型的 chat 请求 | 带 tool call 的补全 | LiteLLM |
| Evaluation | 任务配置、可选 harness 压缩包 | 分数、逐任务奖励、轨迹、日志 | Harbor（每 trial 独立云沙箱） |
| Sandbox | E2B SDK 请求 | 隔离沙箱、自定义镜像 | E2B |

### 2.3 接口设计五原则

1. **沿用既有协议**：OpenAI chat completion、Harbor 配置 schema、未修改的 E2B SDK，前沿模型已“天然会说”。
2. **异步执行**：训练/评估提交即返回 handle，可并行多实验、提前取消。
3. **可检查证据**：返回 loss 曲线、逐任务通过情况与 harness 行为，支持“诊断为什么”而非只看“分数变没变”。
4. **自文档**：每个服务附 skill document，会读文档即可用。
5. **记录执行**：服务侧独立留存提交数据、loss、轨迹、日志与计费明细，支持事后审计。

### 2.4 形式化定义

- 任务：给定初始系统 (M₀, h₀)、评估协议 E、允许改动集合 C、预算 B_total，智能体输出 (M\*, h\*) = π(M₀, h₀, E; C, B_total)；harness-only 时 M\* = M₀。
- 得分与增益：s(π) = Eval_E(M\*, h\*)，Δ(π) = s(π) − Eval_E(M₀, h₀)。
- **RSI-Index**：设基准 b 的 avg@3 分数为 s_b，初始为 s⁰_b，则
  `RSI-Index = (1/n) Σ_b (s_b − s⁰_b) / (1 − s⁰_b)`，即“剩余性能差距被闭合的平均比例”，0 = 初始系统，1 = 完美，负 = 退步，各基准等权。
- **审计**：checkpoint 来源核查、与评测任务的 13-gram 重叠检测、LLM judge 审阅轨迹与提交物。

### 2.5 权限如何定义轨道

- 服务级授予/撤销 + 服务内参数“开放/限定集合/固定”，即可在同一环境切换：**Data 轨**（只开训练数据，超参固定）、**Harness 轨**（撤销训练与 rollout，权重固定）、**Joint 轨**（数据+训练设置+harness 全开，只固定基座）、**离线设置**（撤销外网）。

  - GPQA Diamond：100 任务 / 300 trials
  - SkillsBench：37 任务 / 111 trials（仅 science/office/finance 子集）
- **六个研究智能体**：Claude Opus 5、Opus 5.5、GPT-6 Astra、GPT-6 Sol、GPT-6.1 Sol、DeepSeek V4.1 Flash（Claude/DeepSeek 跑在 Claude Code，GPT 系跑在 Codex）。

- **对照与设置**：
  - Joint 主实验：6 agents × 5 benchmarks = 30 个独立 run，每个 $500。
  - 单自由度消融：Opus 5 的 Data 轨 2 run、Harness 轨 2 run（目标换为 Qwen3.6-35B-A3B-Instruct）。
  - 预算对照：Opus 5 与 Astra 在 SWE/TB2 上以 $1,000 重跑，共 4 run。
