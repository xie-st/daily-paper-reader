## 摘要
多模态智能可以被视为人类引导下世界与智能体通过交互实现的协同演化。然而，扩展这一过程面临两个瓶颈：构建异构、可验证的环境成本高昂，且人工的 Harness 迭代难以跟上日益增长的任务多样性与复杂度。一个关键洞察是，具有不同模态和表面形式的任务可以共享相同的底层能力需求。因此，我们提出 The Trinity，一个通过 Creator、Explorer 和 Evolver 三种角色将世界生成与 Harness 演化耦合起来的递归自我改进框架。Evolver 基于经过验证的执行轨迹，将任务组织的基础从表面类别转变为共享需求，把原始任务树重组为分层的能力树。我们引入 Capability-Driven Real2Sim2Real：对于同一节点上的异构任务，Creator 将其共同需求抽象为简化、可验证的模拟世界以进行能力学习，同时在原始任务上的评估用于衡量迁移。沿着这棵能力树，Explorer 通过选择性继承逐步演化出可复用的能力模块，形成 Harness 树，其经过验证的更新在固定拓扑内跨迭代累积。由此得到的 Harness 专注于不同能力，这促使我们提出 Capability-Aware Harness Router，它利用公开任务信息从树中选择兼容的模块配置。我们演化得到的 Harness 在 28 个训练基准上平均性能提升 34 分，在 18 个未见基准上提升 26 分，其中包括两个真实世界具身任务。

## Abstract
Multimodal intelligence can be viewed as human-guided co-evolution between worlds and agents through interaction. However, scaling this process faces two bottlenecks: constructing heterogeneous, verifiable environments is costly, and manual Harness iteration cannot keep pace with growing task diversity and complexity. A key insight is that tasks with different modalities and surface forms can share the same underlying capability requirements. We therefore introduce The Trinity, a recursive self-improvement framework coupling world generation with Harness evolution through three roles: Creator, Explorer, and Evolver. Drawing on verified execution trajectories, Evolver shifts the basis of task organization from surface categories to shared requirements, reorganizing the original task tree into a hierarchical capability tree. We introduce Capability-Driven Real2Sim2Real: for heterogeneous tasks at the same node, Creator abstracts their common requirements into simplified, verifiable simulated worlds for capability learning, while evaluation on original tasks measures transfer. Along this capability tree, Explorer progressively evolves reusable capability modules through selective inheritance, forming a Harness tree whose validated updates accumulate across iterations within a fixed topology. The resulting Harnesses specialize in different capabilities, motivating a Capability-Aware Harness Router that uses public task information to select compatible module configurations from the tree. Our evolved Harnesses improve mean performance by 34 points across 28 training benchmarks and 26 points across 18 unseen benchmarks, including two real-world embodied tasks.

## 2. 方法论

### 2.1 总体框架：三角色闭环

- **Evolver**：基于已验证轨迹归纳能力需求、构建能力树、设计训练关卡、审计模块更新。
- **Explorer**：在能力树上采集轨迹、选择性继承并局部精化模块，形成 **Harness 树**（供路由）。
- **Creator**：按节点构建简化可验证模拟世界，并演化自身 Base Harness（世界生成侧）。
- 三者共享同一能力树拓扑，通过 host 验证的执行反馈闭环耦合；**骨干模型权重冻结**（Claude Opus 5）。

### 2.2 三阶段树构建

- **Stage 1 任务树**：将 44 个公开多模态基准规范化为统一接口（目标、观测、动作、反馈、完成判据、预算），划入 5 个需求域、15 个子类；训练/未见划分在能力归纳**之前固定**。
- **Stage 2 能力树**：
  - 独立 agent 从训练规格与轨迹中提出能力类别，经 judge 合并、reviewer 独立校验，得到 **6 种能力 + 30 种缺陷类型**（PST、HCI、CFR、GVT、VEA、VC）。
  - 每个训练任务获得固定需求集 $K_\tau$，按预定义确定性顺序 $\prec$（c, d, a, b, e, f）排序成路径，用 **Trie 合并公共前缀**：
    $$p_\tau = \mathrm{sort}_\prec(K_\tau),\quad \mathcal{T} = \mathrm{Trie}(\{p_\tau : \tau \in B_{tr}\})$$
  - 共 11 个非根节点；边表示“追加能力”，**不蕴含因果依赖**；未见任务在树固定后才归类，仅用于事后路由评估。
- **Stage 3 Harness 树**：
  - Harness 形式化为 $H_\phi = (\Pi_{er}, M, I, P, F, L)$，六个协议分别负责感知、记忆、推理、规划、编排、循环。
  - 模块为**纯函数**、版本化、位于 prompt 接口之后；仅 Memory 可声明显式携带状态；每步最多 2 次模块调用且不强制调用。

### 2.3 Capability-Driven Real2Sim2Real

- 对同一节点上的异构任务，Creator 抽象其**共同需求**为简化、可验证的模拟世界（3D 场景 + 公开规则 + 固定动作预算 + 评分器），**排除目标任务的布局、私有证明与解法轨迹**，但保留核心决策过程。
- 由 host 执行的 verifier 池检查节点绑定、执行、状态转移、渲染与完成；Explorer 用冻结的 screening Harness 筛选，仅接纳处于**预定中间性能带**的世界，否则沿预设难度维度调整。
- 原始任务上的评估用于衡量**能力迁移**。

### 2.4 递归自我改进（RSI）

- **选择性继承**（右偏并集）：$H^{(i)}_{E,v} = P^{(i)}_v \oplus L^{(i)}_v$，本地模块覆盖同 ID 的继承模块；父模块仅在**严格更高**的 host 验证完成数下才被继承，否则保留旧版。
- **持续精化**：
  $$Z^{(i+1)}_v = \mathrm{Rollout}(P^{(i+1)}_v \oplus L^{(i)}_v,\ \mathcal{D}^{(i+1)}_v),\quad \tilde{L}^{(i+1)}_v = \mathrm{Evolve}(L^{(i)}_v, Z^{(i+1)}_v, F^{(i)}_v)$$
  接受更新需通过证据、归属、接口、版本谱系与可执行契约检查；局部接纳不要求分数上升。
- **Creator 库合并**：迭代末按学习顺序合并去重：
  $$R^{(i+1)}_C = \mathrm{Consolidate}_{\prec_C}\Big(R^{(i)}_C \cup \bigcup_{v \in V^+} \Delta R^{(i+1)}_{C,v}\Big)$$
  保留互补、合并部分重叠、近重复保留先学模块，形成下一轮 Base Harness。

### 2.5 能力感知 Harness 路由

- 路由建模为 context–action–feedback 循环：
  $$h_n = \pi(x_n, \mathcal{C}, R(x_n, M_n), S(M_n)),\quad M_{n+1} = \mathrm{Append}(M_n, (x_n, h_n, f_n))$$
- 使用公开任务信息 + 检索执行经验（余弦相似度 ≥ 0.5、最多 10 条、20,000 条 FIFO 记忆）+ 性能—成本摘要；提交前需给出**基于证据的理由**；未见任务的能力标签在预测账本哈希锁定后才可访问。

## 4. 资源与算力

- **论文未报告 GPU 型号、数量或训练时长**。由于骨干模型完全冻结，不存在模型参数训练，只涉及推理与 agent 演化调用。
- 文中仅以 **token 总量（百万级，M）** 报告成本：如首轮训练 405.70M（Sim）/ 211.56M（Real）/ 278.25M（Task-Domain）；推理成本约 500–600M/次评测；模块干预实验给出 496.70M–583.37M 的对比。
- 明确指出 Creator 的世界构建主导首轮训练开销，后续迭代通过复用世界摊销该成本。**算力细节（硬件、墙钟时间、并行度）缺失，是该文可复现性的一项信息缺口。**

## 5. 实验数量与充分性

- **规模**：5 组主实验 + 多组消融，覆盖 44 个基准、5 个 RSI 迭代、5 种组织方式、5 种路由配置、模块增删干预、2 个具身任务的仿真与真机，附录另附逐节点课程（44 个关卡）与 44 张交互可视化记录。**广度在同类 Harness RSI 工作中属较高水平。**
- **公平性设计较好的地方**：
  - 训练/未见划分在能力归纳前固定；未见任务能力标签仅在预测账本哈希锁定后访问；实例选择器与初始状态哈希预先固定；失败重试规则明确；技术失败计 0 分、无效选择无回退。
  - 路由对比中技能准备记录不进入路由记忆，避免泄漏。
- **需注意的偏保守/偏乐观因素**：
  - 主结果（表 3、图 5、表 8）采用 **Oracle 设定**（每实例选最佳兼容节点 Harness），属于**上界式评估**，与真实部署（需自行路由）之间存在差距；表 4 的路由结果（71.27/60.96）确实低于 Oracle（73.16/63.61）。
  - 具身实验每个条件仅 **10 个 episode**，统计效力有限；作者也承认该对比评估的是“Harness–技能整体配置”，**未隔离模块演化与技能准备的各自贡献**。
  - 模块相关性（图 7）为**描述性统计**，作者明确说明其仅用于引出干预实验，不构成因果结论。
  - 外部对照仅 Codex / DeepSeek 两家

，且仅在 16 个非机器人未见基准上比较，未覆盖具身与训练侧基准。

- **总体判断**：实验设计在“组织方式—路由—模块归因—迁移”四个层面形成了较完整的证据链，且预先固定划分与哈希锁定等做法显著降低了选择性偏差；但**Oracle 上界口径、具身小样本、外部对照覆盖面有限**三点，使得结论更适合表述为“能力驱动的组织与 Harness 演化在该设置下有效”，而非“已被普遍验证”。

## 6. 主要发现与结论

- **能力驱动的组织优于任务驱动**：按能力域/能力树组织 Harness 与课程，在训练与未见基准上均优于 Base、Global 与 Task-Domain 组织；单一全局 Harness 在需求冲突时表现最差，印证了“多专用 Harness + 路由”的必要性。
- **共享能力需求可跨模态迁移**：在简化模拟世界（Sim）中演化的 Harness 能迁移回原始异构任务（Real），说明能力抽象确实捕捉到了跨表面形式的共性，而非任务特定的捷径。
- **RSI 带来持续增益且可摊销成本**：Base→Iter.1–4 的均值曲线单调上升并趋于饱和；首轮开销主要由 Creator 的世界构建主导，后续迭代通过复用世界显著摊销，体现 Real2Sim2Real 循环的经济性。
- **路由是可行的但仍有差距**：Agent Self-Routing 随先验信息增加（能力定义、经验检索）逐步逼近 Oracle，但仍存在明显 gap；证据化理由与经验检索是缩小差距的关键机制。
- **模块—能力存在可干预的对应关系**：相关性矩阵显示模块与六类协议/能力存在结构化对应，受控增删实验进一步表明相关模块的加入/移除会引起方向一致的性能变化，而无关模块影响有限——为“模块级归因”提供了比纯相关性更强的证据。
- **具身任务上的有效性**：SOON 与 CaP-X 在仿真与真机上，演化后的 Harness 配置成功率高于对照配置，说明方法可延伸至具身场景，但受样本量限制。

## 7. 局限与作者承认的问题

- **评估口径偏上界**：主结果使用 Oracle 节点选择，真实部署需自行路由，实际性能低于报告值。
- **具身实验样本小**（每条件 10 episode），且对比的是“Harness–技能整体配置”，未分离模块演化与技能准备的贡献。
- **模块相关性为描述性**，不作为因果结论。
- **算力信息缺失**：仅报告 token 消耗，无硬件、墙钟时间与并行度，影响可复现性与成本外推。
- **外部对照有限**：仅 Codex CLI 与 DeepSeek Harness，且限于非机器人未见基准。
- **能力树边语义**：边表示“追加能力”而非因果依赖，能力归纳仍依赖 LLM judge/reviewer，存在归纳偏差风险。
- **骨干单一**：全部实验基于冻结的 Claude Opus 5，未验证对其他骨干的泛化。

## 8. 启发与可复用要点

- **“能力”作为跨任务的组织单元**，比“任务/领域”更适合异构多模态场景，可作为 Harness 库与课程设计的中间抽象层。
- **三角色闭环（Evolver / Explorer / Creator）+ 共享能力树拓扑**是一个可复用的 RSI 架构模板，尤其适合“环境昂贵、需自动生成可验证世界”的设定。
- **选择性继承 + 版本化纯函数模块 + 严格证据检查**，为“冻结骨干下的 Harness 演化”提供了较稳健的工程契约，可作为防止演化漂移的设计参考。
- **评估卫生实践**值得借鉴：划分先于能力归纳固定、能力标签哈希锁定、技能准备记录不入路由记忆、失败计 0 且无回退。
- **成本摊销思路**：把昂贵的世界构建放在首轮并由后续迭代复用，是降低 RSI 边际成本的关键杠杆。

## 9. 一句话评价

该文将多模态自我改进从“任务驱动”重构为“**能力驱动的多 Harness 协同演化 + 路由**”，以三角色闭环和 Real2Sim2Real 循环给出了一套较完整的工程与评估方案；其证据链在组织方式、迁移与模块归因上较扎实，但 Oracle 上界口径、具身小样本与算力信息缺失，使其结论宜定位为“强有力但非普适验证”的实证主张。
