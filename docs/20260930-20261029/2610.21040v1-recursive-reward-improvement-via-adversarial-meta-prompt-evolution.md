## 摘要
递归自我改进（RSI）因其在有限数据下仍能有效工作的能力而受到广泛关注。在提议者-求解者循环中，提议者模型编写训练任务，求解者模型通过强化学习学习解决这些任务。此类循环已在数学和编程领域取得成功，因为这些领域的每个答案都可以自动检查。开放式专家任务（如临床报告生成）没有标准答案，这使得简单的问答生成不可行。在此类任务中，提议者还必须编写评分标准（rubric），列出答案应包含的内容以及应避免的错误。然而，模型编写评分标准所面临的独特挑战在于其全面性。对于朴素生成的评分标准，求解者往往会利用它，只点出预期主题却缺乏实质内容，从而破坏学习过程。为解决该问题，我们提出 RRI（Recursive Reward Improvement，递归奖励改进），利用一个奖励黑客对抗者来监督奖励。在求解者基于生成任务训练之前，一个对抗者会编写一个答案，该答案钻评分标准的空子，同时尽可能无用；同一模型在未看到评分标准的情况下编写诚实答案；最多进行两步修复来修订评分标准，使诚实答案胜出。发现的漏洞利用方式还会重塑未来任务和评分标准的生成方式。在 HealthBench Professional 上，RRI 相比仅生成（Generation Only）的自我改进基线，在 9B 模型上调整后分数提升 10.9 分，在 27B 上提升 12.4 分；在没有任何外部模型的情况下提升 10.3 分。特别是，在困难任务和写作任务上的提升最大。我们表明，基于 HealthBench Professional 描述训练的 27B 模型，在未见过 PRBench Hard 和 ProfBench 中任何任务的情况下，分别提升 6.6 分和 8.0 分。我们进一步分析了模型生成的问题-评分标准对中的可利用点，以促进未来关于开放式自我博弈的研究。

## Abstract
Recursive Self-Improvement (RSI) has gained wide attention for its ability to work with limited data. In a proposer-solver loop, a proposer model writes training tasks and a solver model learns to solve them through reinforcement learning. Such loops have succeeded in mathematics and coding, where every answer can be checked automatically. Open-ended expert tasks, like clinical report generations, have no answer key, which makes simple question-answer generation not viable. Here the proposer must also write a rubric that lists the content an answer should include and the errors it should avoid. However, the unique challenge behind model-written rubric is the comprehensiveness of it. For naively generated rubric, solvers tend to exploit it, naming the expected topics without the substance behind them, which corrupts the learning process. To solve this problem, we introduce RRI, Recursive Reward Improvement, which uses a reward hacking adversary to supervise the reward. Before the solver trains on a generated task, an adversary writes an answer that games its rubric while being as useless as possible, the same model writes an honest answer without seeing the rubric, and up to two repair steps revise the rubric to make the honest answer win. The exploits found also rewrite how future tasks and rubrics are generated. On HealthBench Professional, RRI improves the adjusted score over the Generation Only self-improvement baseline by 10.9 points at 9B and 12.4 at 27B, and by 10.3 points without any external model. In particular, the gains are largest on difficult and writing tasks. We show that the 27B model trained on the HealthBench Professional description improves by 6.6 points on PRBench Hard and 8.0 on ProfBench without seeing a task from either. We further analyze the exploitable points of model-generated question-rubric pairs to facilitate future research on open-ended self-play.

## 1. 核心问题与研究动机

- **背景**：递归自我改进（RSI）中的“提议者–求解者”（proposer–solver）循环已在数学、编程等**答案可自动核验**的领域取得成功；但医学、法律、金融等**开放式专家任务**（如临床报告、患者咨询）没有标准答案，无法用执行结果或答案键判分。
- **核心矛盾**：开放式任务要求提议者在生成任务的同时**自写评分标准（rubric）**，作为强化学习的奖励。但模型自写的 rubric 往往**不全面、措辞含糊**，求解者会“钻空子”：只点出预期主题、复述任务、堆砌模板化表述，却不提供实质内容，从而污染整个自改进过程。
- **量化证据**：作者称模型生成的问题–rubric 对中**近 99% 可被 hack**；训练中收集的 12,147 个 exploit 案例显示，奖励失败主要集中在“遗漏负向错误”和“rubric 歧义”。
- **研究问题**：在**没有任何人类参考数据**（无参考答案、偏好标签、金标准 rubric）的条件下，如何监督并改进模型自写的奖励？现有去偏方法假设偏差跨任务一致，无法应对“每个问题 rubric 都不同”的情形。

## 2. 方法论：RRI

### 2.1 核心思想
让自改进循环**先攻击自己的奖励，再修复它**：在 solver 训练前，用一个“奖励黑客对抗者”写出能骗过 rubric 但毫无用处的答案，再让同一模型在不看 rubric 的情况下写诚实答案；通过“hack → patch → 再攻击”使诚实答案胜出。同时，发现的漏洞会经**元提示演化**反馈到未来任务与 rubric 的生成中，形成“任务–奖励–求解者”共同进化。

### 2.2 五个组件
- **Proposer（提议者）**：仅接收目标任务的总体描述，无训练数据。先生成临床请求（兼作检索查询），从医学文献库检索段落，再基于文献一次性写出任务与加权 rubric。每条准则带符号权重 \(p_j \in [-10,10]\setminus\{0\}\)，正准则奖励应含内容，负准则惩罚错误。
- **Adversary（对抗者）**：
  - **Hack 阶段**：对抗者看到 rubric，写出“尽可能满足准则但尽可能无用”的答案；同一冻结模型仅看任务、不看 rubric，写诚实答案。Judge 分别打分，计算 exploit 领先量
    \[
    \Delta = s(y_{\text{exploit}}) - s(y_{\text{honest}})
    \]
    若诚实答案不能领先至少 \(\delta=0.20\)，任务判为可 hack，进入 patch。
  - **Patch 阶段**：修复步骤提出新的正/负准则；仅当新准则满足
    - 负准则：在 exploit 上 met、在 honest 上 not met；
    - 正准则：在 honest 上 met、在 exploit 上 not met  
    才被保留（公式 (1)）。即准则必须**区分好坏答案**，而非仅增加内容要求。
  - **Admission（准入）**：重写只有在**新一轮探测**显示 \(\Delta\) 更小时才采纳；最多两轮。即使对抗者仍能击败修复后的 rubric，任务也进入训练池（保留多样性），因为其质量已优于原始版本。
- **Judge（评判者）**：按 benchmark 官方逐准则模板打分，三票多数；探测与 patch 验证时附加“严格判分说明”，只承认答案**明确陈述**的内容，禁止“提及主题、复述请求、对冲、转介指南”得分。
- **Solver（求解者）**：用 GRPO 训练，每个任务采样 \(n=8\) 个回答，优势估计为组内平均成对分差
  \[
  \hat A_i = s(y_i) - \frac{1}{n}\sum_k s(y_k)
  \]
  支持最多两次工具调用（临床知识库/网页搜索），工具片段掩码、查询 token 参与训练。
- **Meta-optimizer（元优化器）**：
  - 每轮抽样分析训练案例，用封闭词表标注失败模式、rubric 缺陷、任务缺陷，并给出三种判定：`model failed a fair task`、`generator at fault`、`model succeeded`。
  - 聚合语料统计（每任务准则数、负准则占比、用例分布、任务自相似度）并与 benchmark 参考对比，检测分布漂移。
  - 重写两个生成 prompt 的 guidance 块；另有 **memo optimizer** 维护不超过 2,400 字符的“已知漏洞备忘录”，目标函数为
    \[
    g = \Delta_{\text{adv}} + \kappa \max(0,\ \bar s_{\text{honest}} - \bar s_{\text{honest}}^{[0]} - \tau)
    \]
    其中 \(\kappa=2.0,\ \tau=0.02\)，防止通过“放宽 rubric 提高诚实分”来刷目标；变差超过容差的版本回滚。
- **自包含设置**：冻结的 solver 基座模型可同时充当 proposer、adversary、repair、judge、meta-optimizer，实现完全无外部强模型的自我改进。

## 3. 实验设计

### 3.1 数据集与 Benchmark
- **主目标域**：**HealthBench Professional**（525 个医生撰写任务，含 consult 236、research 147、writing 142；typical 256、difficult 269；28 个专科）。训练时 proposer **只看到该 benchmark 的文字描述**，所有训练任务与 rubric 均为模型生成，benchmark 仅用于验证。
- **域外泛化**：
  - **PRBench Hard**：550 个金融/法律专家任务；
  - **ProfBench**：40 个化学、物理、金融、咨询的 PhD/MBA 级报告任务；
  - **HealthBench Hard**：1,000 个最难任务（训练/验证均未使用）；
  - **MedXpertQA**：4,450 道多选题，编码为单准则 rubric。
- **指标**：官方长度调整 rubric 分数
  \[
  s(y)=r(y)-\lambda(\ell(y)-\ell_0)/500,\quad \ell_0=2000,\ \lambda=0.0147
  \]
  其中 \(r(y)\) 为满足准则的正权重占全部正权重之比；同时报告 raw score（截断到 [0,1]）。PRBench/ProfBench 用官方加权分数，无长度项。

### 3.2 训练设置
四个设置，每个均含 untrained / Generation Only / RRI：
1. **9B + GPT judge + 检索 + 网页搜索**（主设置，Qwen3.5-9B）；
2. **27B + GPT judge + 检索 + 网页搜索**（Qwen3.6-27B）；
3. **All-self**：冻结的 9B 担任所有辅助角色（含训练与验证 judge）；
4. **No-retrieval**：关闭检索，冻结 9B judge。

### 3.3 对比方法
- **Generation Only**：proposer prompt 不调优的自我改进基线（任务与 rubric 仍由模型生成）。
- **Co-evolve Only**：任务、奖励、solver 共同进化，但**无对抗者**。
- **Evolution only**：仅元提示演化，无 adversary。
- **三种 rubric 奖励方法**：RaR（用合成任务替代其所需的标注数据）、EvoRubrics、SibylSense，均按官方实现。
- **推理时方法**：Medical RAG、RAG-Fusion、i-MedRAG（冻结基座模型 + 检索）。
- **参考模型**：GPT-5.3-chat、GPT-5.5-Chat、GPT-5.4、Gemma 4 31B IT、Lingshu-32B（统一无工具、贪心解码协议）。

### 3.4 评估公平性措施
- 所有对比行共享同一 base model、GRPO 配方、超参数、solver 工具、judge、生成任务数量与 proposer 架构；仅 proposer prompt 是否冻结不同。
- 每个训练模型只报告**最后一个 checkpoint**，不做 checkpoint 选择。
- 用 benchmark 官方 judge（GPT-5.4）对同一批答案**重新评分**，验证排序与 margin 稳健。
- 提供 28 个专科的细分结果。
