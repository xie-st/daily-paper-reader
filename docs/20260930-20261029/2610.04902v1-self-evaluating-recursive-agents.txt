ABSTRACT 

Recursive language-model agents decompose tasks and delegate subtasks to child instances of the same policy, forming a tree of work. Training them, however, is hard: the final outcome is verifiable, but the self-invented intermediate subtasks are numerous and carry no ground truth. Existing methods score each node with a verifier or judge, which is costly at scale and blind to decomposition quality. We argue that a recursive agent must learn three coupled capabilities within one set of weights: decomposing problems into subtasks, solving them, and evaluating the outcomes, each requiring its own training signal. SERA (Self-Evaluating Recursive Agents) turns evaluation into a learned capability of the policy itself. Before delegating, the parent writes a rubric of weighted success criteria for each child subtask; a ranking objective against verified outcomes then trains rubric generation so that the criteria track genuine subtask success. In addition, a complementary leaf-coverage signal provides direct credit for task decomposition. Our central finding is that training the policy to generate aligned rubrics is what drives the gains: because the same weights both evaluate and execute, learning to judge subtasks sharpens the agent’s ability to solve them. Notably, external supervision is also reduced: the judge is consulted only to train the rubric generator, while solving is trained against the agent’s own rubric scores, which outperform direct use of the judge. Beyond training, the learned rubric doubles as an inference-time selector for tree search. On TextCraft-Synth and TextWorld-Sync, SERA improves over strong recursive-agent baselines by 5.38 and 13 .14 points on average, and rubric-guided tree search at inference adds a further 2.43 points on TextWorld-Sync. 

1 INTRODUCTION 

Language-model agents are deployed on tasks that cannot be solved in a pass: multi-hop research questions require coordinating evidence across retrieval steps; repository-scale code changes involve interdependent edits. A natural response is to decompose the problem and delegate each piece to a child agent (Prasad et al., 2024; Schroeder et al., 2025; Chi et al., 2025), turning one query into a tree of work where each child handles a focused subproblem in a fresh context. When the children are instances of the same policy, the system is recursive (Zhang et al., 2025; Gandhi et al., 2026): a single set of weights drives every node. This is the design behind frontier coding and research agents (Anthropic, 2025; OpenAI, 2025; Tie et al., 2026), and it composes across depth: a policy trained at shallow recursion generalises to deeper trees at inference (Gandhi et al., 2026), making recursion a distinct axis of test-time scaling alongside longer chains of thought and wider sampling. Training recursive agents is hard because supervision is scarce and unevenly distributed across the tree. The final outcome is typically verifiable (a research answer can be checked, code can be tested), but the intermediate subtasks the agent invents rarely admit a ground-truth check. The natural remedy is to score each node by its own success instead of broadcasting the root reward, using a verifier or an LLM judge (e.g., Gandhi et al., 2026). This localises credit, but the resulting signal has three limitations. It is coarse : a binary per-node signal cannot separate a clean solution from a barely adequate one, or flag weak work inside a tree that still succeeds. It is expensive : a reliable signal at

And it is silent about decomposition : rewarding whether subtasks were solved says nothing about whether they were the right subtasks to create, though that choice often decides whether the tree succeeds. The root issue is structural: a recursive agent is not doing one thing but three. The same shared weights must decompose hard problems into tractable pieces, solve the subtasks that result, and 

evaluate whether delegated work was actually accomplished. Every child is a fresh instance of the parent, so all three functions live in a single policy. Training the agent well means giving each capability its own signal without the three interfering on shared parameters. A self-invented subtask has no ground-truth check, so the agent must judge for itself whether it succeeded. We make this self-evaluation concrete with a rubric : when the parent delegates a subtask, it commits a short set of weighted natural-language success criteria for the child before the child runs, so they cannot be fitted to the trajectory they will later score. Applying the rubric to the child’s output yields a continuous, subtask-specific score in place of the coarse per-node signal. However, a rubric helps only when its criteria align with subtask success. An untrained policy writes misaligned criteria, and using its scores as rewards helps little, inconsistently across tasks (§4). We therefore train rubric generation, but the signal for that training cannot be the task reward itself: since rubric generation and solving share weights, rewarding the rubric through task reward would let the two co-adapt, inflating rubric scores together without improvement. Instead, the signal comes from an external check: we score subtask rollouts with a verifier or judge and train the rubric to rank verified successes above failures. Importantly, the judge is used only here, never to reward nodes directly as common approaches do; the rubric provides the dense per-node signal itself, so external supervision is lighter overall. Grounded this way, shared weights become an asset: learning to judge subtasks reshapes how the policy solves them, which is our central empirical finding (§4). A capability, subtask decomposition , is the choice of how to split a task into subproblems to delegate. We assign it a reward. In a solved tree, a delegation is credited by the fraction of the task’s leaf-level work its subtree covers, so a delegation that shoulders a large, well-scoped share of the solution scores high, while trivial hand-offs score near zero and delegations in failed trees score zero. This rewards the agent for using delegation to carry structural load, something no execution signal captures. The reward adds little on shallow, near-independent subtasks but helps when subtasks are interdependent, as in tasks with dependency chains, shared state, or coordination (§4). Finally, since the learned rubric captures genuine subtask quality, it is useful beyond training. At inference we search the tree depth-first and select among candidate resolutions by rubric score, propagating the best upward. This further improves final task success without additional training (§4.3). The evaluation capability thus pays off as a reusable inference-time selector, a further scaling axis for recursive agents. We call the method SERA (Self-Evaluating Recursive Agents). Our contributions are as follows: 1. A framing of recursive-agent training as learning three coupled capabilities (decomposing, solving, and evaluating subtasks) in a single shared policy, with evidence that each requires its own training signal (§3). 2. A learned self-evaluation mechanism: policy-generated rubrics trained by a ranking objective against verified outcomes. We show that training rubric generation is what improves execution, that it reduces external supervision while outperforming direct use of the judge (§3). 3. A leaf-coverage decomposition reward that credits a delegation by how much of the verified task it covers, with gains concentrated when subtasks are interdependent (§3). 4. State-of-the-art results on TextCraft-Synth and TextWorld-Sync (§4), and the learned rubric as an inference-time selector for tree search, with further gains (§4.3).

Dense rewards and process supervision for agents. A large body of work densifies sparse outcome rewards with step- or process-level supervision, from process reward models (Lightman et al., 2024) to agentic variants that assign credit to intermediate actions (Zhang et al., 2026; Li et al., 2026b); these operate on flat, linear trajectories with the intermediate signal supplied by a separate critic or an additive decomposition of the return. Classical hierarchical RL such as options (Dietterich, 2000) and goal-conditioned hierarchies (Nachum et al., 2018) assigns credit across levels but assumes a fixed set of subtask types or hierarchy depth. In contrast, SERA operates on a dynamically generated tree where the hierarchy, the subtasks, and the evaluator are all produced by a single policy and vary from rollout to rollout. 

Rubric-based reinforcement learning. A separate question from where credit is assigned is what form the per-node signal takes. Rubrics extend RL beyond exactly verifiable domains by scoring outputs against generated criteria (Liu et al., 2026). Because static rubrics saturate as the policy improves, recent work co-trains the rubric generator with the policy through per-step return decom-position (Tian et al., 2026), alternating generator–judge optimization (Xu et al., 2026), or adversarial co-evolution (Ding et al., 2026), with RubricEM the closest in domain family (Li et al., 2026a). All assume flat or fixed-stage computation with a rubric model separate from the policy. SERA instead applies learned rubric generation to recursive, policy-invented subtasks whose topology varies across rollouts, uses the policy itself as the evaluator, and trains rubrics with a ranking objective anchored to verified outcomes. We find that the label-free discriminativeness signal favored in prior rubric learning degrades performance in a tree, where score spread reflects subtask-difficulty variation more than rubric quality (§4.2); relatedly, work documenting reward hacking under learned reward signals (Gao et al., 2025; Wang et al., 2026; Yang et al., 2026) motivates our verified-outcome anchoring. 

3 METHOD 

3.1 PROBLEM SETUP 

SERA trains a single policy πθ to decompose a root task, execute the resulting subtasks, and evaluate their outcomes (Figure 1). Given a root task x, the policy either solves it directly or emits a 

delegation action that creates a child agent for a self-generated subtask. Recursively applying the same policy produces a tree T , where each node v ∈ T has a subtask Xv , trajectory τv , output ov , final 3environment state zv , child set C(v), and depth d(v). The root task is evaluated by the environment, yielding R ∈ [0 , 1] , whereas intermediate subtasks receive self-evaluated rewards during execution. For variance reduction, we sample K > 1 independent trees {Ti}Ki=1 for each root task. We assign a separate learning signal to each capability. The execution reward gives every node a continuous score from a policy-generated rubric, training the agent to solve subtasks well. The 

leaf-coverage reward credits each delegation decision by the share of the solved task it organizes, training the agent to decompose effectively. The rubric-generation reward trains the agent to write evaluation criteria that track verified outcomes, using a ranking objective over counterfactual rollouts. These three signals are optimized by alternating updates on the shared policy. To prevent evaluation from adapting to the outcome it scores, each rubric obeys an ex-ante commitment : once generated by the parent, it is frozen before the child’s trajectory and final state are observed. 3.2 SELF -EVALUATED EXECUTION REWARD

Execution credit evaluates what an agent does after a decision, but it does not directly evaluate whether the decision to delegate was structurally useful. We therefore assign a separate reward to each delegation event. We measure coverage by leaf nodes (nodes with no children), since leaves are the nodes that solve atomic subproblems and contribute directly to the final answer, while internal nodes serve as orchestrators. Leaf coverage thus captures how much of the final solution is produced through a given delegation, independent of tree depth. Since no additional signal is available to measure each leaf’s individual contribution, we weight all leaves equally; incorporating subtask-level importance weights is a natural extension. Rubric scores are useful only if the rubric criteria correlate with actual subtask success. The most readily available signal for training rubric generation is the root task reward, but because the rubric generator and the solver share πθ, optimizing rubrics through this reward would allow the two to co-adapt, inflating rubric scores without improving actual quality. We instead train rubric generation against verified subtask outcomes obtained from counterfactual rollouts. Specifically, we use a ranking loss that requires the rubric to score verified successes above verified failures on the same 4subtask. This isolates rubric quality from absolute task difficulty, since the rubric need only separate outcomes within a single subtask rather than calibrate scores across different ones. Concretely, during rubric-generation training we clone the environment state at each delegation point and sample a group of B rollouts of the same subtask. One rollout continues the original recursive execution, while the remaining B −1 rollouts serve solely as counterfactual training data for the rubric generator. Note that this cloning and counterfactual sampling is required only for rubric-generation training; the execution and decomposition phases operate on ordinary rollouts without additional sampling. Each rollout b receives a verified outcome yb ∈ [0 , 1] from the environment verifier or an external judge, and the frozen rubric assigns it a score sb. SERA jointly optimizes three objectives on shared parameters. Combining all three gradients in a single update risks instability, since the objectives can interfere and their scales differ. We instead alternate: each optimizer step activates exactly one objective, and the updates cycle in the fixed ratio 

nexec : nleaf : nrub . Execution updates receive the largest share because, in preliminary experiments, execution training is the primary driver of performance and covers the majority of tokens in a typical tree. The leaf-coverage and rubric-generation stages are lighter, each requiring only a small number of periodic updates to improve decomposition and refine the rubric that supplies the dense execution signal. Alternation keeps the credit sources well separated, and the ratio can be adjusted per domain without changing the method. The same learned rubric is then reused at inference time to rank candidate node resolutions during the bottom-up tree-search procedure described in Section 4.3. 

4 EXPERIMENTS 

Benchmarks. We evaluate on two benchmarks that differ in a property central to our method: whether intermediate subtasks can be verified independently. TextCraft-Synth (Gandhi et al., 2026) is a procedural crafting environment requiring hierarchical planning, tool use, and recursive delegation, in which the agent crafts a target item by looking up recipes and delegating sub-crafts to child agents. Crucially, each subtask has a deterministic program verifier returning a binary pass/fail outcome, so SERA’s rubric training requires no external judge here. Tasks span four difficulty levels defined by recipe depth; we train on Medium and evaluate across all levels to test generalization. 

TextWorld-Sync is our multi-agent extension of TextWorldExpress (Jansen & Cˆ ot´ e, 2023), a shared-state text environment for evaluating coordination under constraints, with seven task families spanning dependency chains, resource conflicts, load balancing, and hierarchical decomposition. Unlike TextCraft, subtask outcomes are not independently verifiable; rubric training instead uses an LLM judge that provides binary success/failure labels for counterfactual rollouts, making this the benchmark that tests SERA’s ability to amortize a sparse external signal. On both benchmarks the verified outcome yb is binary, so the ranking loss and leaf-coverage reward from Section 3 apply without modification. Detailed dataset statistics and task-family descriptions are in Appendix C. 

Baselines. We compare against three types of baselines: prompting, single-agent RL, and recursive multi-agent RL. (1) Prompting : Qwen3-4B-Instruct in single-agent and multi-agent (recursive delegation enabled) modes. (2) Single-agent RL : GRPO (Shao et al., 2024) and CISPO (Chen et al., 2025), both trained without delegation. (3) Recursive multi-agent RL : RAO (Gandhi et al., 2026), which jointly trains root and subagent trajectories with per-node binary rewards. To isolate each component’s contribution, we also evaluate ablations that add one capability to RAO ( RAO + Decomposition , RAO + Rubric Training ) or remove one or more from the full method (SERA w/o Decomposition and SERA w/o Decomposition & Rubric Training ); the exact reward composition of each is given in Appendix Table 6. All reported success rates are determined by deterministic environment verification of the root task. 

Training details. All methods use Qwen3-4B-Instruct-2507 (Yang et al., 2025) as the base model, fully fine-tuned with Adam. All compared recursive methods share the advantage-estimation and policy-optimization pipeline described in Section 3.5, differing only in their reward and credit assign-ments; SERA’s alternating schedule uses the ratio nexec : nleaf : nrub = 16 : 2 : 2 . Each agent exe-cutes at most 20 environment steps at recursion depth up to 3. We report TextCraft-Synth at 250 opti-mizer updates and TextWorld-Sync at 400; remaining hyperparameters are listed in Appendix Table 5. 4.1 EXPERIMENTAL RESULTS

Recursive delegation must be explicitly trained. The prompted Multi-Agent baseline improves over its Single-Agent counterpart by only 3.27 points on TextCraft-Synth and 3.79 points on TextWorld-Sync. In contrast, RAO substantially outperforms Single-Agent GRPO by 39 .97 and 12 .64 points, and Single-Agent CISPO by 35 .86 and 13 .07 points, on the two benchmarks respectively. Merely exposing the model to a delegation interface is insufficient; the policy must be explicitly optimized to decide when to delegate, what to assign, and how to integrate the result. 

Rubric rewards without rubric training do not reliably improve execution. SERA w/o D & RT replaces binary per-node rewards with continuous rubric scores from an untrained generator. De-spite the denser signal, it improves average success by only 3.33 points on TextCraft-Synth and underperforms RAO by 0.83 points on TextWorld-Sync. 

Training rubric generation drives the largest gains. Compared with SERA w/o D & RT, which uses rubric-based execution rewards but no rubric training, SERA w/o D additionally trains rubric generation. This single change improves average success by 2.58 points on TextCraft-Synth and 

9.16 points on TextWorld-Sync. The gains are particularly pronounced on difficult tasks: Hard and Extreme success on TextCraft-Synth improve by 6.62 and 7.60 points respectively. 

Rubric training requires rubric-based execution rewards. Conversely, RAO + RT adds rubric-generation training to RAO but keeps binary execution rewards. 5 CONCLUSION 

We presented SERA, a method for training recursive language-model agents that casts training as three coupled capabilities: decomposing tasks into subtasks, solving them, and evaluating their outcomes. Each capability receives its own training signal, and the three are optimized by alternating updates on a single shared policy. The central finding is that training the policy to generate its own evaluation rubrics, through a ranking objective anchored to verified outcomes, is what drives the largest performance gains. Since evaluation and execution share weights, learning to judge subtask quality directly improves how the agent solves them. This trained rubric also reduces reliance on external supervision: the judge is needed only to train the rubric generator, and the resulting self-generated signal outperforms using the judge directly. Additionally, a leaf-coverage reward provides a direct signal for decomposition quality, with the largest gains on tasks requiring coordination among interdependent subtasks. Beyond training, the learned rubric serves as an inference-time selector for tree search, further improving task success without additional training. Several limitations remain. We evaluate only Qwen3-4B on two synthetic benchmarks, so generaliza-tion to larger models and real-world agent tasks remains untested. Because the policy both writes and applies its own rubrics, self-evaluation could be gamed by scores that drift from genuine task success; we mitigate this by training rubric generation only against verified outcomes—a label-free dispersion reward instead degrades performance (Section 4.2)—but robustness under sparser or noisier verifica-tion, and the residual dependence on verified outcomes to anchor rubric training (Table 2), remain open. Finally, the leaf-coverage reward treats all leaf nodes equally, and subtask-level importance weights may improve decomposition training. Looking ahead, the rubric mechanism suggests learn-ing rubrics that generalize across tasks, using the rubric to guide exploration during training, and extending self-evaluation to settings where even the root outcome is not exactly verifiable. B.2 REWARD SOURCES AND ALTERNATING UPDATES 

Table 6 summarizes the reward configurations and update ratios using the method names from Table 1. Here, D denotes decomposition training with the leaf-coverage reward, and RT denotes rubric-generation training with the verified-outcome ranking reward. Execution updates supervise solving and delegation tokens; D updates supervise delegation tokens alone, and RT updates supervise rubric-generation tokens alone. Each optimizer step activates one objective on the shared policy, rather than summing the three raw rewards. For rubric-based execution, the policy both generates subtask-specific criteria and scores completed trajectories against them. Generating or applying a rubric does not itself constitute RT; RT explicitly optimizes the rubric-generation action using verified counterfactual outcomes. Accordingly, SERA w/o D & RT uses rubric scores without explicitly training the rubric generator. On TextWorld-Sync, the external LLM judge supplies binary subtask labels, whereas the policy rubric scorer supplies continuous execution scores. These training signals are distinct from the deterministic root verifier used to report benchmark success. We allocate most updates to execution, which directly trains task completion throughout the recursive tree. As the policy changes, periodic D and RT updates adjust its delegation decisions and the criteria that supply its execution rewards. Their data requirements differ: D uses ordinary execution trees, whereas RT requires additional counterfactual rollouts and external labels. We therefore keep RT updates infrequent while interleaving them with execution training, allowing the evaluator to adapt to the evolving rollout distribution. SERA uses an execution:D:RT ratio of 16 : 2 : 2 , reserving four of every twenty updates for decomposition and rubric generation. SERA w/o D uses 16 : 0 : 2 , retaining periodic rubric training while assigning the remaining updates to execution. RAO + D uses 12 : 4 : 0 , devoting a larger fraction to delegation updates, which require neither counterfactual sampling nor rubric scoring. The execution-only variants use 1 : 0 : 0 and optimize execution at every step. These ratios control how often each objective updates the shared policy; they are not coefficients applied to a combined reward. All recursive methods use the same total optimizer-update budget within each benchmark, with D and RT occupying part of that budget. On TextCraft-Synth, SERA is the fastest multi-agent method at 24 h06 m, below RAO’s 29 h36 m and well below the rubric-at-every-step ablation SERA w/o D & RT at 47 h02 m, while also being the most accurate (Table 1). Concentrating rubric computation into periodic rubric-generation training, rather than scoring every execution step against a rubric, is therefore what keeps SERA’s cost low on this benchmark. On TextWorld-Sync, SERA instead takes 24 h14 m versus RAO’s 13 h08 m. The two benchmarks diverge because their rollouts differ in cost: independent crafting branches in TextCraft admit parallel execution, whereas TextWorld’s shared-state dependencies force sequential interaction. The counterfactual rollouts used for rubric-generation training must also traverse these dependencies, and local rubric generation and scoring add per-step overhead even as external judge calls fall (Table 2). SERA thus trades additional training time on TextWorld for a 13 .14 -point average accuracy gain over RAO. C TEXT WORLD -S YNC DATASET CONSTRUCTION 

TextWorld-Sync extends the CookingWorld environment in TextWorldExpress (Jansen & Cˆ ot´ e, 2023) to test recursive delegation under shared-state constraints. Its design separates local subtask 15 completion from joint task success, complementing the independently verifiable crafting subtasks in TextCraft-Synth. C.1 SHARED WORLD AND AGENT -L OCAL CONTEXTS 

The standard TextWorldExpress interface exposes one mutable game through a single avatar. We retain the CookingWorld dynamics and introduce a coordinator that lets recursive agents interact with one shared world. Objects, containers, inventory, tools, doors, recipe progress, and task score are shared across agents. Each agent maintains its own logical location, dialogue history, observation stream, and step budget. Model calls may run concurrently, but environment reads and state transitions are serialized under a lock and committed atomically. Consequently, an item acquired by one agent becomes unavailable to others, while their locations and histories remain separate. This distinction permits concurrent planning while preserving consistent state updates and exposing dependencies between agents’ actions. C.2 PROCEDURAL TASKS AND COORDINATION STRUCTURES 

An original CookingWorld instance specifies one recipe, its required ingredients, and a target meal. TextWorldExpress procedurally samples recipes, layouts, object placements, and difficulty parameters. We extend this generator to sample multiple disjoint recipes per seed, assign ingredients to dishes, and introduce one of seven coordination structures. The complete instance is recorded in a fixed manifest and reconstructed at runtime by a multi-dish adapter. Independent dish branches can be delegated in parallel, subject to the instance’s resource and dependency constraints. Table 8 summarizes the seven task families and the coordination decisions they require. They range from independent branches to shared-resource conflicts and nested dependencies, providing different conditions for evaluating decomposition quality. The deterministic root evaluator reads structured environment state and requires every ingredient to be collected and correctly processed, and every dish prepared and consumed. Completing an individual dish yields partial progress but does not terminate the root task. This root-level check does not provide labels for arbitrary policy-generated subtasks; SERA therefore uses an external judge for rubric-training labels on this benchmark. C.3 DATASET SPLITS AND DIFFICULTY LEVELS 

Tasks are assigned to Easy, Medium, Hard, or Extreme according to the number and scale of their constraints. The fixed TextWorld-Sync split contains 1,500 training tasks, 200 validation tasks, and 1,400 test tasks. Training comprises 900 Medium, 150 Hard, and 450 Extreme tasks; validation and test contain 50 and 350 tasks per difficulty, respectively. For comparison, TextCraft-Synth training uses the fixed subset of 852 Medium tasks, with evaluation on 632 tasks spanning all four levels. Thus, TextCraft-Synth tests transfer from Medium training tasks across recipe depths, whereas TextWorld-16 Sync training covers several levels of coordination difficulty.
