## 摘要
预训练的视觉-语言-动作模型（VLA）在未见过的长时程任务中常常中途失败。递归自我改进（RSI）提供了一种补救手段，但具身 RSI 方法要么围绕冻结的执行器改进其运行框架（harness），因而无法补充缺失的动作，要么在持续失败上训练执行器，却不追问失败究竟源于执行器的调用方式，还是源于其自身能力。我们研究自改进具身系统应在何时改变其执行器的权重，并提出 AdaRSI，一个面向具身智能体的按需 RSI 框架。一个编码智能体首先改进自身技能与运行框架，然后通过从保存状态重试失败子步骤来归因持续失败，并仅对仍不可靠的子步骤进行微调，所用示范由其自行收集，并沿用先前任务积累的经验。在 RoboCasa365 的全部 50 个目标任务上，以 GR00T N1.5 作为执行器且不使用人类示范，AdaRSI 在全部三个套件上提升了该 VLA，并将未见过的组合任务成功率从 4.6% 提升至 13.8%。与微调每个子步骤相比，它以仅 28% 的 GPU 时间和 22% 的自收集示范达到略高的成功率；而不使用运行框架进行微调虽然训练更多，收益却远低。

## Abstract
Pretrained vision-language-action models (VLAs) often fail midway through unseen long-horizon tasks. Recursive self-improvement (RSI) offers a remedy, but embodied RSI methods either refine the harness around a frozen executor and so cannot add a missing motion, or train the executor on persistent failures without asking whether a failure lies in how the executor is called or in what it can do. We ask when a self-improving embodied system should change the weights of its executor, and propose AdaRSI, an on-demand RSI framework for embodied agents. A coding agent first improves its skills and harness, then attributes persistent failures by retrying failing sub-steps from saved states, and fine-tunes only the sub-steps that remain unreliable, with demonstrations it collects itself and experience carried over from earlier tasks. On all 50 target tasks of RoboCasa365, with GR00T N1.5 as the executor and no human demonstrations, AdaRSI improves the VLA on all three suites and raises its success on unseen composite tasks from 4.6% to 13.8%. Compared with fine-tuning every sub-step, it reaches slightly higher success while using only 28% of the GPU time and 22% of the self-collected demonstrations, and fine-tuning without a harness trains more yet gains far less.

# AdaRSI 论文结构化总结

## 1. 核心问题与研究动机

- **背景**：预训练视觉-语言-动作模型（VLA）虽能完成大量操作任务，但在未见过的长时程组合任务中常“中途失败”——可能接近错误目标、误判步骤成败，或缺少某个必需动作。
- **现有具身递归自我改进（RSI）的两类局限**：
  - **Harness 级方法**：围绕冻结执行器改进技能、工具与调用程序，改动廉价可读，但无法补足执行器缺失的动作能力。
  - **Policy 级方法**：直接微调执行器权重，部分方法按“近期成功率低”或“高风险场景”选择训练目标，但**不区分失败究竟源于“调用方式不对”还是“执行器不会做”**。
  - 少数同时作用于两层的系统，也只是在精炼 harness 产生的数据上训练，仍未回答“何时该改权重”。
- **核心问题**：自改进具身系统应在何时改变执行器的权重？
- **核心主张**：这是一个**归因问题**——只有当某个子步骤在尝试了其他调用方式（不同指令、位姿、接近方式）后仍不可靠时，才应改权重；先改 harness 还能设定策略训练与调用时的状态分布。

## 2. 方法论

### 2.1 系统形式化

- 系统 \(S=(A,H,\Pi)\)：
  - \(A\)：语言模型编码智能体，负责任务理解、系统运行与反馈读取；
  - \(H\)：harness，包含技能、工具及组合它们的程序（procedure）；
  - \(\Pi\)：执行器库，初始为 \(\Pi_0=\{\pi_0\}\)（单个预训练 VLA），随子步骤策略加入而增长。
- 改进阶段在仿真中进行，可用特权状态；部署阶段 harness 与库固定，仅用常规观测。无人类示范。
- 目标：在低成本 \(C(S)=C_H+C_\Pi\) 下最大化部署成功率 \(J(S)\)。

### 2.2 Harness 级改进（第一层）

- Harness 从最小集开始：仅暴露执行器、相机/本体感知、场景夹具地图、底盘与机械臂底层命令、基础导航工具；其余工具（精细对位、复位机械臂、相机变焦等）由智能体自行编写。
- 智能体在**留出验证回合**上运行系统，依据执行记录修订工具与程序；开发时可重置场景、保存/恢复仿真快照、查询成功检查。
- **快照支持反事实重执行**：同一子步骤从同一状态用不同指令/接近方式重试，从而区分“调用不当”与“动作缺失”。

### 2.3 下降至权重（第二层）

- **失败归因**：定义“执行器受限子步骤”——智能体找不到任何 harness 能让 \(\pi_0\) 可靠完成；记录这些子步骤及 \(\pi_0\) 从相应状态测得的成功率。
- **自采集示范**：对决定训练的子步骤，用两种方式在仿真中采集数据：
  - 对基础执行器做**拒绝采样**（反复 rollout，保留成功片段）；
  - 编写**脚本专家**读取特权状态（物体位姿、关节状态）生成并标注数据（特权信息学习范式，部署时不可见）。
- **微调与验证**：每个示范集从 \(\pi_0\) 或已有策略微调出新策略加入 \(\Pi\)；在开发状态上与新策略对比 \(\pi_0\)，仅在更优的子步骤上推荐新策略，其余默认 \(\pi_0\)；同时确定新策略的调用方式（如调用前机器人如何站位）。
- **策略保留**：所有训练过的策略保留在库中，部署智能体按程序推荐调用，也可在 \(\pi_0\) 反复失败后改用其他策略。

### 2.4 跨轮次与跨任务的递归

- 每轮映射 \(S_{k+1}=g(S_k,E_k)\)，经验 \(E_k\) 含开发运行、验证记录与训练结果；harness 与策略持久化，后续轮次可复用。
- **跨任务迁移**：选取覆盖高/中/低基础成功率的试点任务，不限预算地改进；从训练日志写出**经验文档**（哪类子步骤值得训练、多少数据足够、何处浪费），并按固定规则设定后续任务的**训练预算**（约束训练步数与自采集示范数）。
- 部署时由同一智能体的新实例按最终程序运行，无快照、成功检查或特权状态。

## 3. 实验设计

- **Benchmark**：RoboCasa365 全部 **50 个目标任务**，分三个套件：
  - Atomic-Seen（18 个，出现在执行器训练数据中）
  - Composite-Seen（16 个，出现在训练数据中）
  - Composite-Unseen（16 个，由熟悉子任务组合而成、训练数据中不存在）
- 遵循官方协议：目标划分（厨房与物体不与预训练重叠）、官方任务时程（含工具步数）、官方成功检查；每任务测试 **50 个场景**；开发/验证/测试场景互不重叠，测试场景不参与改进。
- **执行器**：GR00T N1.5（复合任务用 Composite-Seen checkpoint，原子任务用 Atomic-Seen checkpoint）。
- **智能体**：GPT-6.1-sol，通过 Codex 运行。
- **对比系统**：
  1. VLA：\(\pi_0\) 单独用完整任务指令运行；
  2. Agent + VLA：智能体自行发子指令但不做开发/训练；
  3. Agent + harness：只做 harness 轮次；
  4. AdaRSI：在 3 基础上加权重轮次。
- **消融变体**（Composite-Unseen）：
  - Agent + weights（只微调、无 harness）
  - Agent + harness（只改 harness）
  - Always train（每个子步骤都微调并默认调用）
  - Fixed procedure（把 AdaRSI 的程序与策略当固定程序执行，部署时无智能体）
  - AdaRSI w/ \(\pi_0\)（保留最终系统但用 \(\pi_0\) 替代微调策略）
  - Lowest first（按 \(\pi_0\) 成功率最低优先训练，同预算）
- **额外分析**：配对子步骤测试（同状态、同指令、同步数比较 \(\pi_0\) 与微调策略）、逐任务成本表、案例研究（WaffleReheat、WashFruitColander、GetToastedBread 等）。

## 6. 主要结论与发现

- **整体效果**：AdaRSI 在三个套件上均最优，50 任务平均 **48.8%**，对比 VLA 42.4%、Agent + harness 46.7%；Composite-Unseen 从 **4.6% → 13.8%**（约 3 倍），Atomic-Seen 75.4% → 79.7%，Composite-Seen 43.0% → 49.0%。
- **Harness 是更大杠杆**：仅让智能体发子指令（Agent + VLA）反而在 Atomic-Seen 下降（75.4→72.2）；经执行反馈改进工具与程序后升至 78.3%，Composite-Unseen 翻倍至 9.9%。多数失败源于程序而非缺失动作。
- **权重轮次补充关键缺口**：在 Composite-Unseen 再添 3.9 个百分点；WaffleReheat 从 0% → 38%（仅训练“开微波炉门”一个子步骤），RecycleBottlesByType 0% → 18%，BreadSelection 42% → 52%。
- **训练集中在哪里**：两个 seen 套件上多数训练策略从未被调用（Atomic-Seen 用 12/72，Composite-Seen 用 8/34，\(\pi_0\) 仍执行 78%/98% 的操作步）；Composite-Unseen 上 38 个策略中 32 个被使用，85% 训练时间花在被用策略上。
- **微调的双面性**：配对测试显示，对 \(\pi_0\) 不会的动作（开微波炉门 0/18→7/18；抓玻璃瓶 2/44→17/44）微调有效；对 \(\pi_0\) 已会的动作（放羊角包 16/40→11/40；放果酱 14/39→9/39）微调反而变差。
- **按需训练 vs 全量训练**：Always train 成功率 12.6% 低于 AdaRSI 13.8%，却用 3.1× 策略、4.5× 示范、3.5× GPU 时间；微调策略执行 71% 操作步 vs AdaRSI 的 15%，且会替换本已可靠的子步骤（WaffleReheat 38%→28%，WashFruitColander 58%→34%）。
- **无 harness 的微调收益有限**：Agent + weights 训练更多（45 个策略、1.25× GPU 时间）但部署只调用 5 个，成功率 7.2%；AdaRSI 调用 32 个。harness 决定“从哪些状态训练与调用”。
- **归因不可替代**：Lowest first 规则选中的子步骤与 AdaRSI 高度重合（13 个中 11 个相同），但成功率 11.8% 不敌 harness 的 12.0%，远低于 AdaRSI 的 16.6%——归因不仅选“训练什么”，还决定“从哪些状态学”。
- **部署时保留智能体有价值**：Fixed procedure 即使有特权状态辅助也只达 6.9%，远低于 AdaRSI 的 13.8%；在需要根据视角选站位或失败后换策略的任务上差距最大。
- **权重与程序贡献大致相当**：在 5 个权重轮次有变化的任务上，AdaRSI 相对 harness 增加的 31 次成功中，17 次依赖微调权重，14

…次依赖程序（调用方式）的调整。也就是说，权重轮次并非“万能补丁”，它只在 harness 已把问题压缩到“执行器确实不会”的那部分子步骤上才产生增量；两者的贡献接近对半，说明自改进系统需要**同时**保留两层，而不是用其中一层替代另一层。

- **成本-效果关系**：AdaRSI 在 Composite-Unseen 上用约 1/3.5 的 GPU 时间、约 1/4.5 的示范数取得高于 Always train 的成功率；相对 Agent + weights 也用更少训练（966 vs. 1,204 GPU 分钟）换来近两倍成功率（13.8% vs. 7.2%）。作者据此主张：RSI 的瓶颈不是“训练量不够”，而是“训练对象与训练状态选得不对”。
- **失败模式观察**：案例研究显示，剩余失败多集中在需要长时程状态维持、精细接触或对视角敏感的子步骤；部分任务即使加入新策略，仍会因上游子步骤的偶发失败而级联失败。这说明单点子步骤改进的收益会被任务链长度稀释。
- **对“何时改权重”的回答**：综合消融，作者给出的判据是——**先穷尽 harness 层面的调用方式，仍不可靠才下降至权重**；并且训练数据应来自“归因后确认受限”的状态分布，而非全局成功率排序。Lowest first 与 Always train 的结果表明，仅凭成功率高低选目标不足以复现 AdaRSI 的收益。

## 7. 局限与待验证之处

- **仅仿真验证**：全部结果来自 RoboCasa365 仿真，依赖仿真快照、特权状态与可重置场景；真实机器人上的快照回滚、反事实重执行与脚本专家标注都更难实现，作者称真实实验留待后续版本。
- **单一执行器与单一智能体**：执行器固定为 GR00T N1.5 的两个 checkpoint，智能体固定为 GPT-6.1-sol/Codex；未验证方法对更弱/更强 VLA、不同 LLM 智能体或不同动作空间的迁移性。
- **基准覆盖面**：虽覆盖 50 个任务，但均属同一仿真套件、同一机器人形态与厨房/家务场景；“组合未见”任务的子技能仍在训练分布内，真正的开放域新技能未涉及。
- **归因判据依赖验证回合的统计**：判定“执行器受限”需要足够的重试次数与稳定的成功率估计，样本少时可能误判；文中未系统分析该判据的敏感性与阈值选择。
- **成本口径**：以 GPU 分钟与 token 计量，缺少 GPU 型号、并行度与墙钟时间，跨系统复现成本比较存在不确定性；Also，改进阶段的智能体 token 成本与训练成本未合并为单一目标函数。
- **递归轮次有限**：跨任务迁移的经验文档与预算规则由作者手工设定固定规则，长期多轮递归是否会漂移、经验文档是否会过拟合到试点任务，尚未评估。
- **安全与部署约束**：部署阶段虽去掉了特权状态，但智能体仍可在失败后切换策略；这种运行时自适应带来的不可预测性与安全性问题未被讨论。

## 8. 总体评价与启示

- **贡献定位**：论文的主要贡献不是某个新模型，而是一个**归因框架**与可操作的工程流程——用 harness 的可逆、廉价修改去“探测”失败原因，再把权重更新限制在探测后仍失败的子步骤上。这把具身 RSI 从“训练什么”推进到“何时训练、从哪些状态训练”。
- **证据强度**：主对比、消融与配对测试相互印证，尤其“微调对已会动作有害”“无 harness 的微调调用率极低”“Fixed procedure 大幅退化”三组结果，较有说服力地支撑了核心主张；但证据全部来自仿真，外部效度仍是主要短板。
- **实践启示**：对构建具身智能体的团队而言，优先投资可编辑的 harness（工具、程序、调用约定）与可回滚的开发环境，可能比直接扩大策略微调规模更具性价比；策略库应保留历史版本并允许运行时回退，而非用新策略整体替换。
- **研究启示**：后续工作可探索自动化的受限子步骤判定（如基于置信区间或主动探测）、把归因信号用于在线部署、以及在真实机器人上验证快照式反事实重执行的可行性。
