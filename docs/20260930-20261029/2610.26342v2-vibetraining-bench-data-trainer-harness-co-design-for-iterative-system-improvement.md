## 摘要
递归自我改进（RSI）要求智能体诊断系统瓶颈，并协调训练与推理两方面的改进。我们将智能体联合优化训练数据、训练器和推理执行框架的能力称为跨组件协同设计。我们提出 VibeTraining-Bench，一个用于评估该能力在终端操作、软件工程、多轮工具使用和数学推理等任务上表现的基准。在每个任务中，研究智能体在固定资源预算下从相同的初始智能体系统出发。在验证反馈的引导下，它们迭代优化数据、训练器和推理执行框架，然后选择并提交最终智能体系统以在测试集上评估。为防止奖励黑客行为，我们实施三项保障措施：测试数据隔离、研究容器与评分容器分离，以及对研究智能体的网络限制。评估结果表明，前沿研究智能体能够显著提升目标智能体系统。例如，在 SWE-bench Verified 上，GPT-6-Astra 将目标智能体系统的性能从 32.9% 提升至 53.7%，接近人工开发的 instruct 模型的 55.4%。然而，它们在协同设计并迭代优化数据、训练器和执行框架以实现累积性能提升方面的能力仍有提升空间。我们希望 VibeTraining-Bench 能成为一个统一平台，推动 RSI 发展，加深我们对智能体系统跨组件优化的理解。代码和数据见 https://github.com/D2I-ai/VibeTraining-Bench。

## Abstract
Recursive self-improvement (RSI) requires agents to diagnose system bottlenecks and coordinate improvements across training and inference. We refer to the agents' capability to jointly optimize training data, the trainer, and the inference harness as cross-component co-design. We introduce VibeTraining-Bench, a benchmark for evaluating this capability across tasks spanning terminal operation, software engineering, multi-turn tool use, and mathematical reasoning. Within each task, research agents start from an identical initial agent system under a fixed resource budget. Guided by validation feedback, they iteratively refine data, trainers, and inference harnesses, then select and submit a final agent system for evaluation on the test set. To prevent reward hacking, we enforce three safeguards: test data isolation, separate research and grading containers, and network restrictions for research agents. Our evaluation results show that frontier research agents substantially improve target agent systems. For example, on SWE-bench Verified, GPT-6-Astra raises the target agent system's performance from 32.9% to 53.7%, comparable to the human-developed instruct model's 55.4%. However, there is still room to improve their ability to co-design and iteratively refine data, trainer, and harness to achieve cumulative performance gains. We hope that VibeTraining-Bench will serve as a unified platform for advancing RSI, deepening our understanding of cross-component optimization for agent systems. Code and data are available at https://github.com/D2I-ai/VibeTraining-Bench.

## 1. 核心问题与研究动机

- **背景**：递归自我改进（Recursive Self-Improvement, RSI）被视为通往自主 AI 研发的路径之一，要求智能体自行诊断系统瓶颈、提出并验证对智能体系统的修改。
- **核心概念**：论文提出 **跨组件协同设计（cross-component co-design）**，即智能体联合优化三类相互依赖的组件：
  - **训练数据（Data）**：示例选择、过滤、格式对齐、合成；
  - **训练器（Trainer）**：训练算法、损失计算、超参数、模型合并；
  - **推理执行框架（Harness）**：提示、工具接口、执行循环、输出解析、记忆管理。
- **问题缺口**：
  - MLE-Bench、RE-Bench 等关注任务特定的 ML 工程/研究成果，而非系统级协同改进；
  - RSIBench-Data、AI4AI-Bench、HarnessOpt-Bench、MLS-Bench 均只开放**单一组件**，归因清晰但无法考察耦合；
  - PostTrainBench、Agent²RL-Bench 扩展到数据构建与后训练流程，但**推理 harness 不在优化循环内**，且已报告 reward hacking（研究智能体直接在测试数据上训练）；
  - 尚缺少在**同一持续演化的目标系统**内、跨训练与推理迭代选择与协调修改的评测。
- **整体含义**：论文主张 RSI 的关键能力不是单点优化，而是"在哪里改、如何协同地改"的判断力，并为此提供统一评测平台。

## 2. 方法论

### 2.1 任务形式化

- 每个任务提供：基座模型 \(M_0\)、初始训练数据 \(D_0\)、训练器 \(T_0\)、推理 harness \(H_0\)、固定资源预算 \(B\)；初始目标系统 \(P_0=(M_0,H_0)\)。
- 第 \(t\) 轮迭代，研究智能体可在任务允许的编辑空间内修改 \(D_t\)、\(T_t\)、\(H_t\)；候选系统 \(P_t=(M_t,H_t)\)，其中 \(M_t\) 可以是**新训练的、多模型合并的、或复用早期迭代的**。
- 验证反馈 \(f_t\) = 验证集分数 + 逐任务执行轨迹（日志、rollout、分析），用于指导后续修改。
- 研究结束后智能体自选 \(P^\star\) 提交，隔离评分器在隐藏测试上**只评一次且不返回反馈**；度量指标为
  \[
  \Delta_{\text{test}} = \text{Eval}_{\text{test}}(P^\star) - \text{Eval}_{\text{test}}(P_0)
  \]

### 2.2 可编辑空间设计

- **Terminal-Bench 2.1、SWE-bench Verified**：开放 \(\{D,T,H\}\)，因 harness 直接决定终端/代码库交互（执行循环、命令行调用、内存管理）。
- **τ3-Bench、Toolathlon、AIME**：仅开放 \(\{D,T\}\)，benchmark 提供的执行适配器或评测接口固定。

### 2.3 防奖励黑客的三重保障

- **数据隔离**：测试任务及测试派生反馈在研究阶段全程不可访问；
- **容器隔离**：研究工作区与评分服务运行在分离容器，研究智能体无法修改评分代码或评测数据；
- **网络限制**：研究沙箱禁止外部网络访问。
- 验证须经受控接口请求，评分器返回聚合分数、分母、逐任务分数与轨迹。

### 2.4 研究智能体工作流约束

- 数据只能来自 `train_resource_manifest.lock.json` 授权资源，可过滤/去重/重平衡/混合/重写/增强/合成/蒸馏，但每条派生记录的**来源必须可追溯**；
- 禁止用验证任务或评分器返回轨迹构造训练数据，禁止在研究期间检索外部数据；
- 训练入口为 `run_train.sh`，可修改 `framework_src/` 下 slime、Megatron-LM 的 Python/Shell 代码（改算法、数据处理、checkpoint 处理），CUDA/C++ 改动需重建扩展；
- 最终交付 `final_model/`（模型 + 可选 harness）的候选快照。
