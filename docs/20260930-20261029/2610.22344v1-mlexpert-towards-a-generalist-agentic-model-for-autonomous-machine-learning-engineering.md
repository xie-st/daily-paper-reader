## 摘要
大语言模型（LLMs）正从辅助科学研究和工程扩展至自主开发与改进 AI 系统，推动 AI for AI（AI4AI）作为通向递归自我改进（RSI）的路径。工作流驱动的机器学习工程（MLE）系统通过管理长时程实验的复杂编排，为这一追求提供了可行路径；而近期的 MLE 系统采用模型主导的交互，使模型能够自主组织实验，并基于执行反馈调整优化策略。然而，每个实验的反馈反映了若干先前决策，且一次长 MLE 运行包含许多此类高成本实验。因此，训练必须从长交互轨迹中选择有用的监督，并从中间结果中学习。我们提出一种用于自主长时程 MLE 优化的后训练方法，并将其用于训练 MLExpert，一个 35B 的混合专家（Mixture-of-Experts）智能体模型。我们设计了 Kaggle-MLE Factory 来构建可执行任务，以及用于模型主导实验的交互框架。分层智能体监督微调（SFT）通过结果引导的监督，将通用工具使用和编码能力迁移到 MLE。窗口化交互强化学习（WIRL）将相邻实验结果之间的多轮决策视为一个执行窗口，并为其分配共享的基于结果的奖励。异步收集与策略校正支持在轨迹结束前更新策略。在 MLE-Bench Lite 上，MLExpert 将基础模型的平均奖牌率从 37.9% 提升至 72.7%，达到与 Kimi-K3 和 GLM-5.3 等更大前沿模型相当的性能。进一步实验表明，MLExpert 在 NatureBench Lite、智能体脚手架优化和算法优化上的性能均有所提升，表明所学习的优化能力可泛化到其他任务。

## Abstract
Large language models (LLMs) are expanding from assisting scientific research and engineering to autonomously developing and improving AI systems, advancing AI for AI (AI4AI) as a pathway toward recursive self-improvement (RSI). Workflow-driven machine learning engineering (MLE) systems provide a practical path toward this pursuit through complex orchestration that manages long-horizon experimentation, while recent MLE systems adopt model-directed interaction, allowing models to autonomously organize experiments and adapt optimization strategies based on execution feedback. However, feedback from each experiment reflects several preceding decisions, and a long MLE run contains many such costly experiments. Training must therefore select useful supervision from long interaction trajectories and learn from intermediate outcomes. We propose a post-training method for autonomous long-horizon MLE optimization and apply it to train MLExpert, a 35B Mixture-of-Experts agentic model. We design the Kaggle-MLE Factory to construct executable tasks and an interaction harness for model-directed experimentation. Hierarchical agentic SFT transfers general tool-use and coding capabilities to MLE through outcome-guided supervision. Windowed Interaction RL (WIRL) treats the multi-turn decisions between successive experiment results as an execution window and assigns it a shared outcome-based reward. Asynchronous collection and policy correction support policy updates before the trajectory ends. On MLE-Bench Lite, MLExpert improves the average medal rate of the base model from 37.9% to 72.7%, achieving performance comparable to larger frontier models such as Kimi-K3 and GLM-5.3. Further experiments show that MLExpert improves performance on NatureBench Lite, agent scaffold optimization, and algorithm optimization, suggesting that the learned optimization capability generalizes to other tasks.

## 2. 方法论

### 2.1 总体思想

论文将 MLE 建模为可执行方案的迭代优化问题：

- 任务表示为 \(e=(d_e,D_e,m_e)\)，分别为任务描述、数据和评价指标；
- 目标是寻找方案 \(y\) 最大化任务得分 \(S_e(y)\)；
- 智能体策略 \(\pi_\theta\) 在时间预算 \(B_e\) 内通过工具交互产生轨迹 \(\tau=(o_0,a_0,o_1,\dots,a_{L-1},o_L)\)；
- 优化目标为最大化最终提交方案 \(\hat y_\tau\) 的期望得分：
  \[
  J(\pi_\theta;e)=\mathbb{E}_{\tau\sim p_{\pi_\theta}(\cdot|e,B_e)}[S_e(\hat y_\tau)]
  \]

整体由三部分组成：**Kaggle-MLE Factory 任务构建**、**Interaction Harness 交互环境**、**分层 Agentic SFT + WIRL 后训练**。

### 2.2 Kaggle-MLE Factory：可执行 MLE 任务构建

- 将历史 Kaggle 竞赛转化为带公开工作区、隐藏测试集和统一评测接口的可执行任务。
- 使用多智能体流水线：
  - **Discovery agent**：按竞赛状态、规模、提交格式筛选；
  - **Analyzer agent**：提取数据结构、字段、模态特征，形成任务规格；
  - **Generator agent**：准备数据、构造隐藏标签测试集、实现评测器；
  - **Executor / Validator**：在真实数据上执行，检查数据完整性、提交格式、标签非退化、训练/测试 ID 重叠、评分函数有效性；
  - 错误返回构建智能体修复，最后人工复核。
- 文中从 11,649 条竞赛元数据出发，注册 160 个任务，排除 6 个标签或评分问题任务，保留 **154 个任务**用于轨迹收集。

### 2.3 Interaction Harness：模型主导的长时程交互

- 采用 ReAct 风格循环，**不依赖外部搜索策略**，由模型根据当前实验状态决定分析、修改、执行、回溯或更换方向。
- 实验状态存储在 **solution nodes** 中，包含候选代码、执行日志和元数据；父链接修订形成**实验树**，支持比较、回溯与重访。
- 主要工具包括：
  - `analyze`：调用独立分析子智能体进行数据分析、结果诊断；
  - `execute_bash`：检查数据和运行环境；
  - `write_full_code` / `patch_code`：创建或修改方案；
  - `execute_code` / `control_run`：启动和控制实验；
  - `write_plan` / `edit_plan` / `read_plan`：维护实验计划；
  - `list_nodes` / `select_node`：检索候选状态与历史；
  - `invalidate_node`：排除不可信或过拟合候选；
  - `update_answer` / `get_current_answer`：维护最终提交候选。
- 当上下文接近上限时，对早期消息进行摘要并保留近期交互。

### 2.4 分层 Agentic SFT

- **第一阶段：通用智能体 SFT**
  - 使用多样智能体任务中的编码与工具使用轨迹，学习基础工具调用和代码修改能力。
- **第二阶段：MLE 领域适配 SFT**
  - 使用 MLE 教师轨迹和文献衍生的科学实验任务轨迹，提升算法设计、实验分析和迭代优化能力。
- **互补示范数据**：
  - 初始方案轨迹：从任务开始到首次成功执行并达到质量阈值的交互前缀；
  - 长时程优化轨迹：覆盖方案构建、反馈分析、迭代修改和最终提交选择；
  - 分析子智能体轨迹：训练独立数据分析与结果诊断。
- **结果引导的监督筛选**：
  - 对轨迹按提交得分排序，设质量阈值 \(\eta=0.4\)；
  - 找到首次最佳提交位置 \(j^\star\)，计算峰值后的平均相对退化 \(d(\tau)\)；
  - 若退化超过阈值 \(\delta=0.05\)，以首次最佳提交为截断锚点；否则以最后一次提交为锚点；
  - 保留锚点前的有效探索和失败恢复，删除退化尾部，并最多延伸 10 个完整工具交互。
- **训练目标**：只对新增的推理、文本响应和工具调用 token 计算损失，工具反馈和历史上下文仅作为条件输入并被 mask。

### 2.5 Windowed Interaction RL（WIRL）

- **核心思想**：将相邻两次实验结果之间的多轮模型决策定义为一个**执行窗口** \(u_m\)，窗口共享该次实验的结果奖励，从而不必等待整条轨迹结束即可更新策略。
- **窗口奖励设计**：
  - 执行错误且由模型动作导致：\(-1.0\)；
  - 无执行错误但无可评分提交：\(-0.6\)；
  - 有效提交但低于奖牌阈值：\(-0.4+T_m\)；
  - 铜牌或银牌：\(1.0+T_m\)；
  - 金牌：\(2.0+T_m\)。
  - 其中 \(T_m\in\{-0.2,0,0.2\}\) 表示相对上一次有效提交的局部性能趋势。
- **共享优化权重**：直接使用可验证执行奖励 \(\hat A_m=R_m\) 作为窗口内所有主模型输出 token 的共享权重，不采用 GRPO 的组内归一化。
- **异步收集与策略校正**：
  - 实验时长不同，WIRL 异步收集已完成窗口组成 batch；
  - 长轨迹可能跨多个策略版本，因此记录 rollout 时 log-prob；
  - 对 token 计算校正比 \(q=\exp(\ell_{\text{old}}-\ell_{\text{roll}})\)，在区间 \([0.2,4.0]\) 内按 \(q\) 加权，区间外 token 排除出策略梯度更新。
- **优化目标**：
  - 使用 PPO 风格 token 级策略梯度损失；
  - 每个窗口按有效输出 token 数归一化，再在 batch 内平均；
  - 加入相对 SFT 参考模型的 KL 正则和熵正则；
  - 仅使用具有可信执行反馈的窗口，基础设施错误或评分不可用的失败不进入训练。
