## 摘要
大多数当代人工智能（AI）系统在发布时参数被冻结，并通过外部更新来改进，而理想的系统应能从自身经验中持续改进，我们将这种能力称为递归自我改进（RSI）。然而，研究 RSI 需要一个持续变化、可客观验证且具有自然基础的环境，这对智能体演化构成了根本性挑战。在此，我们提出 DeepEvolve，一个基于未来事件预测的可持续演化智能体系统；其中智能体与动态演化环境持续交互，并通过内化和外化这些交互中获得的经验来改进。一个“活”的环境合成可验证任务，而递归演化引擎将每次预测背后的推理轨迹转化为能力：将搜索与预测解耦，使参数级演化适应易受污染的实时环境；同时蒸馏可复用技能，使智能体能够从这种环境所提供的有限实时轨迹中演化。在外部 FutureX 排行榜上（该排行榜根据真实世界结果评估预测，并每周更新），我们自我改进的预测器连续三周在所有系统中排名第一，评分提升最高达 195%。在我们合成的评估中，它在四个基础 LLM 上均位列前三，最高以 10.7 个 Bradley--Terry 分优于最强基线。更广泛地说，这些结果表明，一个为自我改进而构建的系统最好被理解为一个与真正鲜活、开放的环境共同演化的智能体，这指向 AI 的转变：从在固定数据上训练静态模型，转向培养能够从自身经验中变得更强、并以这样的开放世界作为其成长不可或缺基础的智能体。

## Abstract
Most contemporary artificial intelligence (AI) systems are released with frozen parameters and improve through external updates, whereas an ideal system would keep improving from its own experience, a capacity we call recursive self-improvement (RSI). Yet studying RSI requires an environment that is continuously changing, objectively verifiable, and naturally grounded, posing a fundamental challenge for agent evolution. Here we introduce DeepEvolve, a sustainable evolution agent system grounded in future event prediction, in which agents continuously interact with a dynamically evolving environment and improve by internalizing and externalizing the experience gained through these interactions. A living environment synthesizes verifiable tasks, and a recursive-evolution engine turns the reasoning trajectory behind each prediction back into capability: decoupling search from prediction adapts parameter-level evolution to the contamination-prone live environment, while distilling reusable skills lets the agent evolve from the limited live trajectories such an environment affords. On the external FutureX leaderboard, which evaluates predictions against real-world outcomes and is updated weekly, our self-improved forecaster ranked first across all systems over three consecutive weeks, achieving up to a 195% improvement in rating. On our synthesized evaluation, it ranked among the top three across four base LLMs, outperforming the strongest baseline by up to 10.7 Bradley--Terry points. More broadly, these results suggest that a system built for self-improvement is best understood as an agent that co-evolves with a genuinely living, open-ended environment, pointing to a shift in AI from training static models on fixed data toward cultivating agents that grow stronger from their own experience, with such an open world as the indispensable basis of that growth.

## 1. 核心问题与研究动机

- **根本问题**：当代 AI 系统发布即“冻结参数”，能力提升依赖外部人工整理数据与离线重训，属于**被动改进**；理想系统应能从自身经验中持续、累积地变强，即**递归自我改进（Recursive Self-Improvement, RSI）**。
- **研究 RSI 的真正瓶颈不在方法而在“环境”**：递归要求环境能（i）持续提出新挑战、（ii）无需人工干预即可判定是否进步、（iii）自然接地。而当今主流评测所依赖的固定数据集是“惰性”的——既不更新任务，也不能自行判定进展，且容易被记忆/污染。
- **为何选“真实世界事件预测”作试验台**：它天然满足三个性质——接地的（基于正在展开的世界而非手工构造数据）、可验证的（真实结果随时间自动揭晓）、非平稳的（世界持续变化）。由此可闭合“观察世界→预测→获得结果→学习→改进下一次预测”的回路。
- **与邻近工作的区别**：自生成数据自训练缺乏外部可验证真值、易自我强化偏差；持续学习多在静态/人为切分的任务流上；面向推理的 RL 只优化单任务奖励，不追求跨时间复利。
- **核心论点**：可持续的自我改进不能只推“单一杠杆”（权重 / 提示 / 记忆），而应让**参数、技能、环境三者从同一份预测轨迹中共同演化**；环境是“源头”，决定另外两者的上限。
- **整体含义**：AI 的发展范式应从“在固定数据上训练静态模型”转向“在活的开放世界中培育会成长的智能体”，进度度量也应从“某一时刻能做什么”转为“改进的速率、上限与持久性”。

## 2. 方法论：DeepEvolve 框架

### 2.1 总体思想

系统由三个模块构成**闭环**（而非流水线），状态记为三元组 Σ(t) = (θ(t), S(t), E(t))，分别对应智能体参数、技能库、环境；一轮演化即

- θ(t+1) = Φ_rl(θ(t), T(t))
- S(t+1) = Φ_skill(S(t), T(t))
- E(t+1) = Φ_env(E(t), T(t))

其中 T(t) 为在 Q(t) 上 rollout 得到的轨迹池。“递归”指本轮产物即下一轮原料，且 Φ_env 持续生成与更新后策略匹配的新任务，使系统不收敛到固定权重。

### 2.2 Prometheus：活的数据环境

- **两条问题生成路径**：①模板式生成（从公开日历、赛程、订阅源、结构化页面抽取即将发生的事件并套用模板）；②智能体驱动的开放发现（由 Codex 浏览网站、解读日程与进行中的新闻，构造结构化问题草稿）。
- **问题形式化**：q = (e, o, f, t_cut, t_dl)，即事件标识、待预测结果、答案格式、生成时刻、预测截止时刻。
- **流水线**：Q(t) = SELECT ∘ FILTER(GEN(D(t), S_env(t)))，其中 S_env 为 Athena 回传的“任务合成技能”，用于把生成偏向智能体弱项。
  - **时间合法性与验证**：仅保留 t_cut < t_dl 且 t_cut < t_res(q) ≤ t_cut + H（H 为时间视野，如 24 小时）。
  - **去重与冲突检测**：由 (e, o, f, 时间边界) 生成可复现 id；同 (e,o) 属性一致则保留代表、冲突则整组丢弃。
  - **多样性选择**：优先未出现事件，每事件最多 2 题；优先历史上较少覆盖的领域/来源、较少出现的题型与答案格式、较早截止者。
- **奖励来源**：事件揭晓后给出客观结果 y_q，定义可验证奖励 r(q, p̂) = 1[argmax_o p̂(o) = y_q]，即由“时间”而非人工标注提供监督。

### 2.3 Branchus：智能体预测器

- **按“是否依赖执行时刻”拆分两个团队**（核心设计）：
  - **搜索团队**（scheduler / searcher / critic）：时间敏感，负责分解问题、检索证据、评估可靠性，产出搜索轨迹 τ_s；事件揭晓后同一检索会直接查到答案，因此必须在开放窗口内完成并**缓存**。
  - **预测团队**：时间不变，只读取缓存的搜索轨迹集合 {τ_s^(j)}，做证据聚合、冲突消解与概率判断，p̂ ~ π^p_θ(·| q, {τ_s^(j)}, S)。
- **技能管理**：技能库 S(t) = S_0（人工种子）∪ 历轮蒸馏所得；每个技能是四层元组 s = (s1, s2, s3, s4)，由抽象（跨领域原则）到具体（可执行流程/来源）；推理时按 Eq.(9) 检索，对每个匹配技能保留“仍然适用的最具体层级”，使无先例的新问题也能受益于更抽象层级。

### 2.4 Athena：递归演化引擎（三条杠杆）

- **参数级 Φ_rl（RLVR + RFT）**
  - 关键技巧：**只训练预测团队**，输入为已冻结的缓存证据。这样既避免“答案泄漏”（模型无法再去检索必然蕴含答案的证据），又保留探索空间（同一证据下采样 G 个预测）。
  - 奖励 r_i ∈ {0,1}，组内归一化得优势 A_i = (r_i − mean)/std；用带裁剪的 GRPO 目标更新（重要性比 w_i(θ)、裁剪区间 ε）。另用 RFT 在成功轨迹上做微调。
- **行为级 Φ_skill（技能蒸馏）**
  - ΔS = ORGANIZE ∘ FILTER ∘ EXTRACT ∘ EVAL：
    - EVAL：裁判模型**逐动作**按角色 rubric 打分（scheduler/searcher/critic 等），**扣留真实结果 y_q**（避免“结果正确但过程错误”被当成好经验），多裁判取中位数；
    - EXTRACT：区分“有帮助但非显然的正经验”与“反复出现的错误模式（负经验）”；
    - FILTER：剔除仅复述 rubric、无轨迹支撑、只规定“查什么来源”而非“怎么预测”的弱经验；
    - ORGANIZE：把轨迹中实际执行的流程**逐字保留为 s4**，逐级泛化为题型级 s3、领域级 s2、跨域原则 s1，且每层须落在该角色职责内。
  - 无需梯度，权重不变，因而可在每轮后廉价重复。
- **环境级 Φ_env（对抗式任务合成）**
  - 由已揭晓的 (q, p̂, y_q) 按答案类型/任务特征映射到类别 c，统计错误画像 ρ(c) = E[1 − r(q, p̂)]；
  - 取 argmax_c ρ(c) 作为“最不可靠类别”，经 SYNTHESIZE(ρ) 生成任务合成技能 S_env（含目标类别、适用条件、事件发现流程、构造规则、质量约束），注入 Prometheus 生成器；
  - 要求：只规定“如何造题”，不规定“如何答题”，且每题必须客观、可复现解析、在 cutoff 时未知。
- **训练稳定性与污染控制**：搜索/预测解耦使“多次 rollout”可读同一冻结证据池；若答案泄漏，奖励会提前坍塌，作者据此把“奖励持续有效”作为未泄漏的间接证据。
