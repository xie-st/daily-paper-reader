## 摘要
递归自我改进（RSI）是指系统还能改进其改进方式，这是通往 AGI 道路上的长期愿景。语言智能体越来越多地将程序性知识存储为可复用技能。技能优化为实现 RSI 提供了直接途径，因为优化过程本身可以编码为一项技能。然而，现有技能优化器遵循手工设计的流程。即使是演化元技能的方法，也将其限制在固定流水线中，并为每个任务重新学习。我们提出 Skill$^{\infty}$，使技能优化能够递归自我改进：元智能体遵循元技能来优化任务技能，并使用相同过程优化元技能本身。优化由智能体主导。元智能体诊断执行轨迹、提出候选方案、请求独立评审并分配搜索预算。元技能定义这些步骤，使自我改进能够重写它们。该元技能还与任务技能解耦，在多个技能优化任务上进行细化，然后复用于跨不同领域优化任务技能。与部署时一样，两个层级的技能都是通过原生技能发现加载的标准包。在 83 个 SkillsBench 任务上，Skill$^{\infty}$ 的通过率达到 60.7%，而人工精选技能为 56.4%，SkillEvolver 为 54.5%。

## Abstract
Recursive self-improvement (RSI), in which a system also improves the way it improves, is a long-standing aspiration on the path to AGI. Language agents increasingly store procedural knowledge in reusable skills. Optimizing skills offers a direct way to achieve RSI, because the optimization procedure itself can be encoded as a skill. Existing skill optimizers, however, follow a hand-designed procedure. Even methods that evolve a meta-skill confine it to a fixed pipeline and relearn it for each task. We present Skill$^{\infty}$, which makes skill optimization recursively self-improving: a meta agent follows a meta-skill to optimize task skills and optimizes the meta-skill itself using the same procedure. The optimization is agent-led. The meta agent diagnoses execution traces, proposes candidates, requests independent reviews, and allocates the search budget. The meta-skill defines these steps, allowing self-improvement to rewrite them. This meta-skill is also decoupled from task skills, refined on multiple skill optimization tasks and then reused to optimize task skills across diverse domains. As in deployment, skills at both levels are standard packages loaded through native skill discovery. On 83 SkillsBench tasks, Skill$^{\infty}$ reaches a pass rate of 60.7%, compared with 56.4% for human-curated skills and 54.5% for SkillEvolver.

# Skill$^{\infty}$：用于智能体技能优化的递归自我改进 —— 论文总结

## 1. 核心问题与研究动机

- **背景**：递归自我改进（RSI）指系统不仅提升任务表现，还能改进“产生改进的程序本身”，是通往 AGI 的长期愿景（从 Good 的智能爆炸到 Gödel Machine）。语言智能体正把程序性知识封装为可复用的 **skill**（技能包），而“优化技能的程序”本身也可以写成一项技能，因此技能优化成为实现 RSI 的直接、可解释途径。
- **现有方法的共同缺陷**：
  - SkillOpt、CoEvoSkills、SkillEvolver 等优化器仍遵循**手工设计的固定流程**；在一个技能上学到的优化经验无法迁移到下一个技能。
  - MetaSkill-Evolve 虽演化元技能，但**管线角色与连接方式固定**，且元技能**绑定于它共同演化的那个任务技能**，需要逐任务重新学习。
  - 部分方法在优化时**注入技能或提示智能体加载技能**，与真实部署条件（依赖原生技能发现）不一致，无法检验智能体是否会自主激活技能。
- **核心论点**：只改进技能、不改进“改进程序”的优化器终将停滞；RSI 正是针对这一瓶颈。

## 2. 方法论

### 2.1 核心思想

- 让**元智能体**遵循一个**元技能**（meta-skill）去优化任务技能，并用**完全相同的过程**优化元技能自身；两个循环在元技能处交汇，形成 “∞” 形状。
- 优化完全**由智能体主导**（agent-led）：诊断轨迹、提出候选、请求独立评审、分配预算均由元智能体推理决定，而非硬编码启发式。

### 2.2 形式化定义

- **技能包**：遵循 Agent Skills 开放规范，以 `SKILL.md` 为核心（front matter 声明 name/description，正文为指令），可捆绑脚本与参考文件。
- **原生技能发现（native skill discovery）**：智能体初始只看到名称与描述，判断有用后才加载完整指令与资源（渐进式披露）；因此**描述本身也在优化范围内**。
- **任务评分**：$S(s;T)=\frac{1}{|T|}\sum_{\tau}\frac{1}{n}\sum_j r_j(s,\tau)$，即每任务 n 次试验的平均奖励再对任务宏平均。
- **技能优化任务** $q=(s_0^q, T^q, B^q)$：元技能 $m$ 在预算 $B^q$ 内把种子技能优化为 $s_q^\star(m)$。
- **元奖励/元分数**：$g(m,q)=S(s_q^\star(m);T_q)-S(s_0^q;T_q)$，$S(m;Q)=\frac{1}{|Q|}\sum_q g(m,q)$——即“元技能引导的优化所带来的平均增益”，使同一套优化流程可直接作用于元技能自身。

### 2.3 算法流程（Algorithm 1，单次迭代六步）

1. **Inspect**：查看归档（archive）中的优化历史、父节点、剩余预算。
2. **Diagnose**：对父技能发起 rollout，基于执行轨迹诊断失败原因，形成可证伪的改进假设。
3. **Propose**：从父技能创建 1–2 个候选（各附 proposal：观察 / 改动 / 预期效果 / 证伪条件），并扣减预算。
4. **Evaluate**：并行评估候选并写入归档。
5. **Review**：每个候选提交给**独立评审子智能体**（隔离上下文，只看父/候选包、proposal 与证据）；拒绝无实质改动、从未被激活、或按写法不可用的候选；元技能候选还须保留评审等核心职责。
6. **Decide**：结合分数、评审、历史与剩余预算，选择下一轮父节点或终止。

### 2.4 关键设计

- **搜索即推理**：分数只说明“是否变好”而不说明“为何变好”，元智能体结合诊断与评审解释分数，可保留“打平但有进展”的候选、回退到早期节点、或在增益无法归因时保留父节点。
- **自适应预算分配**：候选数量（探索 vs 深耕）与停止时机由元智能体按目标技能剩余改进空间决定。
- **端到端 RSI**：六步流程写在元技能里而非代码里，因此自我改进可重写任意部分（含评审与选择规则）；**评分机制位于自我改进范围之外**，防止奖励篡改。
- **元技能与任务技能解耦**：先在跨领域的技能优化任务集 $Q$ 上把 $m_0$ 精炼为 $m^\star$，再复用于优化各领域任务技能，从而摊销自我改进成本，并偏好跨领域有效的改动。
- **两层均走原生技能发现**：不注入、不提示加载，保证测得的增益在部署中可复现；元技能可跨 harness 移植。

## 3. 实验设计

- **基准/数据集**：
  - **SkillsBench**：83 个智能体任务，覆盖 8 个领域（软件工程 14、网络安全 7、自然科学 14、金融经济 9、办公 14、媒体内容 9、工业物理 11、数学 5）；在 SkillEvolver 发布的数据集上优化任务技能，在其 83 个测试任务上评测。
  - **KernelBench**：3 个 level-3 问题（深层窄 MLP、ShuffleNet、GRU），共用一个任务技能，考察连续无界奖励下的表现。
- **对比基线**（同一 harness 与骨干模型）：No skill、Human-curated（人工精选技能）、Self-generated（任务中自写技能）、SkillCreator、SkillEvolver，以及消融版 **Skill∞ w/o self-improvement**（用种子元技能）。
- **配置**：Codex CLI + GPT-6 Luna（高推理强度），Harbor 执行试验；种子任务技能来自通用模板（只识别任务、无任务特定知识）；每任务技能搜索预算上限 4 个候选；自我改进内层预算为每优化任务 2 个候选、元技能最多 4 个候选。
- **指标**：SkillsBench 用 avg@5 通过率（reward>0 记为通过）；KernelBench 用正确性加权加速比（错误实现记 0）；所有结果取 5 次独立运行平均。
- **额外实验**：更换骨干模型（GPT-5.6 Luna）与更换 harness（OpenCode）；按 skill-utility 类别（A、B1–B3、C1、C2、D）细分；预算缩放（1/2/8 候选）；token 成本统计；两个案例研究。

- 论文**未报告模型训练算力**（无 GPU 数量、训练时长等信息），因为方法完全基于现成 LLM 的推理与 API 调用，不涉及训练。

  - **覆盖较广但深度有限**：KernelBench 仅 3 个问题、共用一个技能；预算缩放只在“默认预算明显有提升”的子集任务上做，存在**选择性偏差**风险；元技能仅精炼 4 个候选、内层预算 2 个候选，自我改进的搜索空间相对很小。

## 6. 主要结论与发现

- **SkillsBench**：Skill∞ 总体通过率 **60.7%**，超过人工精选技能（56.4%）、SkillEvolver（54.5%）、SkillCreator（48.0%）、自生成技能（42.9%）与无技能（45.5%）；在软件工程（65.7）、媒体（84.4）、数学（92.0）领先最明显。
- **消融**：去掉元技能自我改进后降至 **55.9%**（仍高于其他自动方法），说明“智能体主导的流程”本身已有效，而**自我改进把方法推到人工技能之上**（数学 +24.0、媒体 +22.2、SWE +11.4）。
- **KernelBench**：平均正确性加权加速 **1.62**（SkillEvolver 1.18、无技能 1.02），在 MLP 与 ShuffleNet 上达 1.87 / 1.97，不仅提升“是否成功”，也提升“做得多好”。
- **泛化性**：换 GPT-5.6 Luna 得 66.5%（人工 61.2%），换 OpenCode 得 56.9%（人工 53.3%），优势保持。
- **增益来源**：提升集中在智能体原本够不着的任务——类别 D（两者皆不能解）30.5% vs SkillEvolver 22.1%；类别 C1（仅人工技能能解且≥40%）29.2% vs 15.4%。
- **预算缩放**：1→2→8 个候选，通过率从 47.5% 升至 82.5%，且无需重调流程。
- **行为层面变化**：案例显示自我改进把“平局候选仅在轨迹显示目标失败被解决时才可选中”写入元技能，使平局候选被选比例从 83% 降到 54%——改变的是元智能体的**行为**，不只是措辞。

## 7. 优点

## 7. 优点

- **问题定位精准，概念框架清晰**：论文没有把 RSI 当作空泛口号，而是将其落到“优化技能的程序本身也是技能”这一可操作、可观测的载体上，并用“∞”形双循环把“改进技能”与“改进改进程序”统一为同一套机制，概念简洁且自洽。
- **形式化与工程实现结合紧密**：从技能包、原生技能发现、任务评分到元奖励 $g(m,q)$ 与元分数 $S(m;Q)$，定义层层递进，且每个符号都能在 Algorithm 1 的六步流程与实验指标中找到对应物，避免了“形式化只用于装饰”的常见问题。
- **评测协议贴近真实部署**：两层均走原生技能发现、不注入不提示加载，使测得的增益具备可复现性；这一点直接回应了既往工作在评测条件上的失真，是方法论层面的实质贡献而非增量改进。
- **消融设计具有解释力**：`Skill∞ w/o self-improvement` 同时隔离了“智能体主导流程”与“元技能自我改进”两个因素，结论（前者已有效、后者把方法推到人工技能之上）比单纯报一个更高分数更有信息量。
- **奖励篡改的边界处理得当**：明确把评分机制置于自我改进范围之外，同时允许元技能重写评审与选择规则，在“开放自我修改”与“防止刷分”之间给出了可执行的折中，体现了对 RSI 安全边界的自觉。
- **成本论证务实**：以 token 消耗而非训练算力衡量开销，并给出“自我改进摊销到 83 个任务后增加不到 15%、随复用继续摊薄”的量化论证，使“先花一次成本精炼元技能”的经济性成立。
- **行为层面的证据链完整**：案例研究不止展示分数变化，还展示了元技能文本改写后元智能体**决策行为**的统计变化（平局候选选中比例 83%→54%），为“自我改进改变的是行为而非措辞”提供了直接证据。
- **可移植性有实证支撑**：跨骨干模型与跨 harness 两组实验表明增益不依赖于特定 CLI 或特定模型，元技能作为文本资产具备跨环境迁移的潜力。

## 8. 局限性

- **自我改进的搜索空间偏小**：元技能仅精炼 4 个候选、内层每任务 2 个候选，且只做一轮（或极少轮）元层迭代。论文展示的是“一次自我改进即有效”，但未回答“持续多轮自我改进是否继续增益、何时饱和或退化”，而这恰是 RSI 概念的核心追问。
- **缺少与训练型/搜索型优化器的对比**：基线集中在提示/技能工程类方法（SkillOpt 系、SkillEvolver、SkillCreator），未与基于强化学习、进化搜索或反思式优化（如 GEPA 类）的方法正面对比，因此“智能体主导优于硬编码流程”的结论目前只在同类方法内部成立。
- **基准覆盖的深度不足**：SkillsBench 虽覆盖 8 领域 83 任务，但每领域任务数有限（数学仅 5 个），领域级结论（如数学 92.0%）的统计稳定性存疑；KernelBench 仅 3 个 level-3 问题且共用一个技能，难以支撑关于“连续无界奖励”的一般性结论。
- **预算缩放实验存在选择性偏差**：只在“默认预算下已有明显提升”的子集任务上做 1/2/8 候选的缩放，47.5%→82.5% 的曲线可能高估了预算收益，因为难任务（默认预算下无提升者）被排除在外。
- **方差报告缺失**：虽为 5 次独立运行取均值，但未报告标准差或置信区间，方法间差距（如 60.7% vs 56.4%，差 4.3 个百分点）是否显著无法判断。
- **自我改进的“不可逆风险”未被系统评估**：元技能可重写评审与选择规则，论文仅以“评分机制在范围之外”作为防护，但未报告自我改进过程中是否出现过退化、是否发生过评审职责被削弱而被回退的情况，也缺少对元技能漂移的长期监测。
- **成本口径不完全可比**：token 成本对比中 SkillEvolver 的输入 token 反而更高（8.06M vs 8.74M 量级接近），但各方法的候选数、rollout 次数与并行度不同，单以 token 衡量未完全归一化；也未报告 wall-clock 时间与美元成本。
- **单一种子模板**：种子任务技能均来自同一通用模板，未考察种子质量对自我改进收益的影响，而“垃圾进、垃圾出”在元学习场景中尤为关键。
- **可解释性停留在案例层面**：元技能具体改写了哪些条款、这些改写如何在多任务上迁移，仅以两个案例说明，缺少对元技能文本演化的系统性分析（如条款级 diff 统计、跨任务复用率）。

## 9. 启示与可借鉴点

- **“把流程写成技能”是一种低成本的元学习接口**：相比把优化策略编码进程序，把六步流程写进 `SKILL.md` 使得自我修改无需改代码、无需重训，天然支持人机共读与审计，这一设计范式可迁移到其他智能体系统的自我调优场景。
- **元奖励定义为“优化带来的增益”而非“任务得分”**：$g(m,q)=S(s_q^\star)-S(s_0^q)$ 的设计使同一套评分机制可直接评估优化器本身，避免了为元层另建一套奖励体系，是构建自指评估的实用技巧。
- **“评分在环外、策略在环内”的安全边界**：将不可自我修改的部分（评分）最小化并置于环外，其余尽量开放，为其他自我改进系统提供了可操作的安全设计原则。
- **独立评审子智能体 + 隔离上下文**：以隔离上下文的评审者过滤“无实质改动/从未被激活/写法不可用”的候选，是一种低成本的质量门控，可缓解自我改进中的自我确认偏差。
- **原生技能发现作为评测前提**：把“智能体是否自主激活技能”纳入评测条件，提示后续技能类工作应避免注入式评测，否则增益无法在部署中复现。
- **按 skill-utility 类别细分归因**：用 A/B/C/D 类别刻画“人与自动方法各自能否解决”，使增益来源可定位（集中在两者皆不能解的 D 类与仅人工可解的 C1 类），这一分析框架值得在技能/工具增强类论文中推广。
- **成本摊销叙事**：把元层成本除以复用任务数来论证经济性，为“一次性元投资 + 多次复用”类方法提供了标准的成本论证模板。

## 10. 总体评价

论文的核心贡献不在于刷新某个基准分数，而在于提出并验证了一条**可操作、可审计、成本可控的 RSI 最小实现路径**：把优化流程本身技能化，再用同一流程优化它自己，并以“优化增益”作为元层奖励闭合自指循环。实验在公平性（共享 harness/骨干/种子/协议、5 次运行、直接消融）与贴近部署（原生技能发现、跨模型跨 harness）两方面做得扎实，行为层面的案例证据也使“自我改进确有其事”的论断超出分数层面。

与此同时，论文对 RSI 最关键的两个问题——**多轮迭代是否持续增益、自我修改是否会漂移退化**——给出的证据仍属初步：元层搜索空间小、仅少量候选、缺方差报告、预算缩放存在选择偏差、也缺少与训练型优化器的对比。因此更准确的定位是：论文证明了“智能体主导的技能自我改进在单轮尺度上可行且优于人工与现有自动方法”，而“递归”能否在更长的时间尺度上兑现，仍是开放问题。

对后续工作的直接指引包括：延长元层迭代并监测饱和/退化曲线、引入多种子模板与显著性检验、在难任务全集上做预算缩放、报告自我改进过程中的回退与漂移事件、以及对元技能文本演化做条款级分析。若这些补足，Skill∞ 有望从“有效的单轮元优化方法”成长为“可长期运行的 RSI 基础设施”。
