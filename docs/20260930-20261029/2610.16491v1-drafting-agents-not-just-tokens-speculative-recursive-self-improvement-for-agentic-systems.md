## 摘要
通过连续修订来改进智能体，需要在有限预算下平衡探索与评估。狭窄的搜索可能错过有用的编辑序列，而完整评估每个中间版本可能在那些序列产生经验证的改进之前就耗尽预算。我们提出推测式递归自我改进（SpecRSI），它在其前代被完全评估之前草拟可执行的后继智能体，同时要求在被采纳前进行完整验证。验证感知树搜索（VATS）利用对某个延续的预测验证回报，在进一步编辑与未完成的检查之间分配预算。组验证优化（GVO）从已完成的搜索中学习改进器，同时保持真实评估器固定。在主要科学比较中，最终增益超过 Janus 33.3%--40.0%。额外评估表明，SpecRSI 在所有 50 个科学骨干--任务对中均优于 Janus，并在二十个骨干上的宏平均系统得分超过 MetaRSI-v1 1.85%--2.38%。编码验证成功率达到 69.4%，而 HGM 为 64.3%，且目标成本指数低 20.8%。

## Abstract
Improving an agent through successive revisions requires balancing exploration and evaluation under a limited budget. A narrow search can miss useful sequences of edits, while fully evaluating every intermediate version can exhaust the budget before those sequences yield a verified improvement. We introduce Speculative Recursive Self-Improvement (SpecRSI), which drafts executable successor agents before their predecessors are fully evaluated, while requiring complete verification before adoption. Verification-Aware Tree Search (VATS) allocates the budget between further edits and outstanding checks using the predicted verified return of a continuation. Group Verification Optimization (GVO) learns the improver from completed searches while keeping the real evaluator fixed. In the main scientific comparison, terminal gains exceed Janus by 33.3%--40.0%. Additional evaluations show that SpecRSI outperforms Janus in all 50 scientific backbone--task pairs and exceeds MetaRSI-v1 by 1.85%--2.38% in macro-average system score across twenty backbones. Coding-validation success reaches 69.4% versus HGM's 64.3% at a 20.8% lower target-cost index.

## 1. 核心问题与整体含义（研究动机与背景）

- **核心问题**：智能体通过连续修订（prompts、tools、workflows）实现自我改进时，每一轮既要“提出可执行变更”，又要“评估变更是否提升任务性能”，二者都消耗时间与算力。真正的问题不是候选想法不足，而是**如何在有限预算下把探索转化为经验证的进步**。
- **两种极端策略的困境**：
  - 单一路径逐版全评估：每步都有新鲜反馈，但搜索面窄，且在依赖编辑之间插入“评估屏障”。
  - 多分支并行全评估：探索更广，但为可能永远不会被使用的分支支付昂贵验证成本；增加 worker 只能降低时延，不能使工作免费。
- **推测式解码的类比与不可直接迁移性**：token 级“草拟—确认”思想可借鉴，但智能体修订存在三点本质差异：
  1. 修订是**可修订的程序**，而非已接受的前缀；后继可以修复尚未可采纳的父代。
  2. 验证是**付费、异构、互补的外部检查**，不是一次目标模型前向传播；多项检查可能需联合满足才能采纳。
  3. 进步是**预算约束下的经验证改进**，搜索结局取决于实际收益与全部已发生成本（含失败与未完成工作），而非提议数或接受数。
- **关键难点**：在付费揭示检查结果之前，估计某个“延续”（continuation，即从当前状态出发的进一步编辑与检查序列）还能带来多少净验证改进；错误估计会浪费不可逆预算。因此评分目标应从“候选当前质量”转向“延续的边际验证回报”。

## 2. 方法论：核心思想、关键技术细节与算法流程

### 2.1 总体框架：两层推测式 RSI 循环
- **内层循环（VATS）**：允许在父代未完全评估时扩展其后继，但**只有完全评估且可采纳的版本才能被 ACCEPT**；改进器在一次搜索内冻结。
- **外层循环（GVO）**：从多次独立完整搜索的反馈中更新改进器；验证契约 Γ 与真实评估器保持固定。
- **状态与契约**：
  - 完整可采纳根 \(r\) 锚定不可变版本树 \(T=(C,A)\)。
  - 验证契约 \(\Gamma\) 指定有限必需项集 \(I\)、执行/采纳规则、约束及更高更优分数 \(J_\Gamma\)。
  - 状态 \(S=(T,E,H,B,N,w)\)：已采纳证据、历史、剩余预算、尝试数、worker 数。
  - \(C_{\text{full}}(S)\) 为完整可采纳集，\(F(S)=\max_{c\in C_{\text{full}}}[J_\Gamma(c)-J_\Gamma(r)]\) 为已观察的采纳就绪增益。
- **三种角色分离**：
  - **真实评估器**：\(\Gamma+\text{Acquire}_\Gamma\)，只提供权威证据。
  - **学习评分器**：\(\hat Q_\phi(S,\omega)\)，预测净验证收益，仅指导花费，不产生证据。
  - **Drafter**：生成后继编辑，不分配评估分数。

### 2.2 VATS（Verification-Aware Tree Search）
- **动作空间**：\(\text{DRAFT}(P,h)\)（在已有父节点上做有界深度编辑）或 \(\text{VERIFY}(J)\)（对已有版本执行检查任务），另有 ACCEPT 终止搜索。
- **Solver（完成包构造）**：
  - 识别缺失项 \(U_c(S)\) 与待检查结果 \(K_c(S)\)。
  - 用 MILP 构造满足前置依赖、共享 setup、冲突与预留预算的可行验证包；包可覆盖单检查价值很低的互补项。
  - 保留原始可行完成种子，允许后续细化。
- **Scorer（延续价值估计）**：
  \[
  Q^\pi(S_t,\omega)=\mathbb E_\pi\big[F(S_{\text{end}})-F(S_t)-\lambda C_{t:\text{end}}-\mu L_{t:\text{end}}\mid S_t,\omega\big]
  \]
  即未来验证增益减去后续费用与时间成本；用冻结快照 \(\hat Q_{\bar\phi}\) 做**整包比较**（式7），保留检查间交互，共享作业/setup 只计一次。
- **Policy（工作选择）**：
  - 按偏好 logits \(z_\psi\) 经带 \(\epsilon\)-探索的 softmax 采样；ACCEPT logit 固定为零。
  - 收集阶段采样，部署阶段取 argmax。
- **执行与采纳**：
  - DRAFT 在真实工件上执行有界计划；不完整父节点可扩展，但每个编辑等待其父；无效编辑计费并终止该路径，保留有效前缀。
  - VERIFY 读取有效相同记录或执行真实检查；预测永不创建证据。
  - ACCEPT 仅需被选版本拥有完整可采纳证据，返回 \( \text{TieArgMax}_{c\in C_{\text{full}}} J_\Gamma(c) \)。

### 2.3 GVO（Group Verification Optimization）
- **信用单元**：从同一根、同一冻结改进器、匹配预算/worker 的 \(G\ge2\)
