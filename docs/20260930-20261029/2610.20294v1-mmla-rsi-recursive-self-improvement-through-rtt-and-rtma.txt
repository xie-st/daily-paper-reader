## ABSTRACT 

An agent can improve its behavior within an unresolved problem by changing how it acts and which experience it retains. We propose MMLA-RSI, a recursive self-improvement scheme with two implementations in Memory-Mediated Learning Architecture: Reasoning-Time Training (RTT) changes the policy state Φ, while Reasoning-Time Memory Adaptation (RTMA) changes authoritative memory 𝑀 . Each route also makes its adaptation method an object of improvement. A current numerical updater trains the policy proposing its successor; a current memory manager chooses the records available to the process proposing its successor. An independently admitted successor takes over the same role in the next generation. We give bounded executable rule languages, shared task/proposal interfaces, and one algorithm for either route or their composition. The RTT instance changes scalar schedules in a clipped-momentum update. The RTMA instance chooses NULL or a complete-row write with possible eviction. A fixed interpreter, trusted committer, and independent evaluator bound what can change. State versions, read closures, and conditional properties describe causal execution, accepted transitions, and finite work. Existing numerical-component studies motivate the construction. In four-candidate program selection, retaining LARC feedback updates reduces expected error by 24.65 and 36.65 percentage points for two trained initializations. In chronological continuous-integration replay, feedback binding is positive while retention increases loss. Completed SQL studies improve substantially over an unadapted substrate but do not establish the required additional online benefit. These results characterize their declared components. The two recursive routes and their joint realization are specified here; their beneficial recursive chains and discovery efficiency remain to be evaluated. # 1 Introduction 

An unsuccessful attempt supplies information that the next attempt may need. A program fails an execution check, a query violates a visible constraint, or a candidate learning rule performs poorly on a development task. The agent must decide both how this feedback changes its behavior and which parts remain available later. Memory-Mediated Learning Architecture (MMLA) makes these two learning objects explicit: policy state Φ and authoritative memory 𝑀 [30]. Reasoning-Time Training (RTT) updates Φ while a problem remains unresolved, then uses that state in a later attempt. Reasoning-Time Memory Adaptation (RTMA) commits a non-NULL successor of 𝑀 that a later attempt reads. The distinction follows the MMLA v4 state account. Here both paths are central. Learning a useful memory is one level of adaptation; improving the method that selects and maintains that memory is another. The same distinction holds between updating a policy state and improving its updater. MMLA-RSI connects each adaptation method to the process producing its own successor. In the RTT implementation, the current numerical updater trains a private proposal policy. In the RTMA implementation, the current manager chooses the authoritative records that the proposal process can read. A locked successor is evaluated independently and, if admitted, replaces its parent in the same proposal-learning role:

Changing a state alone is adaptation. A recursive improvement chain additionally requires the changed adaptation method to participate functionally in producing a later improved method. This dependency has direct precedents. Self-referential meta learning studies systems that modify their learning behavior [9]; STOP executes an improver on itself, and Darwin Gödel Machine uses descendant agents in further self-modification [25, 27]. Our construction specifies the dependency through MMLA’s two state paths: bounded numerical update programs and bounded memory-management programs, their task/proposal interfaces, and independent admission before role replacement. It makes both the changed object and its later use inspectable. MMLA is mixer-agnostic. Low-Rank Adaptive Residual Connections (LARC) provide the current numerical carrier in front of a reused frozen mixer [29]. The Transformer mixer and low-rank factors are implementation choices. Φ denotes a policy-state role, not a synonym for adapter parameters; another declared fast state can fill it. 𝑀 is the committed authority for retained records, not an undifferentiated name for prompts, logs, or caches. These distinctions let the same architecture support policy adaptation, memory adaptation, and their composition. The method contribution is a complete recursive construction with two concrete bounded domains. The RTT domain varies feedback-dependent schedules in a clipped-momentum template. The RTMA domain varies the rule selecting NULL or a complete-row write under finite memory capacity. We specify their state, feedback, failure, read, and version semantics, then give a common algorithm and its conditional properties. Existing component studies motivate separate measurements of functional participation, task benefit, and discovery efficiency. The proposed method, an observed beneficial recursive chain, and an advantage over fixed search are distinct levels of evidence.

## 2.4 Authoritative memory and the RTMA path 

The memory path follows MMLA v4 's definitions of RTMA and dual-state composition [30, Section 72, Definitions 72.2–72.3]. Its transition separates a proposed action from an authorized commit: 

𝑎 𝑀 𝑗 = 𝑉 𝜂 𝑀 𝑘 (𝑀 𝑗 , 𝑑 𝑗 ), (𝑀 𝑗 +1, 𝑣 𝑀 𝑗 +1) = Commit (𝑀 𝑗 , 𝑎 𝑀 𝑗 , 𝑑 𝑗 ). (6) The fixed assembler constructs the candidate record 𝑑 𝑗 from arrived evidence. The manager chooses an allowed action. The trusted committer checks its type, provenance, capacity, expected predecessor, and epoch before installing a complete successor. NULL leaves authoritative content and its version unchanged and produces an explicit no-op receipt. In the minimal instance, a non-NULL action writes one complete row into a selected slot, evicting its previous row if occupied. The later attempt pins the actual successor version. A failed pin, an unread write, and a NULL receipt do not establish the positive RTMA path. Authority concerns which committed records the reader treats as its stored evidence. It does not turn a stored hypothesis into a fact. A row can authoritatively record that an attempt received a particular execution response, with the response’s scope and provenance, without claiming the attempted answer was correct. The manager cannot rewrite the evaluator, forge provenance, or enlarge its own access permissions. The two paths have independent receipts. RTT requires the policy update/read and functional-use obligations in Table 2. RTMA requires a non-NULL complete-row commit and later same-problem read; functional memory dependence is additionally tested by intervening on the memory closure with Φ fixed. A joint interval includes both paths and their interleaving. Neither classification implies positive task benefit.

## 4.4 From a component effect to an RSI effect 

An adapted initialization can outperform another initialization without gaining anything from its own feedback. The objective increment and each arm’s real-feedback increment therefore appear separately in the results. The recursive evaluation likewise reports parent participation and accepted task improvement separately from discovery efficiency; Section 5.9 gives the corresponding interventions and comparisons. Each comparison uses the original unit of generalization. Multiple seeds applied to one task group are repeated measurements within that group; they are not additional independent tasks. Selection uses development groups, and a locked candidate is evaluated on separate audit groups. Once an audit outcome influences a successor’s design, that group becomes part of the development history for subsequent statistical claims. New accepted generations require fresh audit information under the stated admission assumptions.

# 6 Conditional Properties of the Construction 

The method is the adaptation-rule-to-proposal construction in Section 5. The following properties describe its causal execution, accepted transitions, and finite resource use under the stated assumptions. 

Proposition 6.1 (Causal composition) . Suppose each generation begins with an adaptation-rule version measurable with respect to its admitted past; each within-task transition is measurable with respect to arrived records and permitted randomness; and an audit is opened only after the candidate is locked. If callbacks are epoch-bound and cannot modify a closed task, every action in a finite sequence of generations is measurable with respect to the information available at its execution time. Proof. Condition on the admitted state at the start of a generation. Composition of the causal proposal kernel, arrived-feedback map, and selected adaptation operation yields a causal next state. Induction covers the finite attempts in that generation. Candidate locking precedes the audit; admission is therefore a function of information available at the generation boundary. This state supplies the induction hypothesis for the next generation. Epoch checks exclude a late write from a closed task. □

# 8 Relation to Other Self-Improvement Routes 

MMLA-RSI connects policy and memory adaptation with recursive changes to their respective methods. Its distinction from other routes is clearest along three axes: what changes, when feedback becomes a learning signal, and how the changed object participates in the next improvement. These axes overlap; they do not partition all systems into mutually exclusive families. RRSI regularizes the evolution of an agent harness: prompts, control flow, tools, memory, and context management around a frozen backbone [20]. The current harness produces traces and feedback, proposal uses the evolution history with a constrained edit budget, and screening and cost-aware selection determine the next incumbent. The inspected algorithms keep the outer proposal and selection rules prescribed. This is an agent-system route to RSI. MMLA-RSI specifies two narrower mutable domains and their proposal-state pathways: the current numerical updater changes proposal Φ, and the current memory manager changes proposal 𝑀 . The RTMA route overlaps memory and context-management search; its defining construction is the explicit reuse of the candidate management rule in managing the evidence that generates its successor. MemEvolve jointly evolves experiential knowledge and the memory architecture through programmatic encoding, storage, retrieval, and management modules [26]. Its outer process selects architectures using performance, cost, and latency, diagnoses their execution trajectories, and redesigns permitted modules. It is a direct precedent for improving the memory mechanism

Equation 17 places that rule in a particular proposal interface: the current manager controls which arrived evaluation records the successor generator can read, and an admitted successor takes over that proposal-memory role in the next generation. The comparison concerns this parent-to-proposal dependency and the mutable domain. On-policy distillation (OPD) supervises a student’s own rollout prefixes with teacher distributions. # 10 Discussion 

MMLA-RSI develops two ways for an adaptation method to participate in producing its successor. RTT changes the policy state through numerical learning. RTMA changes the authoritative evidence available to the next attempt. Their recursive layers change the numerical updater and memory manager, respectively, then return the admitted rule to that same role in the next generation. The joint construction retains both state paths instead of treating memory as an accessory to policy learning. The component evidence identifies practical difficulties: feedback can change behavior without improving it, a strong direct rule can outperform a learned carrier, and offline training can explain most gains attributed to an online system. These observations motivate measurements of complete task performance, state use, and discovery cost. They neither provide nor rule out an effective recursive chain in the proposed domains. The minimal languages make limited parts of the adaptation process mutable. RTT varies scalar schedules within a fixed numerical template. RTMA varies which complete evidence rows are retained, including the option to write nothing. The trusted memory authority, record semantics, and evaluators stay fixed. More expressive memory transformations or numerical optimizers would be separate domains with their own bounds and comparisons. The empirical question is whether a rule admitted for improved task behavior then helps produce another admitted rule, and whether that discovery process is useful relative to fixed rules and external search at the same information and total cost. Either route can be evaluated first. A joint claim additionally measures the complete task and both state paths, including the cost of invalidating or recomputing memory values when the reader changes.

## B.3 SQL interaction: state changes without endpoint gains 

The first completed task-level SQL study uses grouped interactions from SParC [23], with 56 development interactions across 28 databases and 75 confirmation interactions across 19 databases. Its primary endpoint is whole-interaction success: every turn must produce a query execution agreeing with the reference on the fixed database. This is an operational reference-concordance score, rather than a proof that two SQL programs are equivalent on all databases. Seeds are averaged within the interaction and then databases are weighted equally. The adapted real-feedback method reaches 18.42% confirmation success, compared with 20.18% for the static six-proposal frozen method. The paired difference is −1.75 percentage points, with a 97.5% database-bootstrap interval of [− 4.39 , 0.88 ].The three registered non-neural rule methods each score zero on this confirmation population; the development-selected rule remains the comparator. Beating those particular rules does not establish an advantage over general-purpose SQL systems. The saved-state audit is informative even though the main comparison fails. Across development and confirmation, 393 paired cases contain 1,965 fast-state packages. The audit verifies nonnull gradients and state changes in 786 keep packages and exact initialization, optimizer, and random-state restoration in 786 reset packages. On 225 confirmation task–seed pairs, real keep versus reset changes 14 third-proposal token sequences and three selected SQL outputs, while whole-interaction and last-turn scores remain unchanged in every paired case. Real versus sham produces different actual rewards and fast states in only six of these 225 pairs. This is evidence of local saved-output sensitivity and weak effective sham separation, not positive task benefit. The offline SQL adaptation includes a rank-16 task adapter and the rank-4 input residual, totaling 700,416 trainable entries. Gains over the original model cannot be attributed to the fast residual alone. The strict saved-prefix retention and binding contrasts are zero at the task endpoints despite the verified state and output changes. 

## B.4 CoSQL correction transfer: online increment below the prespecified requirements 

The next completed study uses CoSQL [22] under its own fixed correction-transfer protocol. The evaluation has 358 development episodes across 28 databases and 210 confirmation episodes across 19 databases, with three paired seeds and 43 method–seed cells over 568 episodes. All 24,424 logical records are complete. The endpoint is final-query execution concordance with the reference, macro-averaged by database. It is distinct from the previous study’s whole-interaction success and is not presented as an official benchmark leaderboard score. The adapted real-feedback procedure differs from the static frozen comparator by −0.979 percentage points, with a 97.5% interval of [− 4.247 , 1.759 ]. The registered task-level gate requires at least five points and a positive 97.5% lower bound against both the frozen method and the development-selected rule. It fails against the frozen method. The final audit checks 13,632 prefix bindings and 3,408 reset/query-closure cases. Memory is disabled, but shared support text, proposal history, feedback, tools, and selectors remain in the declared read.
